# flam 与修仙 Data Skill：业务术语与 SQL 示例整理

## 1. 文档目的

本文将当前系统中的 flam 与修仙 Data Skill 整理为知识库录入清单，供后续人工确认、拆分和发布使用。

本文不是迁移脚本，也不改变 `custom_prompt` 中的任何记录。知识库中的业务知识和 SQL 示例只能作为 `reference-only` 参考，不能替换当前数据源、权限、Schema、事件/JSON 映射或当前请求选中的 Data Skill。

### SQL 初步统计

- 本次业务候选共 28 条 Skill、130 个 SQL 代码块；另审阅修仙日期契约 `255` 的 2 个代码块，但不将其计入业务候选。
- 业务候选按空白归一化后得到 115 个唯一 SQL 文本；连同 `255` 的 2 个代码块则为 117 个唯一文本。
- 发现 9 组重复组，覆盖 24 个代码块；发布前应按“问题 + SQL + 方言 + 适用条件”去重，不按 Skill ID 直接保留重复项。
- 业务候选 130 个代码块均能按对应 MySQL 方言解析为单条查询；连同 `255` 则为 132/132。这个结果只是静态解析，不代表已经通过当前工作空间 Schema、对象权限、行权限和 Data Skill 校验。
- 业务候选中 111 个代码块使用了 `{{...}}` 参数或看板参数。
- 11 个代码块含硬编码 `YYYYMMDD`：`240`、`242`、`257`、`269`。录入知识库前应改为参数或明确的查询示例占位说明。
- 91 个代码块使用 JSON 访问表达式。关联对象必须声明宿主表、宿主字段和 JSON Path，不能只保留 SQL 文本。

## 3. 抽取边界

| Data Skill 内容 | 知识库处理 | 说明 |
| --- | --- | --- |
| 业务术语、别名、定义、公式、统计粒度 | 抽取到 `BUSINESS` | 一个指标或一个稳定业务概念一个条目，不按 Skill 一条一条整包复制 |
| 示例问题和已验证查询 | 抽取为 `BUSINESS.examples[]` | 一个问题对应一个 SQL 示例；保留方言和适用条件 |
| 物理表、字段、JSON Path、事件字段 | 进入关联对象或对应结构化知识类型 | 不要仅凭向量文本使用物理对象 |
| `必须使用/禁止使用`、权限、数据源边界 | 继续保留在 Data Skill | 这些是执行约束，不能降级为普通参考文档 |
| 日期默认、成熟窗口、实时/历史选表 | 继续保留在 Data Skill | 由当前请求和当前数据源上下文执行 |
| 图表字段、看板组件、输出契约 | 继续保留在 Data Skill；必要时将指标定义抽成 BUSINESS | 图表布局不是业务术语 |
| MCP 工具调用、工具参数 | 不进入 BUSINESS | 属于能力路由，不是业务知识 |

### flam 推荐拆分示例

- `flam 付费与 LTV 口径` 不应生成一个“大而全”的 BUSINESS 条目，至少拆为：`日付费金额`、`付费用户数`、`付费率`、`ARPU`、`ARPPU`、`首付用户`、`D7 LTV`。
- `flam 新增与留存 cohort 口径` 至少拆为：`新增用户`、`渠道新增用户`、`D1 留存`、`D3 留存`、`D7 留存`。
- `flam 钻石经济口径` 可拆为：`钻石获取量`、`钻石消耗量`、`钻石净变化`，并在关联对象中声明资源字段和来源/去向字段。

### 修仙日期契约 `255`

`255` 主要是通用执行契约：固定 0-14 日日期骨架、按日补零、非递归日期序列和最新完整历史日。它不应整体迁移为业务术语或普通 SQL 示例。

可以另行写成一条平台/数据源级说明文档，但以下内容必须继续由 Data Skill 执行：

- 当前数据源日期字段的选择。
- 最近 15 天和“截至昨天最新完整日”的边界。
- 日期骨架与业务事实的 `LEFT JOIN`。
- 递归 CTE 禁用时的非递归序列方案。

## 7. 知识库录入格式

每个 BUSINESS 条目建议只表达一个稳定概念：

```yaml
knowledge_type: BUSINESS
term: 付费率
aliases: [付费渗透率]
definition: 在同一统计窗口内，满足成功付费条件的去重用户数除以指定分母用户数。
formula: 付费用户数 / 分母用户数
constraints:
  - 必须明确分母是活跃用户、新增用户还是其他授权人群。
  - 付费金额和成功订单条件服从当前数据源 Data Skill。
related_objects:
  - object_type: table
    table: <当前数据源中的事实表>
  - object_type: field
    field: <成功交易或金额字段>
examples:
  - name: 按日付费率
    question: 最近 7 个完整自然日的付费率是多少？
    dialect: mysql
    sql: |
      <通过当前数据源 Schema、权限和 Data Skill 校验后的单条 SELECT/WITH>
    notes: 明确时间字段、分母、成功交易条件和空值处理。
```

SQL 示例不能覆盖 `data-skill` 的统计口径，也不能直接照抄示例中的物理表名或占位符。知识库发布前必须完成：

1. 当前数据源和方言确认：flam/修仙当前均为 MySQL，但仍以实时绑定配置为准。
2. 单条只读查询解析；拒绝 DDL、DML、多语句和无法解析的方言语法。
3. SQL 实际访问的表、字段、JSON Path 与 `related_objects` 一致。
4. 当前用户的 Schema、字段、行权限和 Data Skill 规则检查。
5. 参数化日期和窗口；特别复核 flam `240`、`242`，修仙 `257`、`269` 的硬编码日期示例。
6. 对重复 SQL 做人工去重，保留最清晰的问题描述和适用条件。

## 8. 明确不迁移的内容

- 平台通用权限、数据源上下文、日期契约、粒度、比例、漏斗和图表规则。
- MCP 告警过滤、搜索、证据查询等工具调用 Skill。
- 用户私有 Skill，除非明确创建同等可见性和所有权的私有知识库条目。
- 任何仅描述看板组件、图表字段或输出 JSON 结构、但没有独立业务定义的段落。
