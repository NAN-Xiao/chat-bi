# 知识文档多知识块编辑需求

## 1. 背景

知识库列表中的每一行代表一份独立知识文档，例如：

- 修仙 - 事件参数对照
- 修仙 - JSON 字段解析
- 修仙 - Schema 表字段说明
- 修仙 - Data Skills 知识

当前列表层级不变。用户点击某一行的“编辑”后，应在同一个编辑页面中查看并维护该文档内部的多个知识块，而不是把列表中的多份文档合并到一个编辑器中。

## 2. 目标

让知识维护人员可以在一份知识文档内：

1. 查看全部知识块及其顺序。
2. 独立新增、编辑、复制和删除知识块。
3. 调整知识块顺序。
4. 一次保存整份文档草稿，并按现有流程校验、发布和回滚。
5. 清楚识别用户维护的知识块与系统自动生成的 RAG 检索切片。

## 3. 概念定义

### 3.1 知识文档

知识库列表中的一条记录，是名称、描述、作用域、权限、版本、发布状态和审计记录的归属单位。

### 3.2 知识块

知识文档内部由用户直接维护的内容单元。一期普通文档知识块至少包含：

- 稳定块 ID：系统生成，不因排序变化而改变。
- 标题：必填，用于编辑页导航和检索引用定位。
- 正文：Markdown 内容，必填。
- 排序号：决定页面展示和标准化正文拼接顺序。
- 启用状态：默认启用；停用块不进入新发布版本的检索内容。

### 3.3 检索切片

系统在发布时根据知识块内容自动生成的 RAG 检索单元。检索切片不是用户编辑对象，不能与知识块混用：

- 用户编辑知识块。
- 系统按知识块边界、标题和长度生成一个或多个检索切片。
- 检索切片保留来源知识块 ID、标题、文档版本和切片序号，支持引用追踪。
- 切片算法、长度或重叠参数变化时，可以重新生成切片，不应改变用户维护的知识块。

## 4. 页面结构

### 4.1 列表页

- 每一行仍表示一份独立知识文档。
- 列表不展开文档内部知识块。
- 可增加“知识块数量”列，便于识别文档规模。
- “编辑”只打开当前行对应的文档。

### 4.2 编辑页

编辑页由三部分组成：

1. 文档信息区：名称、描述、知识范围、所属工作空间、标签、数据源关联等文档级信息。
2. 知识块编辑区：按顺序展示当前文档的全部知识块。
3. 固定操作区：取消、保存草稿、校验、发布，继续沿用现有版本生命周期。

知识块编辑区采用可折叠的纵向块列表。每个块显示标题、状态和块级操作，展开后编辑 Markdown 正文。页面同时提供知识块目录，点击目录项可定位到对应块；知识块较多时不要求一次展开全部正文。

## 5. 知识块操作

### 5.1 新增

- 编辑区顶部和末尾均提供“新增知识块”。
- 新块默认插入到用户触发位置之后。
- 新块创建后自动进入编辑状态。
- 标题或正文为空时，可以暂存草稿，但不能通过发布校验。

### 5.2 编辑

- 标题和正文可以独立修改。
- 编辑过程中保留未保存提示。
- 折叠知识块不能丢失尚未保存的输入。
- 一个知识块的表单校验错误应定位到该块，并在目录中显示错误状态。

### 5.3 排序

- 支持拖拽排序，并提供“上移”“下移”作为可访问性操作。
- 排序只改变展示和内容拼接顺序，不改变稳定块 ID。
- 排序结果在保存草稿后生效。

### 5.4 复制

- 复制后生成新的稳定块 ID。
- 标题默认增加“副本”标识，正文和启用状态沿用来源块。
- 复制块插入来源块之后。

### 5.5 删除

- 删除已有知识块前必须二次确认。
- 删除操作先作用于当前草稿；已发布版本继续可用，直到新版本发布成功。
- 文档至少保留一个知识块。删除到只剩一个块时，删除入口禁用并给出明确提示。
- 不提供静默恢复或自动替换知识块。

### 5.6 启用与停用

- 停用只影响下一次发布内容，不直接修改当前已发布版本。
- 停用块仍保留在草稿编辑页中，可以重新启用。
- 发布时至少需要一个已启用且校验通过的知识块。

## 6. 保存、校验与发布

- 保存草稿以整份知识文档为事务边界，提交文档信息、知识块内容、顺序和状态。
- 不提供单个知识块独立发布；同一文档的知识块共享文档版本号。
- 校验结果需要同时提供文档级问题和知识块级问题。
- 发布成功后，系统按当前草稿生成标准化正文、检索切片和向量，并原子切换当前发布版本。
- 任一必需知识块解析、切片或向量化失败时，本次发布失败，上一发布版本继续可用。
- 回滚仍以文档版本为单位，恢复该版本中的全部知识块及其顺序，不执行部分块回滚。

## 7. 上传与兼容规则

- 新建普通文档时默认创建一个空知识块。
- 现有仅包含单段 Markdown 的普通文档迁移为一个知识块，正文不得丢失。
- Markdown 或 Word 上传后，可按标题层级形成知识块预览；用户确认后才替换当前草稿。
- 无标题内容归入“正文”知识块；不得静默丢弃。
- 重新上传产生的新块不能直接覆盖当前已发布版本，必须经过保存、校验和发布流程。
- 事件参数、JSON 字段解析和业务知识继续使用现有结构化编辑器。一期不把不同知识类型混合到同一文档中，也不把 Data Skills 迁入知识库编辑器。

## 8. 权限与隔离

- 知识块继承所属知识文档的作用域、工作空间、管理权限和数据源上下文，不单独配置跨空间权限。
- 平台公共知识和工作空间知识继续遵循现有管理权限。
- 普通成员只能查看已发布内容，不能通过块级接口绕过文档级编辑权限。
- 所有块级读取、写入、排序和删除操作必须先校验文档访问权限和工作空间边界。

## 9. 并发与审计

- 采用“块级乐观并发 + 文档结构版本”两层控制：
  - 每个知识块有独立 `block_revision`，用于检测正文、标题和启用状态的并发修改。
  - 文档维护 `structure_revision`，用于检测新增、删除、复制、排序等结构变更。
- 编辑页打开时记录文档结构版本和各知识块版本，并显示正在编辑该文档的用户及其最近心跳时间。该提示用于协作感知，不作为唯一数据安全措施。
- 保存知识块正文时只提交块 ID、基线 `block_revision` 和变更字段：
  - 不同用户修改不同知识块，可以同时保存。
  - 同一知识块被另一用户修改后，后保存方必须进入冲突处理，不能覆盖服务端内容。
- 保存新增、删除、复制或排序时必须携带基线 `structure_revision`。结构版本过期时拒绝结构写入，防止排序覆盖、删除已复制块或把新块插入错误位置。
- 发生冲突时保留本地编辑内容，重新读取服务端版本，并展示“服务端版本 / 我的版本 / 冲突字段”对比。用户只能选择重新载入服务端内容、以我的内容重试，或手动合并后再次提交。
- “以我的内容重试”必须使用最新服务端版本重新提交并再次校验权限和版本，不能绕过版本检查；系统不得静默合并或自动选择一方。
- 对同一知识块的短时编辑可显示“某用户正在编辑”，但不强制长时间锁定整个文档。用户离开页面、心跳超时或主动释放后，提示自动失效。
- 审计记录至少包含文档 ID、版本、操作类型、操作人、时间，以及新增、修改、排序、停用或删除的知识块 ID。
- 历史版本必须能够还原当时的知识块内容、顺序和启用状态。

### 9.1 并发场景处理表

| 场景 | 处理方式 | 结果 |
| --- | --- | --- |
| 用户 A 编辑块 1，用户 B 编辑块 2 | 块级版本分别校验 | 两次保存均可成功 |
| 用户 A、B 同时编辑块 1 的不同字段 | 同一 `block_revision` 冲突 | 后保存方查看差异并手动合并 |
| 用户 A 编辑正文，用户 B 修改标题 | 仍属于同一块版本 | 不自动拆分合并，提示块冲突 |
| 用户 A 排序，用户 B 新增块 | 结构版本校验 | 结构版本过期方重新加载后重做操作 |
| 用户 A 删除块，用户 B 编辑该块 | 删除使块版本失效 | 编辑方提示“知识块已被删除”，本地内容保留供复制或恢复 |
| 保存请求超时后用户重试 | 使用幂等请求 ID | 服务端已成功时返回原结果，不重复写入 |

### 9.2 一期实现边界

- 一期不做类似 Google Docs 的字符级实时协同编辑，不引入 CRDT 或 OT。
- 一期保证“不同块可并行、同块不丢数据、结构操作不覆盖”，满足知识维护场景的主要并发风险。
- 若后续需要多人同时修改同一段正文，再评估字符级实时协作技术和更细粒度的评论/合并模型。

## 10. 交互状态

- 无知识块：仅允许出现在新建草稿初始化过程中，页面引导用户新增第一个知识块。
- 加载中：知识块目录和编辑区显示骨架状态，禁止提交。
- 保存中：禁止重复保存和排序操作。
- 校验失败：目录和知识块头部显示错误数量，点击错误可定位字段。
- 只读：保留块目录、折叠和定位能力，隐藏新增、复制、排序、删除和保存入口。
- 大文档：只渲染必要的展开内容，避免所有 Markdown 编辑器同时挂载造成页面卡顿。

## 11. 验收标准

- [ ] 点击列表中任意一条记录的“编辑”，只打开该文档，并展示其包含的全部知识块。
- [ ] 用户可以在同一编辑页新增、编辑、复制、排序、停用和删除知识块。
- [ ] 知识块排序后稳定块 ID 不变，保存并重新进入页面后顺序一致。
- [ ] 删除或停用草稿知识块不会立即影响当前已发布版本。
- [ ] 空标题、空正文、全部停用等无效状态可以保存为草稿，但不能发布，并显示块级错误定位。
- [ ] 发布后每个检索切片都能追踪到来源文档版本和知识块。
- [ ] 发布失败时上一发布版本继续提供检索服务。
- [ ] 现有单 Markdown 文档可以无损显示为单知识块。
- [ ] 不同知识文档不会在单条编辑页中被合并展示。
- [ ] 不同知识类型不会在一期被混合到同一文档中，Data Skills 管理入口和生命周期保持不变。
- [ ] 平台、工作空间管理员和普通成员的现有权限边界不因块级能力而扩大。
- [ ] 桌面和移动视口下无页面级水平溢出；知识块标题、状态和操作区不发生遮挡或纵向挤压。

## 12. 一期非目标

- 跨文档批量编辑知识块。
- 将列表中的多份知识文档合并为一份文档。
- 单个知识块独立发布、独立回滚或拥有独立版本号。
- 在同一文档中混合普通文档、业务知识、事件参数和 JSON 字段等不同知识类型。
- 允许用户直接编辑系统检索切片、向量或切片算法参数。
- 将 Data Skills 作为知识块迁入知识库。

## 13. 后续扩展

- 跨文档复制或移动知识块。
- 块级引用关系和依赖校验。
- 块级变更对比与评论。
- 结构化知识类型的通用块容器。
- 大文档的虚拟滚动、目录搜索和批量折叠。
