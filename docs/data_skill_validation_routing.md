# SQL 执行优先与语义提示

2026-09-17 用户明确验收目标：优先生成可执行 SQL，允许语义、维度和口径不够准确。本说明替代上一版“结构不满足先修复、业务冲突再裁决”执行策略。

## 执行门槛

SQL 必须通过权限、工作空间/数据源范围、物理表列、只读限制、数据库方言和参数解析校验。语法或执行错误仍进入现有有限修复。模型和数据服务不可用、没有授权数据等情况仍明确报告，不能用无关 SQL 或虚构表列伪造成功。

Data Skill 和知识库继续参与生成；它们不再作为语义裁决的执行闸门。生成提示允许基于授权的真实表列作近似分析，并要求说明假设。

用户未指定时间时，“最近七个完整自然日”仅作为生成建议，不再要求模型返回范围必须恰好等于该区间。已提供的合法范围原样用于日期参数渲染；日期格式、起止顺序、日期配置一致性和占位符完整性仍独立检查。

## 质量问题

日期补齐、补零、字段/维度偏好、指标口径等 Data Skill 检查转为质量提示，不再引发知识裁决和语义修复。明确声明 rule_type: security 的校验仍严格拦截；真正权限始终以权限服务为准，Skill 不能授予权限。

智能问答保存并显示质量提示，继续执行通过物理和权限校验的 SQL。分析助手保留执行成功的数据块，附带 warning 和 quality_warnings，不因语义检查失败再次执行 SQL。

事件值缺失或未确认时提示结果可能为零/空，不改写原 SQL 或删除真实返回的列。SQL 成功但日期结果不能形成有效图表时，保留 SQL 与结果，明确提示图表限制，不将查询标成失败。

SQL 生成和执行链路不再调用知识裁决；authority.py 中的裁决工具及历史日志保留，但不参与当前执行放行。

## 验证原则

主要验收标准是 SQL 真实执行成功及结果被保留；语义正确性单独记录。图表仍只能绑定实际返回的字段。保留权限、只读、物理列与参数错误的负向测试，确保允许语义近似不会放宽数据访问边界。
