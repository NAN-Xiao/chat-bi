# Tab 卡片紧凑摘要显示调整设计

## 背景

当前看板摘要策略在顶部布局下使用 `440x360` 作为显示下界，导致宽度约 300、但仍有可用空间的卡片直接隐藏摘要。用户希望小卡片也显示摘要，只有内容确实放不下时才隐藏。

## 目标

- 内容区达到 `300x250` 时显示摘要。
- 内容区宽度小于 300 或高度小于 250 时隐藏摘要。
- `300x250` 至 `440x360` 区间使用紧凑摘要密度，不回写 Card 外框或 `sizeX/sizeY`。
- 保留现有 Tab 单向链路：根节点 `border-box` 测量一次，布局状态单向更新，图表保持稳定 key 原地 resize/render。
- 不新增 `chart-show-area` 观察、不新增异步重试、不通过 key 卸载重建图表。

## 方案

调整通用 `resolveInsightDisplay` 的顶部摘要显示边界：

1. `TINY_MIN_WIDTH/HEIGHT` 继续作为唯一硬隐藏边界。
2. 移除顶部布局中 `TOP_BASIC_MAX_WIDTH/HEIGHT` 对 `show=false` 的提前返回。
3. 让现有 `belowBasicThreshold` 分支把小于原 basic 阈值的可用卡片降级为 `basic`，并保持 `maxStats` 受限。
4. 保留已有迟滞逻辑，避免在尺寸边界附近来回切换密度。

## 状态与失败处理

布局 resolver 仍由 Tab 协调器按规范帧和数据结构签名调用。普通数据值刷新不重新转换；失败时保留上一稳定 display，不写外框尺寸、不修改 key、不安排重试。

## 验证

- 新增回归断言：`300x250` 显示 `basic` 摘要，`299x250` 和 `300x249` 隐藏摘要。
- 保留既有 `440x360`、迟滞、布局和失败签名测试。
- 运行 Tab 协调器、摘要布局、SQView 响应式、ChartComponent resize、类型检查和生产构建。
