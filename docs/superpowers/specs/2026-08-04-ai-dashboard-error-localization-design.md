# AI 看板错误中文化设计

## 目标

AI 看板不得直接展示 Axios 生成的英文错误，例如 `Request failed with status code 404`。前端应将任务创建、任务轮询和任务恢复过程中出现的已知 HTTP 状态与业务错误类型转换为当前语言对应的提示。

本次只修改 AI 看板错误展示，不改变全局请求拦截器和其他业务页面。

## 错误解析规则

新增一个无 UI 依赖的 AI 看板错误解析函数，输入任意异常对象和翻译函数，输出可直接展示的字符串。解析优先级如下：

1. 保留后端返回的中文业务说明，包括 SSE `type=error` 的嵌套 JSON 内容。
2. 识别标准业务类型 `permission_denied` 和 `data_unavailable`，使用已有或新增的 i18n 文案。
3. 根据 HTTP 状态映射 AI 看板专用提示：
   - `400`：请求参数有误，请检查后重试。
   - `401`：登录状态已失效，请重新登录。
   - `403`：当前账号没有执行此操作的权限。
   - `404`：问数任务不存在或已失效，请重新提问。
   - `422`：请求参数校验失败，请重新提问。
   - `429`：请求过于频繁，请稍后重试。
   - `500`：问数服务处理异常，请稍后重试。
   - `502`：问数服务网关异常，请稍后重试。
   - `503`：问数服务暂时不可用，请稍后重试。
   - `504`：问数服务响应超时，请稍后重试。
4. 无 HTTP 响应时显示网络连接提示。
5. 未识别异常使用通用中文提示，不直接显示 Axios 默认英文状态文本。

限流或额度接口已经返回明确中文说明时，优先保留后端说明，不用通用 `429` 或 `503` 文案覆盖。

## 接入范围

- `ChartAnswer.vue` 的任务创建失败、轮询失败和恢复失败统一调用错误解析函数。
- `ErrorInfo.vue` 继续负责最终展示，不承担网络异常解析。
- i18n 文件补充简体中文、繁体中文和英文键，避免在 TypeScript 中硬编码中文。
- 不修改后端任务状态协议，不修改全局 `request.ts`。

## 测试

使用 Node 测试覆盖纯错误解析函数：

- Axios 风格 `404` 转为“问数任务不存在或已失效，请重新提问”。
- 后端中文业务说明优先于状态码通用提示。
- `data_unavailable` 嵌套 JSON 保留具体中文原因。
- 无响应和未知异常返回对应的 i18n 通用提示。
- 英文 `Request failed with status code ...` 不会直接返回给展示层。
