# Chat 会话渐进式加载设计

## 背景

AI 看板会话切换或页面恢复时，当前实现容易让用户感知为“慢”：历史记录、图表数据、任务恢复等动作混在同一条恢复链路里。尤其当会话里有多条历史回答和图表时，用户需要等待较多异步请求完成后，才能稳定看到最新生成状态。

本设计选择“优先级队列 + 逐条显示 + 有限并发”的方案。目标是在不增加后端压力、不改变业务口径的前提下，让会话主体先可见，正在生成的回答优先恢复，历史图表数据分批补齐。

## 目标

- 会话切换后立即显示已有聊天记录、问题文本、已有回答文本和图表骨架。
- 最新未完成回答优先恢复，避免切页或会话切换后长时间停在“思考中”。
- 历史图表数据后台分批加载，不阻塞首屏渲染。
- 图表数据请求使用有限并发，默认同时最多 3 个请求。
- 会话切换过程中避免旧会话异步结果写回新会话。
- 普通历史数据加载失败不影响当前正在生成的回答。

## 非目标

- 不改变后端任务执行模型。
- 不改变 SQL 生成、语义层、指标口径或数据源权限逻辑。
- 不引入浏览器 Web Worker 或真正多线程计算。
- 不让所有历史记录都被判定为正在生成。
- 不恢复当前已隐藏的分析和预测按钮入口。

## 总体方案

会话加载拆成两条路径：

1. **主路径：立即展示会话结构**
   - `Chat index.vue` 获取会话详情后立即设置 `currentChat`。
   - 页面先渲染用户问题、已有文本回答、图表容器和加载骨架。
   - 不等待所有 `get_chart_data` 请求完成。

2. **后台路径：按优先级补齐异步数据**
   - 最新未完成记录走最高优先级恢复，不进入普通历史图表队列。
   - 历史图表数据进入有限并发加载队列。
   - 队列按优先级执行：正在生成记录 > 首屏可见记录 > 最近历史记录 > 更早历史记录。

## 组件职责

### Chat index.vue

- 负责会话切换、当前会话状态和全局生成状态。
- 识别最新未完成记录，并触发其恢复。
- 创建并驱动图表数据加载队列。
- 在切换会话时取消或废弃旧队列。
- 通过 `chatId` 或加载版本号防止过期请求写回。

### ChartAnswer.vue

- 继续负责单条回答的任务恢复、任务事件轮询、最终答案展示和图表数据渲染。
- 对未完成记录：
  - 有 `task_id` 时直接轮询任务事件。
  - 无 `task_id` 但有 `record.id` 时查询记录关联任务，再决定轮询或刷新记录。
- 对已完成但缺图表数据的记录，显示骨架，由外部调度补齐数据。

### chatLoadScheduler.ts

新增前端工具模块，用于管理历史数据加载：

- 接收加载任务，任务包含 `chatId`、`recordId`、优先级、执行函数和写回函数。
- 控制并发数，默认 `maxConcurrency = 3`。
- 支持按任务键去重，避免同一条记录重复请求。
- 支持取消当前会话的未执行任务。
- 执行写回前校验当前会话仍匹配，避免切换会话后污染状态。

## 加载优先级

优先级从高到低：

1. 最新未完成回答恢复。
2. 当前首屏可见记录的图表数据。
3. 最近 5 条历史记录的图表数据。
4. 更早历史记录的图表数据。
5. 推荐问题等非首屏附属信息。

最新未完成回答恢复不受历史图表并发队列阻塞。

## 数据流

1. 用户点击历史会话或页面从隐藏状态恢复。
2. 前端请求会话详情。
3. `currentChat` 立即更新，页面先展示已有记录和骨架。
4. 扫描记录，找到最新未完成回答。
5. 最新未完成回答立即调用 `restoreRecordTask()`。
6. 已完成但缺图表数据的历史记录加入加载队列。
7. 队列按优先级和并发上限调用 `chatApi.get_chart_data(recordId)`。
8. 请求完成后校验 `chatId` 或加载版本号。
9. 校验通过则写回对应记录；失败则丢弃结果。

## 错误处理

- 当前生成任务恢复失败：保留在对应回答上展示错误，并停止该条任务恢复。
- 历史图表数据加载失败：只影响对应图表卡片，允许后续重试。
- 会话已切换：丢弃旧请求结果，不弹全局错误。
- 请求重复：队列按任务键去重，不重复调用相同 `recordId` 的图表数据接口。

## 性能约束

- 默认历史图表并发数为 3。
- 正在生成记录的恢复请求不和普通历史图表加载排队。
- 不一次性触发所有历史记录的数据请求。
- 后续可以根据实际接口耗时和浏览器表现把并发数调整为配置项。

## 测试策略

- 单元测试 `chatLoadScheduler.ts`：
  - 并发上限生效。
  - 高优先级任务先执行。
  - 相同任务键去重。
  - 取消队列后未执行任务不再运行。
  - 过期会话结果不写回。
- 回归测试 `taskRestore.ts`：
  - 有部分 `analysis` 但未终态的记录仍可恢复。
  - 非最新历史记录不会因为有旧内容被误判为正在生成。
- 组件级验证：
  - 会话切换后记录先显示，图表骨架随后补齐。
  - 最新未完成回答优先恢复。
  - 快速切换两个会话不会出现数据写错会话。

## 验收标准

- 切换到历史会话后，不需要等待全部图表数据加载完才显示聊天记录。
- 最新未完成回答能优先恢复，用户能尽快看到“思考中”状态继续更新。
- 历史图表按批次补齐，加载期间页面可滚动、可阅读已有内容。
- 同时图表数据请求数不超过设定并发上限。
- 快速切换会话不会把旧会话图表数据写到新会话。
