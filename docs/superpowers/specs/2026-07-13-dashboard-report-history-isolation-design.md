# 报表解读历史隔离设计

## 背景

当前报表解读历史统一保存在浏览器 `localStorage` 的
`dashboard_report_prompt_history:v1` 键下。整张看板、不同图表、不同看板以及同一浏览器中的不同登录用户都会读取这份共享记录，导致问题和解读结果串用。

## 目标

- 报表解读历史必须按工作空间、用户、看板和解读目标隔离。
- 保持现有行为：每个隔离范围最多保留 4 条，记录保留 3 天。
- 历史记录继续保留问题、答案、标题和解读对象说明。
- 无法确定归属的旧版全局历史不迁移，升级后直接清理。

## 存储方案

继续使用浏览器本地存储，不新增后端表或接口。新存储键使用 `v2` 版本，并由以下字段组成：

1. 当前工作空间（租户）ID。
2. 当前用户 UID。
3. 当前看板 UID。
4. 解读目标作用域。

解读目标作用域规则：

- 整张看板：`dashboard`。
- 普通单图 `SQView`：`chart:<configItem.id>`。
- Tab 报表区域 `SQTab`：`tab:<configItem.id>:<activeTabName>`。

所有键片段统一规范化和转义。任一必需标识缺失时，历史功能采用失败关闭策略：不读取、不保存，避免记录落入共享或错误作用域。

## 数据流

打开报表解读面板时，组件根据当前用户、工作空间、看板和解读目标构造作用域，只加载该作用域的历史。生成解读结果后，仍向同一作用域保存问题和答案。

首次调用新版历史逻辑时删除旧的 `dashboard_report_prompt_history:v1`。旧记录没有用户 UID、看板 UID 等可靠归属信息，因此不尝试猜测或迁移。

点击历史记录时继续恢复该记录的问题和答案。由于列表已经按目标作用域隔离，恢复的答案与当前解读对象保持一致。

## 代码范围

- 调整 `reportPromptHistory.ts`，增加作用域类型、v2 键生成、失败关闭以及 v1 清理。
- 调整 `SQPreviewHead.vue`，传入整张看板的历史作用域。
- 调整 `SQComponentWrapper.vue`，传入单图或当前 Tab 区域的历史作用域。
- 扩展 `reportPromptHistory.test.mjs`，覆盖隔离和旧历史清理。

## 测试标准

- 同一作用域的保存、读取、去重、数量限制和 TTL 行为保持不变。
- 不同用户、工作空间、看板之间不能互相读取历史。
- 同一看板的整板、普通图表和不同 Tab 区域之间不能互相读取历史。
- 缺少必需标识时不创建共享历史键。
- 旧版 v1 历史被清除且不会进入任何 v2 作用域。
- 两个报表解读入口均显式传入作用域。

## 非目标

- 本次不实现跨浏览器或跨设备同步。
- 本次不修改报表解读模型提示词、数据上下文或后端会话接口。
- 本次不迁移无法可靠归属的旧历史。
