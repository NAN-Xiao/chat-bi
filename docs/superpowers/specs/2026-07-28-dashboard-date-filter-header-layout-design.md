# 仪表板日期选择器标题同排设计

## 背景

图表卡片的日期范围选择器当前独占标题下方一行。宽卡片中这会产生额外留白，并且现有图表高度公式没有扣除日期工具条的高度，导致图表内容越过卡片底边后被 `overflow: hidden` 裁剪。

## 目标

- 宽卡片中将日期选择器放在标题右侧，与标题处于同一排。
- 保持解读、刷新、全屏和更多操作位于卡片右侧操作区。
- 窄卡片中允许日期选择器换到标题下方，避免挤压标题和操作按钮。
- 使用结构化弹性布局计算剩余高度，修复图表底部坐标轴被裁剪的问题。
- 保持日期选择、图表刷新、权限和数据逻辑不变。

## 布局设计

卡片头部继续使用现有 `header-bar`，其左侧新增一个内容分组，用于承载标题和日期选择器；右侧保留现有操作区。宽卡片中，标题与日期选择器横向排列，间距为 `12px`。标题可以收缩并显示省略号，日期选择器保持稳定宽度，不参与无意义的横向拉伸。

当卡片容器宽度低于约 `560px` 时，通过现有容器查询让左侧内容分组换行：标题占第一行，日期选择器位于第二行。响应式判断基于卡片自身宽度，不使用视口媒体查询。

日期选择器不再作为 `header-bar` 之后的独立兄弟节点，因此不会额外占用一整行。无日期能力的图表只渲染标题，不保留空占位。

## 高度修复

`chart-base-container` 改为纵向 Flex 容器。头部、可选透视工具条按照实际内容高度占位，`chart-show-area` 使用 `flex: 1 1 auto` 和 `min-height: 0` 自动填充剩余空间。

删除依赖 `calc(100% - Npx)` 和 `:has(...)` 组合的图表高度公式，避免标题密度、日期选择器、透视工具条或摘要区域变化后再次产生越界。外层仍可保留 `overflow: hidden` 作为卡片边界保护，但正常图表区域不得再超过卡片内容边界。

## 行为边界

- 不修改日期筛选状态、日期格式、日期弹层和应用请求。
- 不修改图表类型、坐标轴配置、表格列逻辑或数据查询。
- 不对 ROI、游戏或任何具体业务字段增加特殊判断。
- 保留现有日期选择器的禁用、展开、键盘焦点和响应式文本省略行为。

## 验证

- 先增加失败测试，约束日期选择器位于头部内容分组内，并约束卡片使用纵向 Flex、图表区域使用剩余高度。
- 运行日期筛选器及相邻仪表板组件测试。
- 运行前端 TypeScript 构建。
- 在编辑画布和预览页分别验证宽卡片同排布局、约 `560px` 窄卡片换行，以及表格和折线图底部均不越过卡片边界。

## 非目标

- 不重新设计右侧操作按钮。
- 不改变日期弹层样式或增加快捷日期范围。
- 不调整卡片保存尺寸或仪表板网格尺寸。
