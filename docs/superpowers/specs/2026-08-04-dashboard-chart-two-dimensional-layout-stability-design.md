# 看板图表二维布局稳定性设计

## 背景

看板图表在摘要可见的大尺寸卡片中会在图表与“数据加载中”之间持续闪烁；缩小卡片使摘要隐藏后，闪烁停止。现有修复通过宽高阈值和迟滞控制摘要显隐，但没有消除摘要、图表和 `ResizeObserver` 之间的尺寸反馈。

## 根因

`chart-show-area`、`chart-content-row` 和 `chart-container` 形成嵌套 Flex 布局。图表行使用 `flex-basis: auto`，内部图表同时声明 `height: 100%`。摘要出现后，图表行的内容尺寸会参与父容器的剩余空间计算；图表重绘又改变被观察元素的尺寸，从而形成“测量、重绘、再测量”的反馈链。顶部摘要主要影响高度，侧边摘要还会影响宽度，因此只调整高度阈值不能覆盖该现象。

## 方案

保持现有摘要类型、密度和显隐策略不变，不增加新的宽高特例。

在看板图表布局层统一约束剩余空间：

- `chart-show-area` 和 `chart-content-row` 使用零 Flex 基准，剩余空间只由父容器分配，不由图表内容反推。
- 两层容器同时设置 `min-width: 0` 和 `min-height: 0`，允许顶部及侧边布局在两个轴向正确收缩。
- 图表容器继续填满分配后的图表行；摘要保持 `flex: 0 0 auto`，只占自身所需空间。
- 不修改数据加载、刷新状态或摘要业务配置，避免把布局问题转移到加载生命周期。

## 验证

1. 在响应式布局测试中先增加失败断言，要求图表剩余区域使用零基准伸缩，并具备双轴最小尺寸约束。
2. 覆盖顶部摘要和侧边摘要共用的容器规则，证明宽度与高度均被约束。
3. 运行 `SQView` 响应式、状态机、图表原子渲染和尺寸监听回归测试。
4. 运行前端构建。
5. 在大尺寸和小尺寸卡片间往返调整，确认摘要按原策略显示或隐藏，图表不再重复进入加载遮罩。

## 非目标

- 不隐藏所有摘要。
- 不改变摘要统计口径或图表数据。
- 不增加针对某个看板、图表或业务字段的尺寸特例。
