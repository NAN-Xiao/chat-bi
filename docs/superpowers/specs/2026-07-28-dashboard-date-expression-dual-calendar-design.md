# 看板日期表达式双月日历设计

## 背景

当前 `DashboardDateExpressionPicker.vue` 的右侧区域只显示开始、结束日期摘要或端点编辑卡片，缺少参考控件中的双月日历面板。用户无法从日历中直观看到快捷范围，也无法直接点击日期选择范围。

## 目标与范围

- 在现有日期表达式弹层右侧增加并排双月日期范围面板。
- 左侧快捷范围、顶部表达式摘要、取消和应用语义保持不变。
- 快捷范围变化后，双月日历同步展示并高亮解析后的开始、结束日期。
- 用户直接在日历中选择范围后，草稿自动切换为静态的“自定义时间”。
- 保留现有动态端点表达式编辑能力。
- 只修改通用日期表达式组件及其测试，不修改旧看板日期控件 `sq-view/index.vue`。
- 不在通用组件中增加 ROI 名称、看板 ID、数据源或业务字段分支。

## 方案

复用 Element Plus 的 `ElDatePickerPanel`，使用 `daterange`、`value-format="YYYY-MM-DD"` 和 `unlink-panels` 构成双月范围面板，并通过 `ElConfigProvider` 复用中文本地化配置。该方案沿用项目已有双月日期控件的组件能力，范围高亮、月份切换和日期边界由 Element Plus 负责。

不手写日历网格。手写方案虽然可以精确控制外观，但会重复处理日期排列、跨月范围、禁用状态和键盘交互，维护成本高。

## 交互与数据流

1. 弹层打开时，从当前表达式生成独立草稿，并解析出开始、结束日期。
2. 日历面板的显示值始终由草稿解析结果生成，不直接修改已应用值。
3. 点击左侧快捷范围时保留对应 `preset` 表达式，日历仅同步高亮解析结果。
4. 用户在日历选择完整范围后，将草稿改为：

```ts
{
  version: 1,
  mode: 'range',
  start: { mode: 'static', date: start },
  end: { mode: 'static', date: end },
}
```

5. 日历选择开始但尚未形成完整范围时，不提交不完整表达式，也不改变已应用值。
6. 点击“应用”后才更新组件 `v-model` 并触发既有 SQL 刷新链；取消或关闭弹层丢弃草稿。

## 布局

- 左侧快捷选项保持现有宽度和视觉样式。
- 右侧主体为双月日历，月份并排显示，并允许左右独立月份导航。
- 顶部保留紧凑的表达式名称和日期范围摘要，不再使用两张大日期摘要卡占据日历区域。
- 动态端点编辑仅在“自定义时间”模式下保留为紧凑辅助区域，不能遮挡或替代双月日历。
- 弹层宽度随双月面板调整，并设置明确的最小宽度；窄视口下允许面板内部收敛，不能让文字和操作按钮重叠。

## 校验与异常

- 日历只接受两个合法的 `YYYY-MM-DD` 日期，且开始日期不得晚于结束日期。
- 未完成的日历范围不生成表达式，应用按钮继续受现有校验状态控制。
- `all_time` 仍保留原表达式语义；因其范围超出常规日历可浏览区，日历只负责展示可用月份，不把该预设静默改成其他范围。
- 未知或无效表达式继续显示明确校验错误，不回退到默认 30 天。

## 测试与验收

- 组件契约测试验证存在 `ElDatePickerPanel`、`daterange`、`unlink-panels` 和中文 locale 配置。
- 快捷预设切换后，面板值与解析范围一致，表达式仍保持 `preset`。
- 日历选中完整范围后，生成两个静态端点并切换为自定义范围。
- 日历操作在点击“应用”前不更新外部模型；取消后外部模型保持不变。
- 动态端点编辑、表达式校验和原有日期模型测试继续通过。
- `sq-view/index.vue` 不发生修改。
- 前端定向测试和生产构建通过，并在本地浏览器中验证双月面板、月份切换、范围高亮、取消和应用行为。
