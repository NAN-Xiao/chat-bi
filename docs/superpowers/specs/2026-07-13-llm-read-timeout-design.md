# 大模型读取超时解耦设计

## 背景

当前 `LLM_REQUEST_TIMEOUT` 默认值为 45 秒，同时用于 OpenAI 客户端读取超时、流式输出空闲超时和后台任务总等待上限计算。直接把该值提高到 120 秒，会把后台任务总等待上限从约 15 分钟扩大到约 40 分钟。

## 目标

- 将大模型 HTTP 读取超时和流式输出空闲超时提高到 120 秒。
- 将后台任务总等待上限继续保持为 900 秒。
- 保持 `LLM_MAX_RETRIES=1` 不变。

## 设计

1. 将 `LLM_REQUEST_TIMEOUT` 默认值从 45 调整为 120。
2. 新增独立配置 `LLM_TASK_MAX_WAIT_SECONDS`，默认值为 900。
3. `LLMService.await_result()` 使用 `LLM_TASK_MAX_WAIT_SECONDS` 作为启用心跳时的总等待上限，不再通过 `LLM_REQUEST_TIMEOUT * 20` 推导。
4. OpenAI 和 Azure OpenAI 客户端继续使用 `LLM_REQUEST_TIMEOUT`，因此读取超时变为 120 秒。
5. 不修改模型重试、图表历史消息、Schema 裁剪或提示词逻辑。

## 配置语义

- `LLM_REQUEST_TIMEOUT`：模型连接建立后，等待响应数据的最长空闲时间，默认 120 秒。
- `LLM_TASK_MAX_WAIT_SECONDS`：一个启用流式心跳的后台模型任务允许等待的总时长，默认 900 秒。

两个配置均保留环境变量覆盖能力。

## 测试

- 验证默认读取超时为 120 秒。
- 验证默认任务总等待为 900 秒。
- 验证 OpenAI 客户端接收 120 秒超时配置。
- 验证任务总等待逻辑读取独立配置，不随读取超时增加到 2400 秒。

## 风险与回滚

读取超时提高后，单次失败请求最多会等待更久；现有一次自动重试可能使最终报错时间接近 240 秒以上。若模型服务恢复速度不理想，可通过环境变量单独下调 `LLM_REQUEST_TIMEOUT`，而不影响任务总等待上限。
