# 图表抽屉数据源权限设计

## 目标

让看板图表加载、刷新和报表解读使用图表抽屉明确绑定的数据源进行权限校验；只有图表未配置数据源时，才回退到看板的数据源。

## 背景

`ROI_test` 看板记录绑定数据源 6，但其中图表抽屉保存的数据源为 8，且 SQL 所需 ROI 表属于数据源 8。现有逻辑将看板数据源与前端传入的数据源强制要求一致，导致具备数据源 8 权限的用户也被拒绝。

## 规则

1. 图表存在有效的抽屉数据源时，该数据源是图表 SQL 执行、刷新和报表解读的唯一权限目标。
2. 图表未配置抽屉数据源时，使用看板绑定的数据源作为兼容回退。
3. 同一看板的每张图表独立校验其解析后的数据源。用户无权访问某图表的数据源时，该图表不得返回缓存、快照或新查询结果，并显示无查看权限。
4. 看板资源可见性可由看板绑定数据源或至少一张图表的解析后数据源满足；这只决定是否能取得看板布局，不授予其他图表的数据访问权。
5. 报表解读在后端从已保存的看板和组件配置解析数据源，不信任前端传入的数据源 ID。多图表解读仅接受所有目标图表均具有访问权的请求；否则返回无查看权限，避免将任一未授权图表的上下文带入模型。

## 改动范围

- 后端看板服务：抽取“图表执行数据源解析”和“看板可见图表数据源”辅助逻辑，替换看板加载、图表 SQL 预览/刷新中的单一看板数据源校验。
- 后端分析助手：报表解读目标校验改为按已保存组件解析实际数据源，忽略前端传入的不一致数据源。
- 测试：覆盖显式图表数据源优先、回退行为、单图表拒绝不泄露数据、看板可见性以及报表解读的授权和拒绝路径。

## 不做的事

- 不改变工作空间与数据源的绑定模型。
- 不将数据源 6 的权限当作数据源 8 的数据权限。
- 不修改现有看板或数据源记录。

## 验收标准

- 图表抽屉绑定数据源 8 且用户拥有 8 的查看权限时，图表可加载、刷新并可解读，即使看板记录的数据源为 6。
- 用户只拥有数据源 6 权限时，不能得到数据源 8 图表的 SQL 结果、缓存或解读上下文。
- 未配置图表抽屉数据源的既有看板仍使用看板数据源，既有权限行为不变。
