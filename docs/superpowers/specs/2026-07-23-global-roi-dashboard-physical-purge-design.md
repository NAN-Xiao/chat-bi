# 全局 ROI 看板物理清理设计

## 背景

产品侧已明确要求一次性物理清空所有工作空间中的固定 ROI 看板单例及其关联 ROI 图表。此次操作是数据治理任务，不为前端增加跨工作空间的删除入口，也不改变普通看板删除功能。

## 目标

- 物理删除 `core_roi_dashboard_chart` 中全部 ROI 图表记录。
- 物理删除 `core_roi_dashboard` 中全部 ROI 看板记录，包括每个工作空间的固定单例。
- 不修改、不删除普通看板主体数据 `core_dashboard`；仅在验证时读取其记录数。
- 让删除后的每个工作空间 ROI 页面保持可用，并可在首次新增图表时按现有单例确保流程重新创建内部记录。

## 方案

使用一次性维护脚本执行数据库清理，而不是暴露全局 HTTP 删除接口。

1. 读取并记录两张目标表的删除前行数。
2. 通过仓库既有本地 PostgreSQL 备份工具生成备份。
3. 在一个数据库事务内，先执行 `DELETE FROM core_roi_dashboard_chart`，再执行 `DELETE FROM core_roi_dashboard`。
4. 提交后重新读取两张目标表行数，要求均为零。
5. 清理 ROI 图表缓存，避免缓存短暂返回已删除的图表数据。

先删子表再删父表满足关联约束；任何 SQL 失败时事务回滚，两张表不会出现半清空状态。

## 边界

- 仅目标表：`core_roi_dashboard_chart`、`core_roi_dashboard`。
- 不影响：`core_dashboard`、推荐看板、我的看板、普通看板目录、数据源、Data Skills、工作空间与用户数据。
- 操作覆盖所有工作空间，不按租户、用户或数据源筛选。
- 此次为物理删除，不保留软删除记录，不提供恢复逻辑；恢复仅可依赖执行前备份。

## 验证

- 执行前后分别统计两张 ROI 表的记录数。
- 清理后验证两张 ROI 表均为零行。
- 额外统计 `core_dashboard` 记录数，确认清理前后不变。
- 执行后访问 ROI 页面时应显示空状态；新增 ROI 图表时应重新创建当前工作空间的固定单例。

## 风险与控制

- 风险：操作不可逆且覆盖所有工作空间。
  控制：执行前完成备份，输出备份路径与删除前计数。
- 风险：事务失败造成部分数据清理。
  控制：将两条删除语句置于同一事务，异常时回滚。
- 风险：缓存返回过期图表。
  控制：删除后清除 ROI 图表相关缓存键。
