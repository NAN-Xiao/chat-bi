# SQL 别名作用域最小修复设计

## 背景

Smart Q&A 曾生成外层查询引用子查询内部表别名的 SQL。数据库返回
`Column 'e.time' cannot be resolved` 后，现有 SQL 修复分类器没有将该错误识别为
可修复的 SQL 生成错误，因此任务直接失败。

## 目标

1. 在通用 SQL 生成规则中明确查询块的别名可见范围，降低首次生成错误 SQL 的概率。
2. 精确识别 `Column ... cannot be resolved`，让现有 SQL 修复再生成流程处理该错误。
3. 用回归测试覆盖错误识别，同时保证普通数据库内部错误不会被扩大为可修复错误。

## 设计

### SQL 生成规则

在通用 SQL 模板中增加规则：每个 `SELECT` 查询块只能引用当前查询块
`FROM`/`JOIN` 中可见的表或别名。外层查询引用子查询时，只能使用子查询别名及其
明确输出的列，不能引用子查询内部表别名。

该规则保持领域和数据源无关，不包含任何 Flam、游戏或具体字段假设。

### 错误分类

在 SQL 执行错误文本分类中增加大小写不敏感的精确模式，匹配数据库返回的
`Column '<限定列名>' cannot be resolved`。命中后分类为
`DATABASE_SYNTAX_OR_DIALECT`，复用现有的有限次数 SQL 修复再生成流程。

不将整个错误码 `1815` 加入可修复错误码集合，因为该错误码可能承载非 SQL 生成类
内部错误。连接、超时、权限和数据不可用错误继续保持不可修复分类。

### 测试

先增加一个失败测试，构造包含 `Column 'e.time' cannot be resolved` 的异常链，断言其
进入 `DATABASE_SYNTAX_OR_DIALECT`。再增加相近但不匹配的内部错误用例，证明分类范围
没有被放宽到所有 `1815` 或所有 `cannot be resolved` 文本。

提示词规则属于静态配置，通过文本断言确认通用别名作用域要求持续存在。

## 非目标

- 本次不实现基于 `sqlglot` 的执行前别名作用域 AST 校验。
- 不自动改写 SQL，也不原样重复执行错误 SQL。
- 不修改 SQL 修复次数、连接重试、权限或超时策略。

## 验收标准

- 指定错误文本会触发现有 SQL 修复再生成流程。
- 非匹配的数据库内部错误仍不触发 SQL 修复。
- 通用 SQL 生成提示包含明确的查询块别名作用域约束。
- 相关测试及受影响的 Smart Q&A SQL 修复测试通过。
