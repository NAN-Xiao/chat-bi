# 修仙实时付费图表拆分设计

## 目标

将修仙工作空间推荐看板“实时看板”中的“每小时付费数据”拆成两个独立抽屉，避免把数值字段“收入金额”错误地作为图表系列。

## 当前状态

- 看板 ID：`10604280d5a941af9720800bce6e030f`
- 当前组件 ID：`2193936101973073920`
- 当前 SQL 输出：`小时`、`支付记录数`、`收入金额`
- 当前错误配置：条形图，X 轴为小时，Y 轴为支付记录数，系列为收入金额。
- 当前布局：`x=1`、`y=1`、`sizeX=36`、`sizeY=14`。

## 方案选择

### 方案 A：拆成两个独立图表（采用）

两个抽屉复用同一条 SQL 和数据结果：

1. “每小时支付记录数”：柱状图，X 轴为小时，Y 轴为支付记录数，系列为空。
2. “每小时收入金额”：折线图，X 轴为小时，Y 轴为收入金额，系列为空。

优点是指标单位清晰，查询口径一致，相同 SQL 可复用缓存；缺点是看板组件数量增加一个。

### 方案 B：保留一个表格

用表格同时展示三个字段。配置最简单，但不利于观察小时趋势。

### 方案 C：单图双指标

在一个图中同时使用支付记录数和收入金额。当前图表配置没有明确的双纵轴合同，两种单位共用纵轴容易误导，因此不采用。

## 数据与配置

- 两个抽屉均保留当前 `event_realtime` SQL，不修改日期、事件和产品过滤条件。
- 两个抽屉均显式配置 `columns`、`xAxis`、`yAxis` 和空 `series`，不依赖字段自动推断。
- 计数图指标类型为可加指标，聚合为 `sum`。
- 收入图指标类型为可加指标，聚合为 `sum`。
- 洞察摘要保留最新值、平均值和总和；两个指标的总和都有明确业务含义。

## 布局

- 原组件改为左侧：`x=1`、`y=1`、`sizeX=35`、`sizeY=14`。
- 新组件放在右侧：`x=37`、`y=1`、`sizeX=35`、`sizeY=14`。
- 两个组件使用不同 ID，`component_data` 与 `canvas_view_info` 一一对应。

## 更新与回滚

- 更新前保存目标看板的 `component_data`、`canvas_style_data`、`canvas_view_info` 和 `version` 到 `.codex-runtime`。
- 使用租户 ID、看板 ID 和当前 `version=3` 做乐观锁更新；版本不一致时停止，不覆盖并发修改。
- 回滚时恢复备份的三个 JSON 字段和版本对应内容。

## 验证

1. 数据库中目标看板包含两个组件和两个 view 配置，ID 集合完全一致。
2. 两个 view 的 SQL 完全相同，系列均为空，Y 轴分别为支付记录数和收入金额。
3. 页面显示两张并排图，图例不再出现收入金额数值。
4. 两张图都能查询到当前小时数据，且控制台和后端日志没有新增错误。
