# 普通用户图表配置元数据权限修复设计

## 背景

普通用户在“我的看板”中添加图表后，可以进入图表编辑抽屉，但点击“图表配置”会收到“仅支持管理员调用！”提示。当前配置器初始化通过多个接口分别读取数据源详情、表、字段和工作空间事件配置；这些请求的权限语义、错误展示和返回结构彼此分散，任一请求触发管理员校验都会由全局请求拦截器直接弹出错误。

产品权限目标已经确认：普通用户只要同时拥有当前看板编辑权限和当前数据源访问权限，就应当能够使用“图表配置”和“SQL 明细”，包括生成 SQL、预览和应用图表；可见数据仍受数据源、表和字段权限限制。

## 目标

- 为图表配置器提供一个稳定、只读、权限裁剪后的元数据接口。
- 普通用户打开图表配置时不再调用管理员专用接口，也不再出现管理员权限提示。
- “图表配置”和“SQL 明细”继续使用同一份编辑权限，不新增独立权限口径。
- 管理员的数据字典维护、结构元数据维护和结构变更接口保持现有权限边界。
- 无权限、配置错误和服务异常必须明确返回，不使用空字段或预览字段进行静默替代。

## 非目标

- 不放宽结构元数据维护、结构变更申请、数据源成员管理等管理员接口。
- 不修改普通用户的数据源、表、列授权模型。
- 不引入跨工作空间或多数据源隐式可见性。
- 不改变 SQL 预览和 AI 生成 SQL 的后端安全校验。
- 不处理与本问题无关的图表编辑器重构。

## 方案对比

### 方案一：新增配置器只读元数据接口

新增数据源范围的只读接口，一次返回配置器需要的数据源摘要、可见表字段和事件目录。后端在一个入口统一完成数据源、表、字段和工作空间边界校验。

优点是权限语义明确、请求数量少、错误处理一致，并且不会扩大管理员维护接口的授权范围。缺点是需要新增一个前后端接口契约。

### 方案二：继续组合现有接口

保留多个初始化请求，只修正触发管理员校验的调用。

改动较小，但权限和失败处理继续分散；后续新增字段来源时仍容易出现部分请求成功、部分请求 403 的状态。

### 方案三：静默忽略 403

给可选请求增加静默错误选项，避免全局弹窗。

该方案只隐藏错误，可能让字段列表为空并继续保存错误配置，违反仓库“不允许静默兼容回退”的要求，因此不采用。

## 选定设计

采用方案一，新增配置器专用的只读元数据接口。

### 后端接口

建议接口：

```text
GET /datasource/builder-schema/{datasource_id}
```

接口要求当前用户拥有目标数据源的访问权限。返回结构只包含配置器运行所需信息：

```json
{
  "datasource": {
    "id": 1,
    "name": "示例数据源",
    "type": "postgresql",
    "type_name": "PostgreSQL"
  },
  "tables": [
    {
      "id": 10,
      "table_name": "orders",
      "table_comment": "订单明细",
      "custom_comment": "订单明细",
      "table_role": "event_fact",
      "fields": []
    }
  ],
  "event_catalog": {
    "groups": []
  }
}
```

具体规则：

1. 数据源不存在或当前用户不可访问时返回 `404` 或现有权限装饰器规定的 `403`，不得返回其他数据源的默认结构。
2. 普通用户只返回 `get_user_scoped_table_ids(...)` 允许访问的表。
3. 每张表只返回 `get_column_permission_fields(...)` 允许访问的字段。
4. 字段输出复用 `_build_field_list_items(...)`，保留 JSON 子字段、显示名、语义类型和表达式等通用配置器信息。
5. 表和字段注释复用工作空间范围的 `_apply_schema_comments(...)`，不得从其他工作空间读取元数据。
6. 事件目录来自当前工作空间绑定数据源的 datasource-scoped tracking 配置；只保留当前响应中可见表、可见字段能够支撑的事件和属性。
7. 管理员用户仍通过同一只读接口加载配置器数据，但不改变 `/schema-metadata`、`/schema-change` 等维护接口权限。

接口只负责读取配置器元数据，不执行 SQL、不保存图表，也不返回连接密码等敏感配置。

### 前端调用

在 `frontend/src/api/datasource.ts` 增加 `builderSchema(id)`。

`DashboardSqlEditor.vue` 的 `loadSchemaTables()` 改为只调用该接口，并继续使用现有 `dashboardBuilderMetadata` 缓存和请求序列校验：

```text
打开图表配置
  -> 校验 canEditSql
  -> 请求 builder-schema
  -> 写入 datasourceInfo、schemaTables、trackingEventCatalog
  -> 清理已失效的显式配置并显示验证信息
```

移除初始化路径中的 `getDs + tableList + N 个 fieldList + trackingConfig.get` 组合请求。加载失败时保留明确错误状态，不使用 SQL 预览字段替代完整 schema；用户可以关闭抽屉或重试，但不能在元数据不完整时误保存字段映射。

### 权限关系

图表配置入口需同时满足：

```text
dashboardCanEdit == true
canEditSql == true
当前用户拥有 datasource 访问权限
```

其中前两项控制前端编辑入口和交互一致性，数据源、表、字段权限由后端作为最终安全边界。不得新增 `chart_config` 权限，也不得根据用户角色名称在前端自行推断表字段范围。

### 错误处理

- `403`：显示当前账号无此数据源访问权限，关闭或禁用配置区域。
- `404`：显示数据源不存在或已解绑，禁止生成和应用。
- `5xx` 或网络错误：显示元数据加载失败并提供重试，不回退到预览字段。
- 返回结构缺失：视为接口契约错误，显示明确提示并禁止应用。

全局请求提示可以继续工作；配置器不得通过 `.catch(() => null)` 吞掉影响字段正确性的错误。

## 测试设计

### 后端

- 普通用户拥有数据源和全部表字段权限时，接口返回完整的可用配置器结构。
- 普通用户只有部分表权限时，不返回越权表。
- 普通用户只有部分列权限时，不返回越权字段和依赖这些字段的事件属性。
- 普通用户无数据源权限时返回 `403`，不泄露数据源摘要。
- 工作空间管理员和平台管理员仍可读取配置器结构。
- 数据源绑定到其他工作空间时，不返回其他工作空间的注释或事件目录。
- 响应不得包含密码、主机凭据等连接敏感字段。

### 前端

- 点击“图表配置”只调用 `builderSchema`，不调用 `schemaMetadata` 或其他管理员接口。
- 成功响应能正确填充数据源、表字段和事件目录。
- `403`、`404`、`5xx` 均显示对应错误并禁止应用。
- 快速切换图表或关闭抽屉时，旧请求结果不能污染当前编辑器。
- “图表配置”和“SQL 明细”仍共用 `canEditSql`。

### 回归验证

- 普通用户编辑已有图表并打开“图表配置”，不出现“仅支持管理员调用！”提示。
- 普通用户可以生成 SQL、预览并应用图表。
- 越权表和字段不会出现在选择器、生成上下文或 SQL 中。
- 管理员维护数据字典和结构变更功能保持原行为。

## 风险与控制

- **权限裁剪遗漏**：接口实现必须复用现有权限辅助函数，不重新实现一套角色判断。
- **事件目录泄露**：事件和属性必须按可见表字段过滤，不能直接返回整个工作空间配置。
- **响应体过大**：第一版沿用当前配置器所需字段；继续使用租户和数据源维度缓存，后续再根据实际规模评估分页或版本缓存。
- **旧请求残留**：前端删除原有组合请求后增加源码回归断言，防止再次引入管理员接口。

## 验收标准

- 拥有看板编辑权和当前数据源访问权的普通用户能完整使用两个配置页签。
- 图表配置初始化只经过新的只读元数据接口。
- 表级、字段级和工作空间边界在后端得到验证。
- 不放宽任何管理员维护接口。
- 相关前后端测试与现有看板回归测试全部通过。
