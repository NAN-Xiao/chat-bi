# 看板生成 SQL 日期参数设计

## 目标

看板 AI 仅在生成可变时间范围图表时使用看板日期参数占位符；固定语义的单值指标卡保留原有时间含义，不创建日期控件。

## 适用范围

仅约束 AI 生成并写入看板图表编辑器的 SQL。用户在 SQL 明细页手工编辑的内容不自动改写，避免改变用户明确输入的业务逻辑。

## 生成契约

1. 有时间字段且不是单值 `metric` 的图表属于可变时间范围图表；提示词根据其日期参数类型提供唯一允许的起止占位符。
2. 对 `yyyymmdd_number` 类型，SQL 使用 `{{dashboard_start_yyyymmdd}}` 和 `{{dashboard_end_yyyymmdd}}`；日期字段为数值时无需额外字符串转换。
3. 可变时间范围图表必须保存 `pivot.date_expression`、`pivot.time_field` 与 `pivot.date_parameter_type`，使编辑器执行时能够替换日期参数。
4. 可变时间范围 SQL 不得包含当前日期函数；缺少预期占位符或包含禁止函数时，不写入图表并返回可读的生成失败原因。
5. 固定语义单值指标卡不要求日期参数，也不保存日期控件配置。

## 流程

AI SQL 生成服务根据图表类型和时间字段判断是否需要可变时间范围。需要时，将参数类型和允许的占位符写入提示词，生成结果通过结构化校验后再更新图表 SQL 与 pivot 配置；固定指标卡跳过该分支。聊天图表转存优先保留原有 pivot，未配置的指标卡不自动创建 pivot。

## 错误处理

可变时间范围图表缺少日期参数类型或日期表达式时，生成流程返回配置缺失错误，不尝试猜测字段。其生成结果使用 `CURDATE()` 等禁止函数、或没有使用期望占位符时，返回“生成 SQL 未使用看板日期参数，请重新生成”的明确错误。

## 验证

新增回归测试：对 `yyyymmdd_number` 可变时间范围图表生成近 30 天 SQL，断言 SQL 含起止占位符、不含 `CURDATE` / `DATE_SUB`，且保存的 pivot 配置完整；对固定指标卡断言不要求日期参数；对聊天图表转存断言既有 pivot 被保留、指标卡不自动创建 pivot。
