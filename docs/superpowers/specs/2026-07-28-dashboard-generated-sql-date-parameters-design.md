# 看板生成 SQL 日期参数设计

## 目标

看板 AI 生成 SQL 时，日期范围必须使用看板日期参数占位符，不再输出 `CURDATE()`、`NOW()`、`DATE_SUB(CURDATE(), ...)` 或其他依赖数据库当前时间的相对日期表达式。

## 适用范围

仅约束 AI 生成并写入看板图表编辑器的 SQL。用户在 SQL 明细页手工编辑的内容不自动改写，避免改变用户明确输入的业务逻辑。

## 生成契约

1. 生成提示词根据图表的日期参数类型提供唯一允许的起止占位符。
2. 对 `yyyymmdd_number` 类型，SQL 使用 `{{dashboard_start_yyyymmdd}}` 和 `{{dashboard_end_yyyymmdd}}`；日期字段为数值时无需额外字符串转换。
3. 生成结果必须同时带齐 `pivot.date_expression`、`pivot.time_field` 与 `pivot.date_parameter_type`，使编辑器执行时能够替换日期参数。
4. 生成结果不得包含当前日期函数；缺少预期占位符或包含禁止函数时，不写入图表并返回可读的生成失败原因。

## 流程

AI SQL 生成服务接收图表日期配置后，将参数类型和允许的占位符写入提示词。生成结果通过结构化校验后，再更新图表 SQL 与 pivot 配置。编辑器沿用现有 SQL 执行校验，将占位符替换为当前日期表达式计算出的日期值。

## 错误处理

当时间字段或日期参数类型缺失时，生成流程返回配置缺失错误，不尝试猜测字段。生成结果使用 `CURDATE()` 等禁止函数、或没有使用期望占位符时，返回“生成 SQL 未使用看板日期参数，请重新生成”的明确错误。

## 验证

新增回归测试：对 `yyyymmdd_number` 时间字段生成近 30 天图表 SQL，断言 SQL 含起止占位符、不含 `CURDATE` / `DATE_SUB`，且保存的 pivot 配置包含相同参数类型和有效日期表达式。
