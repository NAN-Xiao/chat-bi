# 工作空间通知头像红点扩展设计

## 背景

全局头像红点当前只提示当前工作空间的待审核加入申请，而且仅工作空间拥有者或管理员可见。用户收到其他工作空间的邀请时，虽然可以在“我的权限/工作空间请求”页面处理，但全局头像没有提示，容易遗漏邀请。

## 目标

- 当前工作空间存在待审核加入申请时，继续为该空间的拥有者或管理员显示头像红点。
- 当前用户存在待响应的工作空间邀请时，无论是否已加入其他工作空间，都显示同一个头像红点。
- 页面刷新或切换工作空间后，红点反映当时的待处理通知状态。
- 红点继续作为纯提示，不改变头像点击、菜单展开或现有导航行为。

## 非目标

- 不增加轮询、WebSocket、服务端推送或跨标签页同步。
- 不增加通知弹窗、通知列表入口、自动跳转或红点数量。
- 不提示用户自己提交且仍在等待审核的加入申请。
- 不新增或修改后端接口，也不改变工作空间申请、邀请和审核流程。
- 不为平台管理员或平台工作空间代理上下文增加该业务通知红点。

## 方案选择

### 方案一：统一工作空间通知加载器（采用）

在现有 `workspaceReviewBadge.ts` 的职责基础上，统一加载“当前空间待审核申请”和“个人待响应邀请”。加载器根据当前上下文决定需要调用的接口，分别容错，并用同一请求序号阻止旧上下文结果覆盖新状态。

优点是通知显示条件、容错和并发保护集中，`Person.vue` 只维护一个待处理数量。缺点是需要扩展现有工具函数及测试。

### 方案二：在头像组件维护两个独立计数器

分别加载审核申请与个人邀请，再通过计算属性合并显示。改动直观，但会在组件中重复权限、异常和并发处理，快速切换工作空间时还需协调两个请求的生命周期。

### 方案三：新增后端通知汇总接口

由后端一次返回所有待处理通知数量。适合未来通用消息中心，但当前已有两个可复用接口，为本次有限刷新需求新增接口和契约成本过高。

## 详细设计

### 数据来源

- 当前空间待审核加入申请：`tenantApi.tenantApplications('pending')`。
- 当前用户待响应邀请：`tenantApi.myInvitations('pending')`。

前端仍对返回记录的 `status === 'pending'` 进行校验，不依赖接口查询参数作为唯一过滤保证。

### 加载规则

1. 普通业务用户始终加载个人待响应邀请，包括普通成员以及当前没有有效工作空间的用户。
2. 当前存在有效工作空间，且角色为 `owner` 或 `admin` 时，额外加载当前空间待审核加入申请。
3. 平台管理员和平台工作空间代理不加载这两类业务通知。
4. 两类记录的待处理数量相加；总数大于零时显示红点。

### 生命周期与并发

- `Person.vue` 创建时立即加载通知，因此刷新页面后可显示红点。
- 工作空间 ID、角色或平台上下文变化时重新加载，因此切换工作空间后可显示新上下文状态。
- 不设置定时器；用户停留在同一工作空间期间新产生的通知无需实时出现。
- 统一加载器使用递增请求序号。上下文变化后，旧请求即使更晚返回也只能返回 `null`，不能覆盖新上下文状态。

### 异常处理

- 两个接口分别捕获错误，一个接口失败时仍使用另一个接口成功返回的待处理数量。
- 全部接口失败时按零条处理并隐藏红点，不弹出错误消息，也不阻塞布局渲染。
- 后续页面刷新、工作空间切换或组件重新挂载时重新尝试。

### 视觉与交互

- 继续复用 `Person.vue` 头像右上角的现有红点和无障碍文本。
- 红点不显示数量、不拦截鼠标事件。
- 点击头像仍只打开现有菜单，不增加通知弹窗或固定跳转。
- 工作空间选择框本身不增加红点。

## 测试策略

- Owner/Admin 当前空间存在待审核申请时显示红点。
- 普通成员收到待响应邀请时显示红点。
- 没有当前工作空间的用户收到待响应邀请时显示红点。
- 用户自己提交的待审核加入申请不计入红点。
- 当前空间没有申请且个人没有邀请时不显示红点。
- 平台管理员和平台工作空间代理不加载、不显示业务通知。
- 一个接口失败、另一个接口有待处理记录时仍显示红点。
- 快速切换工作空间时，旧请求结果不能覆盖新结果。
- 运行相关前端单元测试和前端构建检查。

## 验收标准

1. 刷新页面后，存在任一目标待处理通知时，头像右上角显示红点。
2. 切换工作空间后，管理员审核申请按新工作空间重新计算，个人邀请继续计入红点。
3. 普通成员或无当前工作空间用户收到邀请时也能看到头像红点。
4. 待处理通知清零并刷新页面或切换工作空间后，红点消失。
5. 两个接口互不连带失败，旧请求不污染新工作空间状态。
6. 头像点击、菜单和既有导航行为保持不变。
