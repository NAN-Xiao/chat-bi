# ROI 图表卡片日期表达式入口替换设计

## 背景

当前 ROI 看板图表卡片顶部仍使用通用双月日期范围面板。日期表达式选择器已经用于 `DashboardSqlEditor.vue`，但没有接入卡片入口。本次将截图中的卡片日期控件替换为同一个日期表达式选择器。

## 范围

- 仅替换已配置 `sourceConfig.sql.builder.dateExpressionPickerEnabled === true` 的图表卡片。
- 当前生效对象为“我的看板”ROI 看板已经迁移的 4 张图。
- 普通看板及未启用该配置的图表继续使用现有双月日期范围面板。
- 不通过看板名称、资源 ID、图表标题或业务字段在运行时代码中判断 ROI。
- 不修改 SQL 编辑抽屉中已经实现的日期表达式选择器。

## 组件方案

卡片组件 `frontend/src/views/dashboard/components/sq-view/index.vue` 复用 `DashboardDateExpressionPicker.vue`，不复制日期预设、动态端点、静态端点、校验或展示逻辑。

卡片根据图表配置计算是否启用表达式入口：

```text
sourceConfig.sql.builder.dateExpressionPickerEnabled === true
```

启用时显示表达式选择器，并隐藏现有双月日期面板；未启用时保持现有实现。

## 状态与执行

- 卡片表达式状态从 `pivot.date_expression` 初始化。
- 组件内部修改仍使用独立草稿；取消或关闭不刷新图表。
- 点击“应用”后，以所选表达式构造本次预览请求的 `pivot.date_expression`，并沿用当前图表的 `time_field`、`range_enabled` 和 `date_parameter_type`。
- 应用期间使用卡片现有阻塞刷新状态，避免重复请求。
- 请求成功后更新卡片当前会话中的表达式标签和数据；请求失败时保留上一次成功表达式与数据，并显示现有刷新失败提示。
- 卡片应用不修改 `viewInfo.pivot.date_expression` 和 Builder 持久化配置，因此不会通过看板“保存”意外改变 SQL 编辑抽屉中的默认表达式。
- 重新打开看板时仍从已保存的 `pivot.date_expression` 初始化。

## 兼容与边界

- 表达式入口只用于 SQL 图表；混合数据源、外部 MCP 和实时表继续沿用现有不支持或拒绝逻辑。
- 无效或缺失的持久化表达式不静默回退；卡片不显示可执行的新入口，并保留明确失败边界。
- 普通双月日期面板的状态、刷新和样式不做重构。
- 后端继续负责按业务时区解析表达式、渲染受控 SQL token、权限校验和缓存隔离。

## 测试与验收

- 组件契约测试确认配置开启时渲染 `DashboardDateExpressionPicker`，且不渲染双月日期面板。
- 普通图表继续渲染现有双月日期面板。
- 应用表达式时预览请求包含新表达式，并保留日期参数类型和时间字段。
- 取消、关闭和请求失败不提交卡片表达式状态。
- 4 张 ROI 图均显示新入口；普通看板抽样确认无变化。
- 浏览器验证预设、动态/静态端点、今日空结果、窄卡片布局和刷新结果。
- 前端定向测试、后端日期过滤回归和生产构建必须通过。

## 非目标

- 不增加看板全局日期筛选。
- 不把卡片临时选择持久化到看板配置。
- 不删除现有双月日期控件及其通用能力。
- 不扩大到其他看板或未迁移图表。
