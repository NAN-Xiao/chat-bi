# 字段权限禁止列表与数字 JSON 键设计

## 目标

- 字段权限只保存 `enable=false` 的受限字段，未保存字段代表允许访问。
- 权限编辑列表中受限字段稳定置顶，其余字段保持原顺序；搜索结果使用相同排序。
- 数字 JSON 对象键统一规范为 `$["1001"]`，字段列表、权限校验和运行时 SQL 表达式保持一致。
- 后端继续严格校验被提交的受限字段，不跳过无效元数据。

## 数据流

字段列表仍返回全部可配置字段，前端用已保存的禁止列表恢复开关状态，未命中条目默认 `enable=true`。展示层对结果副本做稳定排序，不修改表单原数组。保存时，`column` 权限仅提交 `enable=false` 条目；`row` 和 `table` 权限保持现有载荷语义。

数字对象键在公共 JSON path 规范化层从 `$.1001` 转为 `$["1001"]`。数据源字段列表、权限条目规范化和方言表达式编译均使用该规范形式，因此 MySQL、PostgreSQL 和 ClickHouse 生成的表达式可被 SQL 权限解析器一致识别。

PostgreSQL 的数字对象键使用字符串操作数 `->> '1001'`，数组下标使用整数操作数 `->> 1001`，避免编译阶段丢失类型。`#>> '{1001}'` 在 PostgreSQL 执行语义中无法静态区分数字对象键和数组下标，权限解析将其标记为不确定路径，并在相关来源字段存在限制时严格拒绝。

## 兼容性

- 现有完整权限矩阵无需迁移；下一次保存时自动压缩成禁止列表。
- 现有禁止条目继续生效，缺失条目继续代表允许。
- 数字键数据库元数据无需批量修改，运行时统一规范化。
- 不恢复字符串载荷兼容，字段权限仍必须以数组提交。

## 验收

- 允许字段不会出现在 `column.permissions` 保存载荷中。
- 受限字段保存并重新打开后仍为关闭状态，且显示在列表顶部。
- `$.1001` 规范为 `$["1001"]`，数字键字段可以被保存为受限字段。
- 数字键 SQL 可被字段权限精确识别。
- PostgreSQL 数字对象键不能通过数组写法或模糊 `#>>` 路径绕过限制。
- 现有权限、聊天历史重检、看板和行权限测试保持通过。
