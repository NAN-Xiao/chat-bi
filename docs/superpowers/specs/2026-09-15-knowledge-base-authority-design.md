# 知识库最高业务优先级设计

## 背景

修改前，Smart Q&A 和分析助手会加载平台级与当前工作空间级知识库文档，但系统规则把知识库限定为“事实、术语、流程和业务背景参考”，涉及指标公式、统计口径、字段选择或 SQL 范式时要求以 Data Skill 和数据源元数据为准。看板 AI SQL 生成缺少知识库加载，本次同时接入共享知识上下文。

这会导致知识库已经加载但无法修正错误语义配置。例如，数据源元数据把 `adinfo.channel` 标记为“渠道”，知识库明确声明“渠道字段是 `adinfo.mediaSource`”时，模型仍会遵循元数据并生成错误 SQL。

本次调整将知识库提升为业务语义最高优先级，使知识库能够覆盖 Data Skill、Schema 语义描述和字段元数据，同时保留权限、当前数据源边界、SQL 安全和物理可执行性校验。

## 目标

1. 当知识库与 Data Skill、表字段注释、别名、字段角色或其他语义元数据冲突时，以当前可见知识库文档为准。
2. 知识库可以定义指标公式、统计口径、表选择、字段选择、JSON 路径、时间窗口、SQL 查询范式和结果解释规则。
3. 知识库可以声明基于现有物理字段的虚拟字段或 JSON 子字段，即使该虚拟字段尚未登记在字段元数据中。
4. Smart Q&A、分析助手和看板 AI SQL 生成使用一致的知识优先级。
5. 冲突或无法执行时给出明确错误，不通过静默回退、第一字段替换或忽略知识库来生成看似有效但业务含义错误的结果。

## 非目标

1. 本次不改变知识库文档的上传、解析、启停、平台级和工作空间级可见范围。
2. 本次不引入向量检索、分块召回或按问题筛选文档；仍加载当前用户可见且状态为 `READY` 的启用文档。
3. 本次不允许知识库绕过当前用户权限、工作空间边界或当前选择的数据源。
4. 本次不允许知识库执行写操作、管理操作或其他违反 SQL 安全规则的行为。
5. 本次不要求前端展示知识库命中文档；来源可见性属于后续独立需求。

## 权威优先级

统一采用以下顺序：

1. **平台安全与访问边界**：当前用户权限、当前工作空间、当前选择的数据源、允许访问的表和字段、只读 SQL、安全限制及输出协议。
2. **物理可执行边界**：SQL 最终引用的物理数据源、物理表和基础字段必须真实存在并可访问。
3. **知识库业务规则**：当前平台级与工作空间级知识库中与问题相关的业务定义和查询规则。
4. **Data Skill**：知识库未定义的业务口径、查询范式和展示规则。
5. **Schema 语义与字段元数据**：表字段注释、别名、字段角色、JSON 子字段登记和样例值。
6. **模型推断**：仅在前述来源均未定义且不存在歧义时使用；不得把推断固化为平台规则。

“知识库覆盖 Schema”指覆盖 Schema 和字段元数据提供的**业务语义解释与逻辑映射**，不表示可以凭空创建数据库中不存在的物理表或基础字段。

## 知识库覆盖能力

### 指标与统计口径

知识库可以覆盖 Data Skill 中的指标公式、分子分母、去重主体、事件集合、成熟窗口和时间范围。例如知识库声明 DAU 使用 `UserActive` 的去重 `uid` 时，冲突的 Data Skill 不得改用事件次数。

### 表和字段选择

知识库可以覆盖字段别名、字段角色和 Schema 注释。例如：

```text
渠道字段是 adinfo.mediaSource。
按渠道统计必须使用 adinfo.mediaSource，不得使用 adinfo.channel。
```

即使字段元数据把 `adinfo.channel` 的别名设置为“渠道”，模型仍必须使用知识库指定的 `adinfo.mediaSource`。

### 虚拟字段和 JSON 路径

知识库可以声明基于已授权基础字段的 JSON 路径或 SQL 表达式。例如物理表 `event` 中存在 JSON 字段 `adinfo` 时，知识库可以定义：

```sql
JSON_UNQUOTE(JSON_EXTRACT(`event`.`adinfo`, '$.mediaSource'))
```

该表达式不要求 `adinfo.mediaSource` 已经作为虚拟字段登记，但必须满足以下条件：

- `event` 是当前数据源中已授权的物理表；
- `adinfo` 是该表真实存在且已授权的基础字段；
- 表达式是只读且符合当前数据库方言；
- 不绕过行级、租户级、产品级或字段级权限条件。

### SQL 查询范式

知识库可以覆盖 Data Skill 和元数据建议的 JOIN、CTE、日期处理、零填充和分组方式，但不能移除权限过滤、当前数据源强制过滤或 SQL 安全限制。

## 冲突处理

### 知识库内部冲突

平台级文档和工作空间级文档发生冲突时，当前工作空间文档优先。相同层级存在冲突时，不允许根据文档顺序静默选择；生成过程必须停止并明确指出冲突文档及冲突内容。

### 知识库与 Data Skill 或元数据冲突

模型必须遵循知识库，并在内部生成检查中确认冲突已按知识库解决。SQL 修复流程也必须保留知识库口径，不能为了让 SQL 执行通过而恢复到冲突的 Data Skill 或元数据字段。

### 知识库与物理数据库冲突

如果知识库引用不存在或无权限的物理表、基础字段，或者表达式不符合数据库方言，系统必须返回明确错误，说明知识规则无法在当前数据源执行。不得忽略知识库并换用其他字段，也不得伪造不存在的 Schema。

## 组件调整

### 共享知识规则

修改 `backend/apps/knowledge_base/context.py` 中的共享系统规则：

- 删除“知识库仅作为背景参考”和“字段选择以 Data Skill、元数据为准”的限制；
- 明确知识库是业务语义最高优先级；
- 明确工作空间知识优先于平台知识；
- 保留权限、数据源、只读 SQL、安全规则和物理基础标识符校验。

### Smart Q&A

Smart Q&A 已通过共享知识上下文向 SQL 生成模型注入知识库。需要更新 SQL 生成指令中的 Data Skill 权威描述，避免基础模板继续声称 Data Skill 是唯一业务口径来源。SQL 修复和重试必须携带相同知识规则。

### 分析助手

分析助手存在独立的指标定义和字段选择提示，需要改为知识库优先、Data Skill 补充。分析模型配置、SQL 生成、报告解释和后续追问必须遵循同一优先级。

### 看板 AI SQL 生成

看板 AI SQL 生成使用共享业务 SQL 上下文和知识库上下文时，必须采用相同冲突规则。生成、修复、预览和保存过程中不得丢失知识库规则。

### SQL 校验

现有物理表、基础字段、权限和只读 SQL 校验继续生效。对于知识库声明的 JSON 子字段或表达式，校验应检查其基础表和基础字段，而不是仅因虚拟字段未登记就拒绝。无法安全解析到已授权基础字段的表达式必须明确拒绝。

## 数据流

1. 根据当前用户和工作空间加载当前可见知识库文档。
2. 分离平台级和工作空间级文档，并形成稳定知识上下文。
3. 加载当前数据源、权限、Data Skill、Schema 和字段元数据。
4. 向模型明确传递统一优先级与冲突处理规则。
5. 模型根据知识库确定业务口径和字段表达式，使用 Data Skill 与元数据补齐知识库未定义部分。
6. SQL 校验器验证当前数据源、物理基础标识符、权限过滤、只读限制和数据库方言。
7. 如果知识规则不可执行，返回明确错误；如果可执行，执行 SQL 并生成结果和图表。
8. SQL 修复时重复应用同一知识优先级，禁止回退到冲突字段。

## 失败与错误信息

至少区分以下错误：

- 知识库内部存在无法消解的同层冲突；
- 知识库引用当前数据源不存在的物理表或基础字段；
- 知识库引用用户无权访问的表或字段；
- 知识库定义的表达式不符合当前数据库方言；
- 知识库要求与平台只读或 SQL 安全规则冲突。

错误信息应指出知识库规则、冲突对象和当前数据源限制，不得只返回通用“SQL 生成失败”。

## 测试策略

### 共享规则测试

- 断言共享知识系统规则明确声明知识库优先于 Data Skill 和字段元数据。
- 断言共享规则仍明确禁止绕过权限、当前数据源和 SQL 安全边界。

### Smart Q&A 回归

- 构造知识库声明 `adinfo.mediaSource = 渠道`、元数据声明 `adinfo.channel = 渠道` 的冲突上下文。
- 断言发送给 SQL 模型的规则要求使用 `adinfo.mediaSource`。
- 断言 SQL 修复上下文仍保留知识库优先级。

### 分析助手回归

- 构造知识库与 Data Skill 指标公式冲突，断言分析助手提示明确要求采用知识库公式。
- 验证 SQL 生成、结果解释和后续分析都携带统一知识规则。

### 看板 AI SQL 回归

- 构造知识库与字段元数据冲突，断言看板 SQL 生成上下文采用知识库字段。
- 验证生成、修复和预览链路不丢失知识上下文。

### 安全边界回归

- 知识库声明合法 JSON 子字段且基础 JSON 列存在时允许生成。
- 知识库引用不存在的基础字段时明确失败，不替换成相似字段。
- 知识库要求访问未授权表时仍被权限校验拒绝。
- 知识库包含写 SQL 或绕过租户过滤的要求时仍被安全规则拒绝。

## 验收标准

1. 文档“渠道字段是 `adinfo.mediaSource`”与元数据“`adinfo.channel` 别名为渠道”冲突时，三个 SQL 生成入口都明确选择 `adinfo.mediaSource`。
2. 知识库与 Data Skill 指标公式冲突时，三个入口都采用知识库公式。
3. SQL 修复不得恢复到被知识库否定的字段或口径。
4. 知识库可以使用基于已授权物理 JSON 列的未登记 JSON 子字段。
5. 知识库不能突破当前数据源、权限、只读 SQL 和物理基础标识符边界。
6. 所有新增和相关现有自动化测试通过。

## 实现与验证说明

- 三个入口及 SQL 修复统一注入完整知识上下文和知识优先规则。看板手动配置的输出协议、日期参数、用户明确选择的分析模型和权限校验仍然生效。
- 低优先级 SQL 规则、分析标识符/结果规则以及看板 JSON 映射出现违规时，调用共享业务冲突裁决。只有模型明确返回“无适用冲突规则”时才继续原校验；覆盖必须返回现有文档 ID 及可核对的原文引用。知识同层冲突、生成结果不符合知识库、无法判断或裁决异常均明确中止，不回退到旧口径。
- 自然语言规则的适用性和同层冲突识别依赖模型，不是确定性的语义证明。原文引用核验用于拒绝不存在的证据，不能替代在线模型质量验证。
- 分析助手的后端默认时间窗口沿用结构化声明：`<!-- data-skill-analysis-time:{"window_days":7,"anchor":"latest_available"} -->`。该声明也可放在知识库正文，工作空间优先于平台、知识优先于 Data Skill；同层不同窗口明确报错。用户明确指定日期仍优先。自由文本中的天数不会直接改写后端时间策略。
- 本地回归覆盖知识上下文传递、冲突证据、错误传播、后续规则继续校验、时间优先级以及 JSON 基础列/子路径权限。在线验证脚本已准备，但向配置模型发送真实知识文档和结构信息的动作被自动审批拒绝，尚未获得在线生成及执行验证结果。
- 修改保留在当前工作树；未重启服务、提交或部署，也未修改已有图表记录。生效需要运行新代码的 API 和 Worker，并重新提问生成图表。
