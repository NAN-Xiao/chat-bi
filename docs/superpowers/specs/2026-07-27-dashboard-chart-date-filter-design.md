# 看板图表独立日期筛选设计

## 背景

“我的看板”和工作空间内“推荐看板”的普通图表需要支持按图表独立选择日期范围。用户选择日期后不应立即查询，只有点击“应用”才执行当前图表 SQL。

普通历史图表默认查询昨天往前共 14 个完整自然日，即开始日期为昨天减 13 天，结束日期为昨天，不包含今天。读取 `event_realtime` 的实时图表不显示日期选择器。

当前设计阶段不修改应用代码、看板配置或数据库数据。本设计明确通用能力、SQL 契约、交互状态和后续分阶段发布边界。

## 目标

1. 在“我的看板”和工作空间内“推荐看板”的普通 SQL 图表中提供独立日期范围选择器和“应用”按钮。
2. 只有明确配置时间字段并采用合法日期参数模板的图表才显示日期操作区。
3. 日期范围必须进入原 SQL 的日期或分区谓词，支持查询原 SQL 固定窗口之外的任意合法历史日期。
4. 读取 `event_realtime` 的图表必须由后端解析识别，并隐藏整个日期操作区。
5. 日期选择只在当前页面会话内有效，不持久化到看板配置。
6. 复用现有 `pivot`、`/dashboard/sql_preview`、权限校验、缓存和图表刷新机制。

## 非目标

- 不覆盖智能问答结果图表、ROI 看板、系统统计图表、混合数据图表、外部 MCP 快照图表或 SaaS 平台模板编辑页。
- 不根据字段名、第一列、SQL 文本相似度或结果数据自动猜测时间字段。
- 不通过通用 SQL AST 自动替换任意已有日期条件。
- 不保存用户最近一次选择的日期范围。
- 当前阶段不批量更新现有看板 SQL 或 `canvas_view_info`。

## 已确认的产品规则

### 覆盖范围

- 覆盖“我的看板”和工作空间内“推荐看板”的普通 `SQView` SQL 图表。
- 每张图表独立维护日期草稿、生效日期、加载状态和错误状态。
- 一张图表应用日期不会刷新或改变其他图表。

### 显示条件

图表必须同时满足以下条件才显示日期操作区：

1. 图表类型属于普通 SQL 图表。
2. 图表明确配置了 `pivot.time_field`。
3. `pivot.range_enabled !== false`。
4. SQL 中存在一组完整、合法的受控日期参数。
5. 后端解析的实际表清单不包含 `event_realtime`。
6. 当前用户有权在该图表配置的数据源上执行 SQL。

缺少任一条件时不得猜测、自动补全或替换字段。`event_realtime` 的判定必须来自后端 SQL 解析结果，不能由前端进行字符串搜索。

如果一条 SQL 同时读取 `event_realtime` 和其他历史表，整张图表都按实时图表处理，隐藏日期选择器和“应用”按钮，继续执行原实时 SQL。

### 默认日期

- 普通图表默认开始日期为昨天减 13 天。
- 普通图表默认结束日期为昨天。
- 默认窗口共 14 个完整自然日，包含昨天，不包含今天。
- 今天和未来日期不可选。
- 开始日期允许等于结束日期。
- 默认日期应按后端应用的业务日期计算，不得通过浏览器 `toISOString()` 的 UTC 截断推导，避免跨时区日期偏移。

## 方案选择

### 采用方案

复用现有图表 `pivot` 配置和 `/dashboard/sql_preview` 执行链，在此基础上增加显式日期参数模板能力。

前端仍通过 `pivot.range=custom`、`custom_start` 和 `custom_end` 传递当前生效日期。后端先将受控日期参数渲染进原始 SQL，再执行现有 SQL 权限校验、透视聚合和查询流程。

### 未采用方案

#### 仅在原 SQL 外层筛选

该方案只能缩小原 SQL 已覆盖的日期范围。如果原 SQL 固定查询近 30 天，外层筛选无法查询两个月前的数据，因此不能满足任意历史日期选择。

#### SQL AST 自动改写

多层 CTE、多表 JOIN、留存成熟窗口和多个业务日期字段无法仅凭一个输出时间字段安全判断应替换哪个谓词。自动改写容易产生业务口径错误，不符合禁止静默猜测的原则。

#### 删除原日期条件后外层筛选

该方案可能先扫描和聚合全量数据，再执行外层过滤，分区裁剪不可控，不适合生产大表。

## SQL 参数契约

后端只接受以下固定参数，不允许自定义模板变量或任意 SQL 片段。

### 日期字段

```sql
WHERE business_date BETWEEN
  {{dashboard_start_date}}
  AND {{dashboard_end_date}}
```

### `YYYYMMDD` 分区字段

```sql
WHERE dt BETWEEN
  {{dashboard_start_yyyymmdd}}
  AND {{dashboard_end_yyyymmdd}}
```

### 时间戳字段

时间戳范围必须采用左闭右开区间，结束边界为所选结束日期的下一天零点。

```sql
WHERE created_at >= {{dashboard_start_timestamp}}
  AND created_at < {{dashboard_end_exclusive_timestamp}}
```

### 模板规则

- 开始和结束参数必须成对出现。
- 同一图表只允许使用一套明确的日期参数类型。
- 日期输入只接受后端验证通过的 ISO 自然日，不接受任意文本。
- 日期字面量由后端按数据源方言生成。
- `YYYYMMDD` 参数只能渲染为严格的 8 位日期值。
- 时间戳结束参数必须由后端根据已验证结束日期加一天生成，前端不得自行拼接时间。
- 参数不能在 SQL 注释、字符串常量或标识符中生效。
- 模板渲染后的最终 SQL 必须再次通过完整的只读、数据源、表、字段和行权限校验。

## 后端设计

### 能力判定

后端在构造看板响应时对普通图表进行只读能力判定，并在响应中添加临时能力信息，不写回 `canvas_view_info`。

能力信息至少区分：

- `available`：时间字段和模板完整，且未读取实时表。
- `realtime`：实际读取 `event_realtime`，隐藏日期操作区。
- `unconfigured`：缺少时间字段或合法参数模板。
- `unsupported`：混合数据、外部 MCP 快照或其他不在本期范围内的图表。
- `forbidden`：当前用户无权执行图表 SQL。

前端只对 `available` 状态渲染日期操作区。其他状态不得回退为猜测字段或原始日期范围。

### 表解析

- 使用现有结构化 SQL 解析能力提取真实物理表清单。
- schema 限定、大小写和合法引号不应影响 `event_realtime` 识别。
- SQL 注释、字符串常量和同名 CTE 不得造成误判。
- 任一真实物理表解析为 `event_realtime` 时，整张图表能力状态为 `realtime`。

### 执行顺序

1. 校验当前用户、租户、工作空间和执行数据源上下文。
2. 校验开始日期、结束日期和普通图表不得包含今天或未来日期的规则。
3. 对模板 SQL 做安全占位处理并解析真实物理表清单。
4. 如果读取 `event_realtime`，拒绝应用日期参数并返回 `realtime` 能力状态。
5. 校验时间字段和日期参数是否完整、成对且类型一致。
6. 按受控参数类型和数据源方言渲染日期字面量。
7. 对渲染后的最终 SQL 执行现有只读、表字段权限和行权限校验。
8. 执行原 SQL，再复用现有透视聚合和图表结果处理。
9. 返回查询结果、刷新时间和临时日期能力信息。

### 缓存

缓存键必须包含现有租户、用户或行权限、数据源和透视边界，并增加：

- SQL 模板内容。
- 开始日期。
- 结束日期。
- 日期参数类型。

不同日期范围不得复用同一结果。首次加载允许先读取对应默认日期范围的缓存，未命中后再执行 SQL。用户点击“应用”时强制刷新当前图表。

## 前端设计

### 状态模型

每张图表按图表 ID 独立维护：

- `draftRange`：日期选择器当前草稿。
- `appliedRange`：最近一次成功查询使用的范围。
- `pendingRange`：当前请求使用的范围。
- `capability`：后端返回的临时日期能力。
- `applying`：当前图表是否正在应用日期。
- `applyError`：当前应用失败信息。

状态只存在于当前页面组件生命周期，不写入 Pinia 持久化、浏览器存储或看板保存请求。

### 首次加载

1. 加载看板及每张图表的临时能力信息。
2. 对 `available` 图表初始化默认近 14 天范围。
3. 将图表加入现有并发数为 2 的加载队列。
4. 优先读取“SQL 模板 + 默认日期范围”的缓存，未命中后执行查询。
5. 默认范围查询完成前保持图表加载态，不短暂展示原始全范围结果。
6. `realtime`、`unconfigured`、`unsupported` 和 `forbidden` 图表不进入日期默认刷新队列。

### 用户交互

- 日期控件位于图表标题下方的现有透视工具栏中。
- 日期范围选择器旁显示“应用”按钮。
- 修改日期只更新 `draftRange`，不发送请求。
- 日期为空、范围非法、包含今天或未来日期、或与 `appliedRange` 相同时，“应用”按钮禁用。
- 点击“应用”只刷新当前图表。
- 查询期间当前图表显示加载状态，日期控件和按钮禁用，其他图表不受影响。
- 查询成功后用结果更新图表，并将请求范围写入 `appliedRange`。
- 查询失败时保留上一次成功数据和 `appliedRange`，同时保留新的 `draftRange` 供修改或重试，并显示明确错误。
- 刷新页面、切换看板或重新进入页面后恢复默认近 14 天。

### 响应式布局

- 日期控件不得遮挡图表标题或右侧图表操作按钮。
- 容器宽度不足时，日期选择器和“应用”按钮整体换到下一行。
- 不通过缩小字体、负字距或覆盖定位强行塞入单行。
- 实时图表不渲染日期操作区，也不额外显示解释性占位文字。

## 推荐看板行为

工作空间内推荐看板与我的看板使用同一查询、权限和日期交互逻辑。推荐看板本身保持只读，用户日期选择只属于当前页面会话，不写回推荐看板配置。

本设计不覆盖 SaaS 平台模板编辑页。平台模板快照和管理员刷新机制维持现状。

## 错误处理

- 日期校验失败：不发送 SQL 请求，显示明确日期错误。
- 模板参数缺失或不成对：能力状态为 `unconfigured`，不显示控件。
- SQL 解析失败：不得猜测表清单；按不可应用日期处理并记录后端错误。
- 权限失败：清空无权查看的新结果，不以旧缓存绕过权限。
- 查询忙或普通执行失败：保留当前用户已有的上一次成功结果，并允许重试。
- `event_realtime` 图表收到日期请求：后端拒绝日期应用，返回明确能力状态；不能静默套用历史日期条件。

## 测试设计

### 后端测试

- 三类合法日期参数渲染。
- 参数缺失、不成对、混用和位于注释或字符串中的拒绝行为。
- 非法日期、开始晚于结束、包含今天和未来日期的拒绝行为。
- 时间戳结束日期正确转换为下一天的排他边界。
- `event_realtime` 在普通、schema 限定、引号和多表 SQL 中的识别。
- 注释、字符串常量和同名 CTE 不造成实时表误判。
- 渲染后的最终 SQL继续执行只读、表、字段和行权限校验。
- 不同日期范围、租户、用户权限和数据源的缓存隔离。
- 默认窗口严格为昨天往前共 14 天。
- 日期查询路径没有看板或业务数据写操作。

### 前端测试

- 只有 `available` 图表显示日期选择器和“应用”按钮。
- 默认日期准确且不包含今天。
- 草稿日期变化不触发请求。
- 点击“应用”只刷新当前图表。
- 两张图表的日期和加载状态相互隔离。
- 成功后更新 `appliedRange`，失败后保留旧数据和新草稿。
- `event_realtime`、未配置、无权限和不支持图表隐藏日期操作区。
- 页面刷新或切换看板后恢复默认范围。
- 我的看板和推荐看板行为一致。
- 窄卡片下标题、日期控件和按钮无重叠。

### 集成与浏览器验证

- 检查实际请求，确认选择日期前无查询、点击“应用”后只有当前图表查询。
- 检查后端最终执行 SQL，确认日期参数进入原始分区或时间谓词。
- 验证查询两个月前等原固定窗口之外的数据。
- 验证普通图表不能选择今天，实时图表完全不显示日期控件。
- 验证桌面和窄屏布局、加载态、失败态和重试流程。
- 验证整个交互没有调用看板保存接口或产生数据库写入。

## 分阶段发布

### 第一阶段：通用能力

- 实现后端模板识别、日期渲染、实时表判定、能力返回、权限校验和缓存隔离。
- 实现前端逐图表日期状态、选择器、“应用”按钮、默认加载和错误回退。
- 增加自动化测试和浏览器验证。
- 不修改现有看板 SQL、`canvas_view_info` 或业务数据。

第一阶段完成后，没有合法日期参数模板的现有图表仍不显示日期选择器。这是显式未配置状态，不进行兼容猜测。

### 第二阶段：图表配置迁移

第二阶段必须单独获得用户批准后执行：

1. 备份目标看板的完整 SQL 和 `canvas_view_info`。
2. 按工作空间、看板和图表 ID 建立明确迁移清单。
3. 为每张图表确认业务时间字段、参数类型和成熟窗口口径。
4. 将日期参数写入原 SQL 的可下推日期谓词，并补齐明确时间字段配置。
5. 对每张 SQL 执行只读预览、结果等价性、日期边界和性能验证。
6. 分批更新看板配置，并保留可恢复备份。

不得批量猜测字段，不得将 `event_realtime` 图表纳入日期模板迁移。

## 完成标准

只有同时满足以下条件，功能才可声明完成：

- 通用代码和测试通过。
- 我的看板与推荐看板的逐图表交互通过浏览器验证。
- 最终执行 SQL 的日期谓词和权限边界得到实际证据。
- `event_realtime` 图表被可靠隐藏。
- 没有看板配置或业务数据的非授权写入。
- 已迁移图表具备备份、验证记录和明确回滚路径。
