# 工作空间特殊 SQL 看板设计

## 背景

当前普通看板以工作空间绑定的数据源为唯一业务数据上下文。前端 SQL 抽屉使用图表的 `datasource` 进行预览和保存，后端加载看板时要求图表数据源与看板数据源一致，并通过普通数据源权限校验后执行 SQL。

本需求增加一种明确隔离的工作空间特殊看板：看板归属于当前工作空间，但不使用该工作空间绑定的主数据源。工作空间管理员可以从当前工作空间配置的特殊数据源白名单中为每个图表选择数据源，并维护、预览和发布 SQL；普通成员只能查看已发布结果。无论管理员编写的 SQL 是否包含租户条件，系统都必须根据当前工作空间对应的租户边界强制执行数据隔离。

特殊看板是普通工作空间数据源模型的受控例外，不改变普通看板、Smart Q&A、分析助手或其他业务入口的数据源选择规则。

## 目标

- 新增工作空间级特殊 SQL 看板类型，与普通看板的数据源执行路径隔离。
- 允许工作空间管理员维护当前工作空间的特殊数据源白名单。
- 允许工作空间管理员在图表 SQL 抽屉中选择白名单数据源并编辑、预览、发布和回滚 SQL。
- 同一个特殊看板允许不同图表选择不同的特殊数据源。
- 普通成员只能执行当前工作空间已发布的 SQL，不能提交临时 SQL 或修改数据源。
- 租户过滤从服务端登录态取得，并由数据库策略或后端 SQL AST 处理强制执行。
- SQL、白名单、缓存、审计和版本记录均包含租户边界。
- 保持普通看板现有的单数据源、工作空间绑定和权限行为不变。

## 非目标

- 不允许普通看板绕过工作空间数据源绑定。
- 不创建跨工作空间共享同一条看板或 SQL 配置的行为；每个工作空间的特殊看板和发布版本完全独立。
- 不把特殊数据源加入工作空间数据源列表，也不改变数据源与工作空间的单绑定模型。
- 不允许工作空间管理员查看或修改数据源密码、密钥等连接凭据。
- 不允许普通成员编辑、预览、发布 SQL 或查看未发布草稿。
- 不支持跨数据源 JOIN；每条图表 SQL 只在一个选定数据源中执行。
- 首期只支持工作空间管理员手工维护 SQL，不接入 SQL 构建器、AI 生成 SQL、Data Skills 或工作空间语义元数据。
- 不允许 DML、DDL、存储过程调用或多语句 SQL。
- 不使用前端传入的 `tenant_id` 作为隔离依据。
- 不以字符串拼接或正则替换实现租户条件注入。
- 不为无法安全分析的 SQL 提供无租户过滤的兼容回退。

## 核心概念

### 工作空间归属

使用新的看板来源值 `workspace_special_sql`。该来源只改变特殊看板的数据源选择、SQL 维护和执行路径，不改变 `CoreDashboard.tenant_id` 的资源归属。在当前代码模型中，`tenant_id` 承载工作空间边界，因此本文产品表述统一使用“工作空间”，持久化和认证上下文仍沿用现有 `tenant_id` 与 `_current_tenant_id(...)`。特殊看板只属于一个工作空间，只有当前工作空间内有资源查看权限的成员可以访问。

特殊看板的 `CoreDashboard.datasource` 保持为空，表示它不使用工作空间主绑定数据源，也没有看板级唯一数据源。每个图表在工作空间 SQL 配置记录中保存自己的 `datasource_id`。后端保存特殊看板画布时移除或忽略图表中的 `sql`、`datasource` 和 `sourceConfig.sql`，工作空间 SQL 配置是唯一事实来源；加载编辑器时通过独立管理接口读取草稿，加载普通看板结果时由后端读取已发布版本并执行，避免用户通过篡改画布 JSON 改变数据源或 SQL。

### 特殊数据源策略

特殊数据源策略描述一个物理数据源能否用于特殊 SQL 看板，以及系统如何对它实施租户隔离和 SQL 安全控制。物理连接继续复用 `core_datasource`，但特殊策略不构成新的工作空间绑定。

策略至少包含：

- `datasource_id`：物理数据源。
- `status`：是否允许用于特殊看板。
- `policy_version`：安全策略版本；策略变化后使旧预览验证和缓存失效。
- `tenant_isolation_mode`：`database_rls` 或 `sql_ast`。
- `allowed_schemas`、`allowed_tables`：可查询对象白名单。
- `tenant_table_rules`：需要租户隔离的表及租户字段映射。
- `query_timeout_seconds`：单次查询超时。
- `max_result_rows`：最大返回行数。
- `allow_functions`、`deny_functions`：可选的函数策略。

连接凭据、租户隔离模式、表级策略和外部租户键映射属于平台安全配置，工作空间管理员不能修改。工作空间管理员只能把平台已启用且明确对当前工作空间可用的策略加入或移出当前工作空间白名单。可选策略列表不能通过普通工作空间数据源列表或全部 `core_datasource` 推导，必须由特殊数据源策略的工作空间可用范围明确给出。

### 工作空间特殊数据源白名单

白名单是特殊数据源策略与工作空间之间的专项授权关系，不是 `CoreDatasource` 的工作空间主绑定关系。一个工作空间可以配置多个特殊数据源，同一个平台特殊数据源也可以授权给多个工作空间，但每次查询只能使用当前工作空间的白名单记录。该专项授权只允许 `workspace_special_sql` 看板执行已发布 SQL，不让特殊数据源出现在普通看板、Smart Q&A 或分析助手的数据源上下文中。

白名单记录包含：

- `tenant_id`：沿用现有字段名，值为当前工作空间 ID
- `special_datasource_policy_id`
- `external_tenant_key`：当前工作空间在目标数据源中的租户值，由平台受控映射解析；默认可与工作空间的 `tenant_id` 相同
- `status`
- `create_by`、`update_by`、`create_time`、`update_time`

唯一约束为 `tenant_id + special_datasource_policy_id`。其中 `tenant_id` 表示工作空间 ID。所有列表、创建、更新和删除操作都必须使用服务端当前工作空间作为过滤条件。工作空间管理员提交白名单变更时只能提交策略 ID；后端从平台受控映射写入或解析 `external_tenant_key`，不得接受工作空间管理员提供的外部租户值。

### 工作空间图表 SQL 配置

SQL 不能只保存在共享画布 JSON 中。系统新增工作空间图表 SQL 配置，以 `tenant_id + dashboard_id + chart_id` 唯一标识一个工作空间内的图表查询；其中 `tenant_id` 使用现有工作空间标识。

配置包含：

- `tenant_id`
- `dashboard_id`
- `chart_id`
- `datasource_id`
- `draft_sql`
- `draft_version`
- `published_sql`
- `published_version`
- `last_validated_sql_hash`
- `last_validated_datasource_id`
- `last_validated_policy_version`
- `last_validated_by`、`last_validated_at`
- `published_by`、`published_at`
- `create_by`、`update_by`、`create_time`、`update_time`

发布和回滚使用独立的不可变版本表，记录 SQL、数据源、策略摘要、操作者和时间。普通成员加载看板时只读取 `published_sql` 和 `published_version`；草稿永远不进入普通成员执行路径。

## 角色与权限

本文“工作空间管理员”对应当前工作空间中的现有租户管理员角色。SQL 维护权属于该角色，不要求平台管理员代为维护；平台管理员只负责物理连接、租户隔离策略和外部租户键映射等平台安全配置。

| 能力 | 平台管理员 | 工作空间管理员 | 普通成员 |
| --- | --- | --- | --- |
| 维护物理连接凭据 | 允许 | 禁止 | 禁止 |
| 维护特殊数据源安全策略 | 允许 | 禁止 | 禁止 |
| 维护当前工作空间特殊数据源白名单 | 可代管 | 允许 | 禁止 |
| 选择图表特殊数据源 | 可代管 | 允许 | 禁止 |
| 编辑和预览 SQL 草稿 | 可代管 | 允许 | 禁止 |
| 发布、回滚 SQL | 可代管 | 允许 | 禁止 |
| 查看已发布看板 | 按资源权限 | 按资源权限 | 按资源权限 |
| 查看连接凭据或其他工作空间配置 | 禁止跨边界展示 | 禁止 | 禁止 |

工作空间管理员只能管理当前认证上下文 `current_user.tenant_id` 对应工作空间下的白名单和 SQL 配置。接口忽略请求体中的 `tenant_id` 或工作空间字段，并以服务端当前工作空间覆盖；跨工作空间资源统一按不存在处理，避免泄漏资源标识。

## 数据模型

建议新增三组表：

### `core_special_datasource_policy`

平台级特殊数据源安全策略。`datasource_id` 唯一，保存租户隔离模式、允许对象、限制参数和状态。复杂结构使用经过 Pydantic 校验的 JSON 字段，禁止保存无法识别的自由格式配置。

### `core_workspace_special_datasource`

工作空间特殊数据源白名单。表中继续使用 `tenant_id` 保存工作空间 ID，唯一约束 `tenant_id + special_datasource_policy_id`，并分别为 `tenant_id`、策略 ID 和状态建立查询索引。

### `core_dashboard_chart_sql` 与 `core_dashboard_chart_sql_version`

前者保存当前草稿与发布指针，唯一约束 `tenant_id + dashboard_id + chart_id`；后者保存不可变版本，唯一约束 `tenant_id + dashboard_id + chart_id + version`。版本记录必须同时保存 `datasource_id`，保证回滚 SQL 时连同原数据源一起恢复。

所有外键或服务层校验必须确认：

- 看板属于当前工作空间且 `source=workspace_special_sql`。
- 数据源存在于当前工作空间启用的特殊白名单。
- 图表 ID 确实存在于当前看板画布中。
- 删除图表时同步软删除 SQL 配置，但保留审计版本。

## 租户隔离

### 租户来源

查询租户只能从后端认证上下文取得：

```text
current_user -> current workspace tenant_id -> workspace whitelist -> external_tenant_key
```

预览、发布校验、普通加载、定时刷新和缓存刷新必须复用同一解析函数。任何请求体、查询参数、画布 JSON 或 SQL 字面量中的租户值都不能替代服务端租户上下文。

### `database_rls` 模式

数据库原生行级安全是首选模式。后端在独立事务中为连接设置当前工作空间对应的租户上下文，数据库策略根据该上下文过滤数据。租户上下文必须使用事务级设置，并在连接归还连接池前自动清理，禁止会话级租户状态泄漏到下一请求。

数据库策略应覆盖所有允许查询的租户业务表。发布前校验需要确认策略仍启用；策略缺失或状态不可验证时拒绝预览和发布。

### `sql_ast` 模式

数据库不支持可靠 RLS 时，后端使用 SQLGlot 解析 SQL，并对策略中声明的每一个租户表注入参数化租户谓词。注入发生在聚合、窗口函数和 LIMIT 之前，并覆盖 JOIN、子查询、CTE、UNION 各分支及表别名。

执行器必须同时验证：

- SQL 为单条 `SELECT` 或 `WITH ... SELECT`。
- 所有物理表均在允许对象白名单内。
- 每个需要隔离的物理表都已成功注入租户谓词。
- 租户值通过绑定参数传递，不进入 SQL 字符串拼接。
- SQL 方言与所选数据源一致。
- 不存在无法安全改写的动态 SQL、过程调用或不受支持语法。

任一条件无法证明时返回明确的“当前 SQL 无法安全应用租户过滤”错误，不执行原始 SQL。

### 防止管理员绕过

工作空间管理员拥有 SQL 维护权，但不拥有租户隔离策略维护权。即使管理员自行编写其他租户 ID、移除 `WHERE`、使用嵌套查询或改写别名，最终执行 SQL 仍必须经过当前工作空间对应租户边界的强制隔离。管理员在编辑器中看到的 SQL 可以显示一个只读的“系统将强制应用当前工作空间租户过滤”状态，但不得提供关闭开关。

## 后端接口

特殊 SQL 看板使用独立接口，避免放宽普通 `/dashboard/sql_preview` 的数据源权限和工作空间约束。

### 白名单管理

- `GET /dashboard/special-sql/datasources`：返回当前工作空间已启用的白名单数据源，不返回凭据。
- `POST /dashboard/special-sql/datasources`：工作空间管理员把可用策略加入当前工作空间白名单。
- `DELETE /dashboard/special-sql/datasources/{id}`：工作空间管理员移出白名单；存在已发布图表引用时拒绝删除并返回引用列表。

### SQL 维护

- `GET /dashboard/special-sql/{dashboard_id}/charts/{chart_id}`：工作空间管理员读取当前草稿、发布版本和可选数据源。
- `PUT /dashboard/special-sql/{dashboard_id}/charts/{chart_id}/draft`：保存数据源与 SQL 草稿，不影响普通成员结果。
- `POST /dashboard/special-sql/{dashboard_id}/charts/{chart_id}/preview`：在当前工作空间租户隔离下预览草稿。
- `POST /dashboard/special-sql/{dashboard_id}/charts/{chart_id}/publish`：重新校验并原子发布 SQL 与数据源。
- `GET /dashboard/special-sql/{dashboard_id}/charts/{chart_id}/versions`：读取版本历史。
- `POST /dashboard/special-sql/{dashboard_id}/charts/{chart_id}/rollback`：把指定历史版本复制为新版本并发布，不改写历史记录。

接口通过 `dashboard_id + chart_id` 确认资源归属，不能仅凭 `chart_id` 操作。

### 看板加载

普通 `load_resource` 保留现有入口，根据 `CoreDashboard.source` 分流：

- 普通看板继续走当前工作空间数据源逻辑。
- `workspace_special_sql` 看板为每个图表读取当前工作空间的已发布 SQL 配置，验证白名单后调用特殊执行器。
- 没有发布版本的图表返回“图表尚未发布 SQL”，不得执行画布中的草稿或旧快照。
- 普通成员响应不返回草稿、连接配置或完整 SQL；工作空间管理员通过独立管理接口读取 SQL。
- 某个图表执行失败只影响该图表，其他图表继续加载。

## SQL 抽屉交互

工作空间管理员打开特殊看板图表抽屉时：

1. 后端返回当前工作空间白名单数据源和当前草稿。
2. 管理员选择数据源后加载该数据源允许展示的 schema 和表字段元数据。
3. 切换数据源立即清空 SQL、预览数据、轴字段、透视配置、构建器状态和上一次预览签名；不自动把旧字段映射到新数据源。
4. 管理员编辑 SQL 并执行预览，预览结果明确标识数据源和当前草稿版本；后端记录通过校验的 SQL 哈希、数据源和策略版本。
5. 保存草稿不影响普通成员；发布成功后普通成员下一次刷新使用新版本。
6. 发布按钮只在最新草稿已通过当前数据源、当前工作空间租户策略的预览和校验后可用；SQL、数据源或策略版本任一变化都会使验证状态失效。

普通成员不能打开编辑抽屉。若产品需要展示 SQL 明细，应另设只读权限，并只展示已发布 SQL，不展示连接信息、草稿和策略内部配置。

## 执行与缓存

新增 `execute_tenant_special_dashboard_query` 作为唯一特殊 SQL 执行入口。它负责：

1. 校验看板与用户属于当前工作空间。
2. 校验图表使用的是当前工作空间已启用白名单数据源。
3. 加载特殊数据源安全策略和外部租户键。
4. 校验并改写 SQL，或设置数据库 RLS 租户上下文。
5. 使用只读连接执行，施加超时和最大结果行数。
6. 记录请求 SQL 摘要、最终执行 SQL 摘要、数据源、租户、用户、图表、版本、耗时和结果状态。

缓存键至少包含：

```text
tenant_id + user_permission_scope + dashboard_id + chart_id
+ datasource_id + published_version + effective_sql_hash
```

应用了用户级行权限时必须包含用户边界。草稿预览和已发布查询使用不同缓存命名空间；发布、回滚、白名单变更或安全策略变更必须使相关缓存失效。禁止跨工作空间使用过期缓存兜底。

## 发布与一致性

发布在单个系统数据库事务中完成：

1. 锁定当前图表 SQL 配置。
2. 重新校验管理员权限、白名单、数据源策略和 SQL。
3. 可选执行受限的零行或小结果验证查询。
4. 写入不可变版本记录。
5. 更新当前发布指针、数据源和发布人。
6. 提交后清理对应查询缓存。

SQL 草稿保存、发布和回滚采用乐观版本号。客户端提交旧 `draft_version` 时返回冲突，禁止静默覆盖另一管理员的修改。

## 错误处理

- 非工作空间管理员维护白名单或 SQL：返回权限错误。
- 跨工作空间访问看板、白名单或版本：按资源不存在处理。
- 数据源不在当前工作空间白名单：返回明确的数据源不可用错误。
- 切换数据源后 SQL 未重新预览：禁止发布。
- SQL 包含未授权表、写操作、多语句或危险函数：拒绝预览和发布。
- 无法安全应用租户隔离：拒绝执行，不回退到原始 SQL。
- 已发布数据源被禁用或移出白名单：停止执行并提示工作空间管理员重新配置。
- SQL 版本冲突：返回冲突错误，保留双方内容供管理员重新比较。
- 查询超时或结果超限：终止查询并返回受控错误，不暴露连接凭据或底层堆栈。

## 审计

以下操作必须写审计日志：

- 工作空间管理员新增、移除或启停白名单。
- 图表切换特殊数据源。
- SQL 草稿保存、预览、发布和回滚。
- SQL 安全校验拒绝。
- 查询执行成功、失败、超时和权限拒绝。

日志不得记录数据源密码或完整结果数据。完整 SQL 可进入受控的 SQL 版本表；通用应用日志只记录 SQL 哈希、版本和受限摘要。

## 迁移与兼容

- 新增表和 `workspace_special_sql` 来源值，不修改普通看板记录。
- 历史普通看板不会自动转换为特殊看板。
- 特殊看板创建时 `CoreDashboard.datasource` 必须为空；普通看板仍必须遵守现有数据源约束。
- 特殊看板保存画布时清理画布 JSON 中的 SQL 和数据源执行配置；历史异常数据即使仍含这些字段，特殊执行路径也必须忽略并记录一致性告警。
- 首期不支持把普通看板直接改成特殊看板；通过明确的创建或复制入口生成特殊看板，避免改变已有资源语义。
- 回滚发布只生成新版本，不删除历史记录。

## 测试策略

### 后端单元与集成测试

- 普通看板仍拒绝图表数据源与看板数据源不一致。
- 特殊看板允许不同图表选择不同白名单数据源。
- 工作空间管理员只能维护当前工作空间的白名单、草稿和版本。
- 普通成员不能保存、预览、发布或回滚 SQL。
- 数据源不在当前工作空间白名单时预览、发布和加载均失败。
- 请求体伪造 `tenant_id` 或工作空间 ID 不会改变实际执行工作空间。
- RLS 连接上下文在连接归还后被清理，不会串工作空间。
- AST 模式覆盖 JOIN、CTE、子查询、UNION、聚合和别名，并对不支持语法拒绝执行。
- 未授权表、DML、DDL、多语句和危险函数被拒绝。
- 草稿不影响普通成员，发布后切换到新版本，回滚生成新的发布版本。
- 乐观锁阻止两个工作空间管理员静默互相覆盖。
- 缓存不会跨工作空间、跨用户权限、跨数据源或跨发布版本命中。
- 白名单或策略禁用后已有图表停止执行。

### 前端测试

- 只有工作空间管理员在特殊看板中看到数据源选择和 SQL 编辑能力。
- 数据源列表只包含当前工作空间白名单。
- 切换数据源后 SQL、字段映射、预览和构建器状态全部清空。
- 未重新预览不能发布。
- 保存草稿和发布具有明确的不同状态提示。
- 普通看板 SQL 抽屉行为保持不变。
- 普通成员不能通过构造请求调用维护接口。

### 安全测试

- 两个工作空间使用相同特殊数据源和相同 SQL 时只返回各自映射的租户数据。
- 管理员在 SQL 中硬编码其他租户值仍不能访问其他工作空间对应的数据。
- 通过嵌套 CTE、UNION、JOIN、子查询和别名尝试绕过租户条件均失败。
- 连接池复用、缓存命中、并发预览和超时重试不会产生跨工作空间数据。
- 错误响应、日志和审计不泄漏连接凭据或其他租户标识映射。

## 分阶段实施

### 第一阶段：安全基础与后端能力

- 新增特殊数据源策略、工作空间白名单、SQL 配置和版本表。
- 复用现有工作空间管理员权限，并新增特殊 SQL 管理权限点和执行器。
- 完成一种目标数据库的租户隔离模式，其他数据库在策略层保持禁用。
- 新增独立的白名单、草稿、预览、发布和回滚接口。

### 第二阶段：看板与抽屉交互

- 新增特殊看板创建入口和 `workspace_special_sql` 分流。
- 在特殊看板 SQL 抽屉中加入白名单数据源选择、草稿和发布状态。
- 完成数据源切换清理、字段元数据加载和错误提示。

### 第三阶段：运行与治理

- 接入看板加载、刷新、缓存和审计。
- 增加版本历史、回滚和并发编辑冲突处理。
- 完成跨工作空间安全测试、性能测试和灰度开关。

## 验收标准

1. 工作空间管理员可以为当前工作空间特殊看板的每个图表选择工作空间白名单数据源并维护 SQL。
2. 普通成员只能看到已发布结果，不能执行任意 SQL 或读取草稿。
3. 特殊看板不依赖当前工作空间数据源，普通看板的数据源规则完全不变。
4. 同一特殊数据源被多个工作空间使用时，任何查询、缓存、预览和错误路径都不会返回其他工作空间对应的数据。
5. 数据源切换不会保留旧 SQL、字段映射或预览结果。
6. SQL无法安全应用租户过滤时明确失败，不执行无过滤查询。
7. SQL 发布和回滚可审计、可追溯，工作空间管理员之间的并发修改不会静默覆盖。
8. 后端、前端和跨工作空间安全回归测试全部通过。
