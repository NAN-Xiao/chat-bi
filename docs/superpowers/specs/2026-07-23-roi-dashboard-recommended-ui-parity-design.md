# ROI 看板与推荐看板界面能力统一设计

## 背景

当前 ROI 看板使用独立的 `RoiDashboardPanel`、`RoiChartGrid`、`RoiChartCard` 和
`RoiSqlEditor`。普通推荐看板则通过预览画布、`SQComponentWrapper` 和
`DashboardSqlEditor` 提供图表展示与配置能力。两套实现的页面结构、图表工具栏、
布局行为、配置项、抽屉和视觉规范已经出现明显差异。

本次调整要求 ROI 看板与普通推荐看板保持相同功能和样式。ROI 只保留独立数据源
逻辑，以及承载该逻辑所必需的独立存储和 API 边界；不再保留其他 ROI 专用前端行为。

## 目标

- ROI 页面采用普通推荐看板的页面头、画布、图表容器、加载态和空状态。
- ROI 图表采用普通推荐看板的工具栏、全屏、刷新、解读和更多菜单能力。
- ROI 新增和编辑图表采用普通推荐看板的配置项、预览能力和抽屉视觉规范。
- 普通推荐看板与 ROI 看板复用同一套通用界面组件，避免复制样式和交互逻辑。
- ROI 图表仍保存到现有 ROI 独立表，并通过现有 ROI API 读写。
- ROI SQL 执行始终使用当前工作空间配置的 ROI 独立数据源。

## 非目标

- 不把 ROI 图表迁移到普通 `CoreDashboard` 或普通画布存储。
- 不删除 ROI 后端模型、图表 API、工作空间权限或独立数据源配置。
- 不改变普通推荐看板的数据源选择、保存格式和权限规则。
- 不为 ROI 保留专用日期筛选器、专用宽度菜单、专用工具栏或专用抽屉布局。
- 不增加 ROI 业务字段、指标口径或特定数据源名称的硬编码。

## 方案选择

采用“共享通用界面能力 + ROI 数据适配层”方案。

直接把 ROI 数据塞入完整普通画布状态，会把 ROI 独立 API、版本控制和权限模型耦合到
普通看板内部状态，改造范围和回归风险过大。只复制普通看板 CSS 和按钮则仍会保留两套
实现，后续功能会再次分叉。抽取稳定的界面边界并通过适配器连接 ROI 数据，可以同时
保证一致性和独立数据源边界。

## 架构设计

### 通用图表容器

从普通推荐看板图表包装层中提取可复用的展示外壳。外壳负责：

- 标题、卡片边框、背景、圆角、内边距和响应式尺寸；
- 解读、刷新、全屏和更多菜单的排列、图标、提示和禁用态；
- 加载、失败、无数据和只读状态；
- 图表内容插槽和操作事件，不直接依赖普通画布 store。

普通推荐看板和 ROI 看板都使用该外壳。普通看板继续由现有画布状态提供数据，ROI
则由 ROI store 和 API 提供数据。编辑、删除、移动等具体命令由各自适配层执行。

### 通用配置抽屉

从 `DashboardSqlEditor` 中提取或复用稳定的抽屉框架和图表配置界面，包括：

- 抽屉宽度、标题区、关闭行为和滚动区域；
- “图表配置”和“SQL 明细”切换；
- 图表类型、轴、系列、表格列、透视、洞察等普通看板配置项；
- 图表预览、数据预览、校验提示和加载状态；
- 底部取消与应用操作区。

通用抽屉通过明确的输入模型和 `preview`、`apply`、`cancel` 事件工作，不直接写入普通
看板或 ROI store。普通看板保持现有保存适配，ROI 使用新的 ROI 配置适配器。

### ROI 数据适配层

ROI 适配层负责：

1. 将现有 `RoiChart` 转换为通用图表展示和编辑模型。
2. 将通用抽屉输出转换为现有 ROI 创建、更新和排序请求。
3. 调用 ROI 预览接口并把响应转换为通用预览模型。
4. 把刷新、编辑、删除和排序命令路由到现有 ROI API。
5. 为图表解读构建与普通推荐看板一致的图表上下文。

适配层不得读取普通看板当前数据源，也不得在 ROI 配置缺失时回退到普通数据源。

## 页面与交互

### 页面结构

- 页面标题、操作区、背景和内容留白与普通推荐看板一致。
- “添加图表”沿用普通看板按钮规格和打开抽屉流程。
- 图表使用与普通推荐看板一致的网格尺寸、间距和响应式规则。
- ROI 页面不再展示数据源副标题或其他普通推荐看板没有的身份信息。

### 图表工具栏

ROI 图表右上角与普通推荐看板保持相同顺序：解读、刷新、全屏、更多。

- 解读使用现有分析助手能力和相同交互样式。
- 刷新重新执行当前 ROI 图表 SQL，并保持统一加载和错误反馈。
- 全屏使用现有 `ChartFullscreenDialog`。
- 编辑和删除进入与普通推荐看板一致的更多菜单。
- 拖动与布局调整遵循普通看板编辑态，不保留 ROI 专用宽度下拉菜单。

### 配置抽屉

- 新增与编辑打开相同的通用抽屉。
- ROI 不再使用现有专用标签页、表单网格和底部“预览/保存”样式。
- 配置字段、校验时机、预览区和“取消/应用”行为与普通推荐看板一致。
- ROI 独立数据源在抽屉中作为已确定的执行上下文，不提供普通数据源切换入口。

## 数据源边界

- ROI 页面进入时继续读取当前工作空间的 ROI 数据源配置。
- 所有 ROI schema、SQL 预览、刷新和保存校验请求都显式使用 ROI 配置对应的数据源。
- 数据源未配置时使用普通看板一致的空状态和提示样式，但文案明确说明缺少 ROI 数据源。
- 当前用户无 ROI 数据源权限时禁用执行和编辑，不自动替换为其他已授权数据源。
- 路由文字、普通看板选中状态、历史配置或同名数据源都不能改变 ROI 执行数据源。

## 状态与错误处理

- 通用组件只表达 `loading`、`ready`、`empty`、`error` 和 `forbidden` 状态。
- ROI 适配层负责把 API 返回映射为这些状态，并保留可诊断的错误信息。
- 刷新、预览或保存失败时保留最后一次成功数据，不把失败结果伪装为空数据。
- 配置字段缺失或无效时显示明确校验信息，不自动选择第一列、其他轴或相似字段。
- 全屏、解读和抽屉关闭必须清理请求与临时状态，避免切换图表后旧响应回写。

## 兼容与迁移

- 现有 ROI 图表记录继续读取，不进行后端数据迁移。
- 适配器兼容现有通用图表配置字段；缺失的必填配置应在抽屉中明确提示并要求用户修正。
- 不增加静默字段映射或默认轴回退。
- 原 ROI 专用日期范围只在其已属于普通看板通用配置时呈现，否则不再作为卡片专用控件。
- 完成替换后删除不再使用的 ROI 专用展示和抽屉样式，避免两套界面继续共存。

## 测试范围

### 单元与组件测试

- ROI 图表到通用展示模型的转换完整且不改变数据源。
- 通用抽屉输出到 ROI API 请求的转换覆盖全部普通看板配置项。
- ROI 预览、刷新、保存只使用 ROI 独立数据源上下文。
- 图表工具栏的解读、刷新、全屏和更多菜单与普通推荐看板一致。
- 编辑、删除、加载、空状态、失败态和无权限状态行为正确。
- 无效字段不发生静默替换。
- 普通推荐看板原有组件测试继续通过。

### 构建与浏览器验收

- 运行前端相关测试、类型检查和生产构建。
- 在桌面和窄屏视口逐项对比 ROI 与普通推荐看板的页面头、图表卡片和抽屉。
- 验证图表不会重叠，工具栏不会溢出，抽屉内容和底部按钮不会遮挡。
- 验证刷新、全屏、解读、编辑、删除、新增和取消流程。
- 通过网络请求确认 ROI 预览和保存仍调用 ROI API，且数据源为 ROI 独立配置。

## 验收标准

- 除数据源上下文外，用户无法从页面结构、图表卡片、工具栏或配置抽屉辨别 ROI 与普通推荐看板使用了不同实现。
- ROI 具备普通推荐看板当前提供的通用图表功能和配置项。
- ROI 不再显示专用日期控件、专用宽度菜单或专用编辑抽屉样式。
- ROI 图表仍保存于现有 ROI 表并通过 ROI API 读写。
- ROI 的 SQL 预览、刷新和保存只使用工作空间配置的 ROI 独立数据源。
- 普通推荐看板功能和视觉没有回归。
