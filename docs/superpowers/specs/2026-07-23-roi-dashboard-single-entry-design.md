# ROI 看板单入口设计

## 背景

当前 ROI 功能在左侧导航中采用“ROI 看板”虚拟分组加多个 ROI 子看板的结构。用户需要取消下拉层级，每个工作空间只保留一个固定的“ROI 看板”入口，所有 ROI 图表统一归属该看板。

本次调整保留 ROI 独立数据源、独立图表存储、SQL 编辑器和工作空间管理员权限，不把 ROI 并入普通推荐看板或“我的看板”。

## 目标

- 左侧导航只显示一个不可展开的“ROI 看板”节点。
- 每个工作空间最多存在一个有效 ROI 看板记录。
- 移除 ROI 子看板的新建、重命名、删除和排序能力。
- 将历史多个 ROI 看板的全部图表无损归并到唯一看板。
- 保留现有 ROI 图表新增、编辑、删除、排序、预览和数据源配置能力。

## 非目标

- 不修改普通看板、推荐看板或“我的看板”的树结构。
- 不改变 ROI 数据源的工作空间绑定方式和权限边界。
- 不删除 `CoreRoiDashboard` 表，也不把 ROI 图表直接改为关联工作空间。
- 不改变 ROI SQL 的执行、只读校验、超时和数据库方言处理规则。

## 方案选择

采用“后端真实单例 + 前端固定入口”方案。

仅隐藏前端下拉列表会导致后端仍可产生多个 ROI 看板，界面语义与数据模型不一致。直接删除 ROI 看板表则会扩大 API、权限和图表编辑链路的改造范围。保留一条内部承载记录并施加工作空间单例约束，可以在较小改动范围内得到一致的数据模型。

## 前端交互

### 左侧导航

- 将现有 ROI 虚拟分组改为虚拟叶子节点，节点名称固定为“ROI 看板”。
- 节点不包含 `children`，不显示展开箭头，也不响应展开、折叠和拖动排序。
- 节点不显示新建、重命名、删除等上下文菜单。
- 点击节点进入 `/dashboard/index?dashboardMode=roi`，路由不再暴露或依赖 ROI 子看板 `resourceId`。
- 路由选中状态使用固定 ROI 节点键，避免内部承载记录创建前后导致导航跳动。

### ROI 页面

- 页面进入后读取当前工作空间的唯一 ROI 看板；存在时加载其图表，不存在时显示空看板。
- 首次新增图表时，前端先调用单例确保接口，再使用返回的内部看板 ID 创建图表。
- 内部看板 ID 只用于 ROI API 调用，不重新显示为左侧子节点，也不写回页面路由。
- 图表新增、编辑、删除、排序和刷新行为保持不变。

## 后端接口与服务

### 单例读取与创建

- 增加读取当前工作空间单例的接口；不存在时返回明确的空结果，读取操作不创建数据库记录。
- 增加幂等的单例确保接口；仅拥有现有 ROI 管理权限的用户可调用。
- 确保接口在事务内查询或创建固定名称“ROI 看板”的记录，并依赖数据库唯一约束处理并发创建竞争。
- 并发冲突时重新读取已创建记录并返回同一对象，不产生第二条有效记录。

### 旧多看板能力

- ROI 列表接口在兼容期最多返回唯一有效记录。
- 旧的新建、重命名、删除和重排接口不再承担产品能力，服务层明确拒绝调用，不能通过绕过前端创建第二个看板或删除固定看板。
- 现有按内部看板 ID 操作图表的接口继续保留，但必须验证该 ID 是当前工作空间的唯一有效 ROI 看板。
- 权限继续沿用当前规则：只有空间拥有者和管理员可访问和管理 ROI 看板。

## 数据约束与迁移

### 唯一约束

在 `core_roi_dashboard` 上增加部分唯一索引：同一 `tenant_id` 下，满足 `deleted = false` 且 `status = 1` 的记录最多一条。历史数据归并完成后再创建索引，避免迁移过程中违反约束。

### 历史归并

迁移按工作空间分别执行：

1. 按 `sort`、`create_time`、`id` 升序选择第一条有效 ROI 看板作为主记录。
2. 将主记录名称固定为“ROI 看板”，排序固定为零。
3. 收集该工作空间所有有效 ROI 看板下的有效图表，按原看板顺序以及图表的 `sort`、`create_time`、`id` 稳定排序。
4. 将这些图表的 `roi_dashboard_id` 改为主记录 ID，并把排序重排为连续值。
5. 将其余 ROI 看板软删除并停用。
6. 已删除图表保持删除状态；若仍关联被归并的看板，则同步改挂到主记录，以保持记录归属一致。

没有有效 ROI 看板的工作空间不在迁移中预创建记录，首次新增图表时再通过确保接口创建。

迁移必须在事务内执行。任何工作空间归并失败时整体回滚，不允许出现图表迁移一半或多条看板同时有效的状态。

## 状态与错误处理

- 无单例记录：显示空 ROI 看板，不作为异常。
- 无管理权限：沿用当前明确的权限提示，不创建单例。
- 数据源未配置或不可用：保留当前 ROI 页面提示和编辑限制。
- 单例并发创建：由唯一索引裁决，服务返回已经存在的唯一记录。
- 请求携带非当前工作空间单例 ID：返回明确的 `404` 或 `409`，不得自动替换为另一条记录。
- 历史数据违反预期约束：迁移失败并输出工作空间和记录标识，禁止静默丢弃图表。

## 测试范围

### 前端

- 组合树只产生一个 ROI 虚拟叶子节点，且不包含子节点和展开箭头。
- 点击 ROI 节点生成不含 `resourceId` 的 `dashboardMode=roi` 路由。
- ROI 节点没有新建、重命名、删除和拖动能力。
- 无单例时显示空页面，首次新增图表前调用确保接口。
- 单例创建后图表加载、编辑、删除和排序仍使用返回的内部 ID。
- 普通推荐看板和“我的看板”导航行为不受影响。

### 后端

- 同一工作空间只能创建或确保一个有效 ROI 看板。
- 并发确保请求返回同一记录。
- 旧多看板写接口被明确拒绝。
- 图表接口拒绝非当前工作空间单例 ID。
- 历史多个看板的图表按稳定顺序完整归并，冗余看板被停用。
- 无历史记录的工作空间保持无记录，首次确保时正常创建。
- 工作空间权限与数据隔离保持不变。

## 验收标准

- 左侧“ROI 看板”没有下拉箭头和子项，点击后可直接查看 ROI 内容。
- 页面 URL 不再包含 ROI 子看板 ID。
- 一个工作空间在数据库中最多只有一条有效 ROI 看板记录。
- 历史多个 ROI 看板中的有效图表数量在归并前后保持一致，顺序符合约定。
- 用户不能通过界面或旧 API 新建、重命名、删除、重排固定 ROI 看板。
- ROI 图表和数据源配置的既有功能通过回归测试。
