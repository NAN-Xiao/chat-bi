# 看板无查看权限后停止自动刷新设计

## 背景

看板图表查询返回 `status=failed` 且 `error_type=permission_denied` 后，页面虽然展示“没有查看权限”，但预览页的周期刷新和编辑页的短时失败重试仍可能再次选中该图表，造成无意义请求与界面重复加载。

## 目标

- 图表在当前页面生命周期内被判定没有查看权限后，不再参与自动刷新或失败重试。
- 用户手动刷新、切换看板或重新进入页面时，重新向后端判定权限。
- 权限终止状态只保存在页面内存中，不写入看板配置、草稿或数据库。
- 其他临时错误继续沿用现有重试和周期刷新策略。

## 方案

预览页和编辑页分别维护一个页面内存集合，以图表组件 ID 标记当前生命周期内已经返回 `permission_denied` 的图表。

图表数据库查询返回权限拒绝时，在保持现有失败展示状态的同时，将组件 ID 加入集合。自动刷新调度、缓存查询队列和短时重试队列只接收未被标记的图表。这样可以在调度入口统一截断后续请求，同时保留其他图表的正常刷新。

完整加载入口负责清空集合。预览页在强制刷新或切换看板并开始新一轮加载时清空；编辑页在重新加载路由对应的看板资源时清空。浏览器重新进入页面会自然创建新的集合。

集合不写入 `viewInfo`。现有 `viewInfo.error_type=permission_denied` 继续只负责渲染“没有查看权限”，不承担跨加载周期的自动刷新控制，避免旧结果或编辑器草稿阻止用户重新判权。

## 数据流

1. 图表进入缓存查询；缓存未命中或失败时进入数据库查询。
2. 数据库结果为 `permission_denied` 时，更新图表失败展示并记录组件 ID。
3. 当前刷新完成后，调度器计算下一轮任务时排除已记录组件。
4. 临时错误仍按现有上限重试；权限拒绝不增加临时重试计数。
5. 用户触发完整刷新或切换看板后清空记录，新请求重新判定权限。

## 异常与并发

- 使用现有 `loadVersion` 和 `AbortController` 防止旧请求污染新看板。
- 仅在请求仍属于当前加载版本时记录权限拒绝。
- 一个图表被拒绝不取消其他图表的请求或自动刷新。
- 权限拒绝集合为空时，行为与现有实现一致。

## 测试

- 预览页：权限拒绝图表不会进入下一轮自动刷新候选集合。
- 预览页：权限拒绝不会触发短时失败重试，其他临时失败仍可重试。
- 编辑页：权限拒绝图表不会继续进入缓存查询或短时重试。
- 生命周期重置：完整刷新或切换看板会清空拒绝集合，允许重新判权。
- 运行相关前端状态测试、类型检查和生产构建，确认没有回归。

## 非目标

- 不修改后端权限判定与错误契约。
- 不改变普通网络错误、查询繁忙或缓存未命中的重试策略。
- 不持久化权限拒绝状态，也不提供新的用户配置项。
