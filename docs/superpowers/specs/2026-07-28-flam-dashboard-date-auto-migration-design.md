# Flam 看板抽屉日期参数化设计

## 目标

为 Flam 默认看板中已确认范围的非实时、非当日抽屉启用日期控件，并将其固定近 7、14 或 30 天的查询窗口改为由看板日期参数驱动。日期切换必须改变实际 SQL 查询范围。

## 范围

迁移覆盖此前确认的留存分析、核心看板、新增看板、活跃看板、付费概览、主城建设、出征数据、渠道分析、活动分析、ROI 看板和投放看板中的指定抽屉。

不迁移 ChatMon 四类看板、实时看板、标题包含“当日”的抽屉、日充值用户数，以及没有固定近 7、14、30 天窗口的 SQL。

## 迁移策略

使用现有 `tools/enable_flam_default_dashboard_date_filters.py` 的受限自动迁移路径。只有满足以下全部条件的 SQL 才会写入：

- 只存在一个可解析的业务日期过滤窗口；
- 窗口表达式明确使用固定近 7、14 或 30 天的日期边界；
- SQL 不是实时数据、快照、累计历史或无法识别的多窗口查询；
- 迁移后可验证起止日期参数数量与日期控件配置。

符合条件的 SQL 会把业务日期窗口替换为 `{{dashboard_start_yyyymmdd}}` 和 `{{dashboard_end_yyyymmdd}}`，并配置默认“过去 30 天”日期表达式。原有图表、透视和其他元数据保持不变。

留存、LTV、活动后续付费和 ROI 的 cohort 起止日期会传入看板参数；D1、D7、30 日等成熟观察窗口保留原有定义。无法从 SQL 唯一定位 cohort 日期条件的复杂指标不会自动修改，而会在预演结果中明确列出。

## 安全与验证

脚本默认预演。写入模式对每个看板先创建恢复快照，以行锁与原始 canvas JSON 的 CAS 条件更新；写入后重新读取并验证目标抽屉的参数、控件和日期字段，同时校验所有非目标抽屉哈希不变。

测试覆盖：固定窗口识别、歧义 SQL 拒绝、日期参数替换、成熟观察期保留、目标配置读回和非目标内容不变。页面抽测会分别选择“过去 30 天”和“过去 7 天”，确认请求参数与返回数据范围发生变化。
