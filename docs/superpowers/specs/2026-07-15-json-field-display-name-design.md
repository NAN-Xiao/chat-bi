# JSON 子字段显示名称闭环设计

## 背景

平台已经通过 `JSON字段解析` Sheet 维护普通 JSON 字典字段的来源表、来源字段、
JSON 路径、生成字段名、类型和属性说明。当前 Sheet 没有“字段显示名”列，导入后
JSON 子字段的 `aliases` 为空。

字段列表接口在缺少别名时，会把 `field_comment` 的第一句回退为
`display_name`。因此类似 `adinfo.adId` 的字段在数据字典和图表字段选择器中都
显示为“来源字段 adinfo 中的 JSON 属性 adId”，而不是字段名称。

已有 `JSON 字段解析 Sheet 导入导出闭环设计` 负责来源表和 JSON 路径的权威
往返。本设计在该契约上增加显示名称，并统一 JSON 子字段在不同页面的回退规则。

## 目标

- 在 `JSON字段解析` 中增加可选的“字段显示名”列。
- 字段显示名导入后成为 JSON 字段的主显示别名，并在再次导出时保留。
- 属性说明只作为说明，不再充当 JSON 子字段名称。
- 数据字典未配置显示名时展示完整规范字段名，例如 `adinfo.adId`。
- 图表字段选择器未配置显示名时展示叶子属性名，例如 `adId`。
- 图表字段悬停信息继续展示完整字段、来源字段、JSON 路径和属性说明。
- 保持旧五列和六列 `JSON字段解析` 工作簿可导入。
- 不改变普通物理字段当前的显示名称回退行为。

## 非目标

- 不从英文属性名自动生成中文业务名称。
- 不从属性说明猜测或截取字段显示名。
- 不修改数据库表结构或增加迁移。
- 不修改事件专属属性在 `事件参数对照` 中的维护方式。
- 不改变 JSON SQL 表达式编译逻辑。
- 不在本次设计中扩展 JSON 字段的多别名编辑能力；“字段显示名”只维护主显示别名。
- 不修改普通物理字段的 `field_comment` 显示回退，避免现有 `dt` 等字段退化为技术名。

## 名称语义

JSON 子字段包含三种不同信息，必须保持职责分离：

| 信息 | 示例 | 用途 |
| --- | --- | --- |
| 规范字段名 | `adinfo.adId` | 唯一配置标识和数据字典技术名称 |
| 字段显示名 | `广告 ID` | 面向业务用户的主名称 |
| 属性说明 | `来源字段 adinfo 中的 JSON 属性 adId` | 说明、搜索和悬停信息 |

显示名优先级固定为：

1. 显式配置的字段显示名。
2. 当前页面定义的规范回退名称。

属性说明不参与名称优先级。

## Excel 契约

`JSON字段解析` 新版固定列调整为：

1. `来源表`
2. `来源字段`
3. `JSON路径`
4. `生成字段名`
5. `字段显示名`
6. `类型`
7. `属性说明`

“字段显示名”可为空。为空表示该字段没有配置业务显示名，不触发警告，也不自动
生成别名。

兼容规则：

- 旧五列工作簿继续兼容，按既有默认事件表规则解析来源表。
- 旧六列工作簿继续兼容，保留显式来源表，但字段显示名为空。
- 新七列工作簿把“字段显示名”映射为 `field_display_name`。
- 其他 Sheet 的表头和导入含义不变。

## 导入流程

专用解析器读取“字段显示名”后，继续复用 `_field_item(...)` 构造
`TenantTrackingFieldBase`。现有 `_field_item(...)` 已把
`field_display_name` 转换为 `aliases`，因此不增加新的持久化字段。

导入规则：

- 显示名非空时，去除首尾空白并保存为主显示别名。
- 显示名为空时，保存空别名，不使用属性说明补齐。
- `生成字段名`、`来源字段` 和 `JSON路径` 的严格校验保持不变。
- 独立 Sheet 与物理表 Sheet 合并同一个 JSON 字段时，显示名按独立 Sheet 的
  当前值写入，属性说明和额外属性继续按既有规则合并。
- 不保留工作簿中未表达的旧显示名，确保导入结果以工作簿为权威来源。

## 导出流程

`_json_field_parsing_rows(...)` 为每个 JSON 字典字段增加
`field_display_name`：

- 有别名时导出第一个非空别名。
- 没有别名时导出空单元格。
- 不从 `field_comment` 生成显示名。

模板导出和当前配置导出都写出新版七列表头。再次导入平台导出的工作簿后，主显示
别名、规范字段名、来源表、来源字段、JSON 路径、类型和属性说明保持一致。

## 字段列表接口

字段列表接口对 JSON 子字段和普通物理字段采用不同策略：

- JSON 子字段：`display_name` 只取第一个显式别名；没有别名时返回空。
- 普通物理字段：保留现有别名优先、字段说明回退行为。

该边界避免 JSON 的自动属性说明冒充名称，同时不影响当前依赖物理字段说明显示
“业务日期（分区字段）”的配置。

JSON 子字段判定继续使用现有 `is_json_subfield`，以及
`source_field + json_path` 元数据，不通过字段名字符串猜测。

## 前端展示规则

### 数据字典

字段名称列保持 `display_name || field_name`：

- 有显示名时，主标题显示业务显示名，副标题显示完整规范字段名。
- 没有显示名时，主标题显示完整规范字段名，不重复显示副标题。
- 属性说明继续显示在原说明列或编辑抽屉中。

示例：

| 配置 | 主标题 | 副标题 |
| --- | --- | --- |
| 显示名=`广告 ID` | `广告 ID` | `adinfo.adId` |
| 显示名为空 | `adinfo.adId` | 不显示 |

### 图表字段选择器

JSON 子字段的名称优先级调整为：

1. `displayName`
2. 显式且不同于完整字段名的 `label`
3. 从规范字段名移除 `sourceField.` 前缀后的叶子属性名

普通字段和事件字段的现有展示规则不变。

示例：

| 配置 | 下拉主名称 | 悬停元数据 |
| --- | --- | --- |
| 显示名=`广告 ID` | `广告 ID` | `event.adinfo.adId`、`adinfo`、`$.adId` |
| 显示名为空 | `adId` | `event.adinfo.adId`、`adinfo`、`$.adId` |

## 现有配置行为

代码上线后，不执行数据库迁移或自动写入：

- 现有 JSON 字段因为没有显式别名，不再显示属性说明。
- 数据字典立即回退到完整字段名。
- 图表字段选择器立即回退到叶子属性名。
- 业务显示名需要维护人员在新版 `JSON字段解析` 中显式填写并重新导入。

该行为不会静默发明业务名称，也不会修改现有字段说明。

## 错误处理

- 字段显示名为空是合法状态，不报错、不警告。
- 字段显示名只包含空白时按空值处理。
- 显示名不参与生成字段名、JSON 路径和来源字段校验。
- 旧工作簿缺少显示名列时按空值处理。
- 其他现有 JSON 字段导入错误和警告保持不变。

## 测试设计

### 后端 Excel 测试

在 `backend/tests/test_tracking_excel.py` 覆盖：

1. 新模板包含七列表头，字段显示名位于生成字段名和类型之间。
2. 新七列工作簿导入后，字段显示名进入 `aliases[0]`。
3. 字段显示名为空时 `aliases` 为空，属性说明只进入 `field_comment`。
4. 导出当前配置时，第一个别名写入字段显示名。
5. 导出后再导入，主显示名、属性说明和 JSON 元数据完整往返。
6. 旧五列和六列工作簿继续成功导入。

### 后端字段列表测试

在 datasource 字段列表测试中覆盖：

1. JSON 子字段有别名时返回别名作为 `display_name`。
2. JSON 子字段无别名、有说明时 `display_name` 为空。
3. 普通物理字段现有说明回退保持不变。

### 前端测试

覆盖 `BuilderFieldPicker` 的名称选择规则：

1. JSON 子字段优先显示显式业务显示名。
2. JSON 子字段无显示名时显示叶子属性名。
3. 普通字段继续显示现有 `displayName || label || field`。
4. 数据字典继续按 `display_name || field_name` 展示，且不从说明列取主名称。

## 验收标准

- `JSON字段解析` 导出包含“字段显示名”，并能无损导入回来。
- 显式配置显示名时，数据字典和图表字段选择器都显示该名称。
- 未配置显示名时，数据字典显示 `adinfo.adId`，图表字段选择器显示 `adId`。
- “来源字段 adinfo 中的 JSON 属性 adId”只出现在说明位置，不再作为主名称。
- 旧五列和六列工作簿兼容。
- 普通物理字段的现有友好名称不回归。
- JSON 字段 SQL 表达式、权限过滤、事件参数和来源表归属不回归。
