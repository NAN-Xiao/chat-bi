# 看板抽屉自适应布局设计

日期：2026-08-03

## 背景

看板组件当前同时包含标题、日期表达式、透视控件、洞察摘要和图表主体。外层通过若干固定的 `height: calc(100% - Npx)` 估算图表高度，内部图表再独立决定字号、间距和辅助信息。组件高度较小时，固定扣减值与实际控件高度不一致；图表内部内容高度也可能超过其容器，最终被外层 `overflow: hidden` 裁切。

现场测量中，核心看板指标卡总高约 123px，标题占 24px，图表主体仅获得 79px，但现有 Metric 紧凑布局仍需要约 106px。增加“日环比”和“周同比”后，底部对比信息因此被遮挡。

本设计把该问题作为通用看板布局能力处理，不针对“活跃用户”、特定数据源或业务字段写特殊逻辑。

## 目标

- 所有看板组件根据真实可用宽高自适应，不依赖固定像素扣减估算主体高度。
- 指标卡、趋势图、柱状图、饼图、漏斗图和表格在小尺寸下都有明确的降级行为。
- 优先保留主数据、图表主体和必要交互；空间不足时按固定顺序收起次要信息。
- 组件尺寸变化、日期控件出现或消失、透视配置变化后自动重新布局和渲染。
- Smart Q&A、全屏预览和其他非看板图表不因看板紧凑策略产生行为回归。

## 非目标

- 不改变 SQL、指标口径、日期口径或字段映射。
- 不为某个业务指标设置专用字号、阈值或文案。
- 不通过整体 CSS `transform: scale(...)` 缩小内容。
- 不在字段缺失时自动替换成其他字段。
- 不重新设计看板网格的拖拽、缩放或持久化协议。

## 方案比较

### 方案一：继续补固定高度规则

为每种控件组合继续增加 `:has(...)` 和 `calc(100% - Npx)` 规则。改动最小，但组合数量会持续增长，无法覆盖控件换行、国际化文案和未来工具栏，仍会出现估算偏差。

### 方案二：所有内容按比例缩放

对整个组件使用缩放或基于容器宽度缩小字体。实现直接，但文字可读性、点击区域、Canvas 清晰度和无障碍体验都会下降，也无法表达不同信息的优先级。

### 方案三：真实剩余空间加图表类型分级适配

外层使用 Flex/Grid 让标题和控件自然占位，主体通过 `flex: 1` 获得真实剩余高度；再将主体实测宽高转换成 `mini / basic / regular` 密度，传给各图表类型。每类图表按照信息优先级做有限降级。

采用方案三。它直接修复根因，规则可测试、可扩展，并能保持不同图表类型的可读性。

## 总体架构

### 外层布局

`SQView` 根容器改为纵向 Flex 布局：

1. 标题栏固定为自然高度，不参与压缩。
2. 日期表达式和透视控件组成统一工具区，允许在宽度不足时受控换行。
3. 图表区域使用 `flex: 1 1 auto; min-height: 0` 消化所有剩余高度。
4. 删除用于估算标题、日期和透视控件高度的多组固定 `calc(...)` 规则。

`ResizeObserver` 继续监听组件尺寸，同时测量图表主体实际宽高。密度判断使用图表主体尺寸，而不是包含标题和工具栏的整个抽屉尺寸。

### 密度协议

增加通用图表布局上下文，至少包含：

```ts
type ChartDensity = 'mini' | 'basic' | 'regular'

interface ChartLayoutContext {
  width: number
  height: number
  density: ChartDensity
  surface: 'dashboard' | 'chat' | 'fullscreen' | 'preview'
}
```

密度由宽高共同决定，并采用单一通用判定函数。初始阈值以现有看板尺寸和视觉回归结果校准，不允许各业务看板自行定义。边界附近应使用稳定判定，避免 ResizeObserver 因一两个像素变化反复切档。

布局上下文从 `SQView` 传入 `ChartComponent`，再传给具体图表实例。非看板调用方可不传，由 `ChartComponent` 根据自身容器测量并使用普通表面默认值，因此现有调用保持兼容。

## 各图表类型行为

### 指标卡

- `regular`：显示指标名、日期、主值、最多两项对比和装饰信息。
- `basic`：缩小留白和字号，保留完整信息。
- `mini`：若外层已显示同名标题，则隐藏内部重复指标名；隐藏装饰短线；保留日期、主值及最多两项对比。
- 对比项优先同行显示，宽度不足时换行；不得覆盖主值或被裁切。
- 对比日无有效分母时继续显示 `-`，不改变数据语义。
- 一张指标卡存在多个主指标时，各指标仍必须使用其明确配置；不把同一组对比值静默复用到其他指标。

### 折线图、面积图、柱状图和条形图

- 图表主体始终优先获得空间。
- `basic` 和 `mini` 逐级减少坐标轴标签密度、图例间距和洞察摘要数量。
- 标签策略只能省略显示，不得改变字段、聚合或排序。
- `mini` 下图例可折叠为紧凑形式，但至少保留当前可见系列的辨识能力。

### 饼图、漏斗图、树图和桑基图

- `basic` 下使用紧凑图例和更小的内边距。
- `mini` 下优先保证图形和关键数值，次要摘要收起。
- 漏斗图在空间允许时仍保留起始值、结束值、总体转化率和逐步转化率；空间不足时按摘要优先级逐级减少，字段发现仍保持通用和数据驱动。

### 表格

- 表头保持可见，内容区获得剩余高度并独立滚动。
- 不通过缩小到不可读字号来塞入更多行。
- 列宽、横向滚动和字段配置保持现有语义，不自动替换列。

### 散点图和热力图

- 小尺寸下降低刻度与标签密度。
- 保留轴含义和颜色映射，不因紧凑模式改变度量字段。

## 信息降级顺序

空间不足时统一按以下顺序处理：

1. 减少非必要留白和装饰。
2. 隐藏与外层重复的信息。
3. 减少洞察摘要和坐标标签密度。
4. 将图例切换为紧凑布局。
5. 允许对比项、工具控件受控换行。
6. 表格内容区滚动。

主值、必要轴含义、错误状态和用户明确选择的字段不得被静默替换或隐藏。

## 数据流与重新渲染

1. `SQView` 的 ResizeObserver 获取外层尺寸。
2. 浏览器完成标题和工具区布局后，读取图表主体的实际尺寸。
3. 通用函数计算密度，并生成布局上下文。
4. `ChartComponent` 在布局上下文变化时重新渲染当前图表实例。
5. 图表实例只读取布局上下文，不查询全局 DOM id，也不自行推测看板业务。

为避免高频抖动，尺寸更新沿用短时合并调度；只有宽、高或密度发生有效变化时才触发重绘。

## 异常与边界处理

- 主体宽或高为 0 时不渲染，待 ResizeObserver 获得有效尺寸后再执行。
- 极端小尺寸下显示明确的最小可读状态，不让内容互相覆盖。
- 加载、空数据和失败状态沿用主体的真实剩余空间居中，不使用固定最小高度撑破抽屉。
- 全屏模式默认使用 `regular`，但仍根据真实容器尺寸响应窗口变化。
- Chat、分析助手和商店预览不继承看板专用的“隐藏重复标题”规则，除非调用表面明确提供了外层标题。

## 测试策略

### 单元与组件契约测试

- 密度判定覆盖宽、高边界及边界稳定性。
- `SQView` 不再包含按控件组合硬编码的主体高度扣减规则。
- `ChartComponent` 在尺寸或密度变化时重绘，在 0 尺寸时延迟渲染。
- Metric 在三种密度下验证可见元素、对比项数量、换行和空值格式。
- 表格在小高度下验证表头可见、内容区可滚动。

### 视觉回归

至少覆盖以下视口和组件尺寸：

- 桌面宽屏四列指标卡，包含日期、主值、日环比和周同比。
- 窄桌面与移动宽度下的单列、双列卡片。
- 同一组件分别带日期控件、透视控件，以及两者同时存在。
- 指标卡、折线图、柱状图、饼图、漏斗图和表格的 `mini / basic / regular` 三档。
- 看板普通视图、编辑缩放过程和全屏预览。

验收时使用 Playwright 截图和 DOM 几何检查，断言关键文本的边界位于图表主体之内，且不存在内容互相覆盖。指标卡还需断言 `scrollHeight <= clientHeight`，或在设计允许滚动的表格中只允许指定内容区产生滚动。

## 验收标准

- 截图中的“活跃用户”卡片在当前尺寸下完整显示日期、主值、日环比和周同比。
- 四张顶部指标卡以及其他看板的指标卡在相同尺寸下均无裁切。
- 日期或透视控件出现后，图表主体使用真实剩余空间，不再依赖固定扣减高度。
- 所有主要图表类型在三档尺寸下没有文本重叠、无意义空白或不可操作控件。
- 现有字段配置、数据权限、日期语义和图表类型不发生变化。
- 前端类型检查、相关单元测试和视觉检查全部通过。

## 实施边界

首轮实施应集中在共享布局协议、`SQView`、`ChartComponent` 和各图表的尺寸表现上。任何看板种子 SQL、业务 Data Skill、数据源配置和看板持久化数据均不在本次修改范围内。
