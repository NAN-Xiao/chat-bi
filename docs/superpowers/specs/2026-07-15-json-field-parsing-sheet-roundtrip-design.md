# JSON 字段解析 Sheet 导入导出闭环设计

## 背景

修仙数据字典工作簿新增了独立的 `JSON字段解析` Sheet，固定列为：

1. `来源字段`
2. `JSON路径`
3. `生成字段名`
4. `类型`
5. `属性说明`

当前 `parse_tracking_excel(...)` 只专门处理 `_说明`、`_表映射`、
`事件参数对照`、`事件分组` 和 `_SQL规则`。其余 Sheet 都会被当作物理表
Sheet 解析。因此 `JSON字段解析` 会被误认为一张名为“JSON字段解析”的业务表，
其中的记录不能写入真实 `event`、`user` 等表的字段元数据，也不能进入运行时
JSON SQL 表达式编译链路。

当前导出逻辑还会把带有 `source_field/json_path` 的配置字段写回 `event/user`
属性 Sheet。仅修复导入不能满足“JSON 子字段只维护在独立总览 Sheet，不写入
event/user Sheet”的要求，因此本次同时补齐导入和导出闭环。

## 目标

- 将 `JSON字段解析` 定义为固定系统 Sheet，并提供专用解析器。
- 把有效记录转换为现有 `TenantTrackingFieldBase` 字段元数据。
- 同一来源字段同时存在于事件表和用户表时，优先归属默认事件表。
- 复用现有运行时 SQL 方言编译器，不在 Excel 中保存方言相关表达式。
- 导出当前配置时，将普通 JSON 字典字段写入 `JSON字段解析` Sheet。
- `event/user` 属性 Sheet 只写物理字段和非 JSON 派生字段；通用表可保留承载
  枚举值映射的兼容行，但字段集合仍以独立 Sheet 为权威。
- 对空路径确认行给出明确警告并跳过，不生成可查询字段。
- 保持事件专属属性继续由 `事件参数对照` 维护，不迁移到总览 Sheet。

## 非目标

- 不从数据库自动采样或推断新的 JSON 路径。
- 不修改 `事件参数对照` 的事件属性结构和导入语义。
- 不新增数据库表或迁移。
- 不为修仙项目硬编码表名、字段名或业务口径。
- 不把空路径确认行保存为可查询字段，也不保证这类提示行在平台再次导出时保留。

## Sheet 契约

Sheet 名固定为 `JSON字段解析`，有效数据行必须同时包含：

- `来源字段`：承载 JSON 文本的物理字段名。
- `JSON路径`：以 `$` 开头的合法 JSON 路径。
- `生成字段名`：内部可查询字段名，通常为 `来源字段.子路径`。
- `类型`：文本、数值、布尔、时间、数组、对象或空值。

`属性说明` 可为空，用作字段注释。

专用解析器不得复用全局表头中“类型 -> row_type”的旧格式含义，而应在
`JSON字段解析` 上下文中将该列解释为字段类型。`生成字段名` 也只在此专用
解析器中映射为 `field_name`，避免改变其他 Sheet 的既有表头兼容行为。

## 导入流程

### 固定 Sheet 识别

新增 `JSON_FIELD_PARSING_SHEET = "JSON字段解析"`，并加入 `SYSTEM_SHEETS`。
这样通用业务 Sheet 循环不会再把它识别为物理表。

导入顺序调整为：

1. 解析系统说明、表映射、SQL 规则、事件参数和事件分组。
2. 解析物理表 Sheet，建立物理字段和非 JSON 配置字段。
3. 最后解析 `JSON字段解析`，让独立 Sheet 成为普通 JSON 字典字段的权威来源。
4. 统一去重并执行既有事件分组校验。

### 来源表解析

工作簿按已确认格式不包含“来源表”列，因此解析器根据当前绑定数据源的
`physical_schema` 查找包含 `来源字段` 的候选物理表：

1. 如果当前默认事件表是候选表，选择默认事件表。
2. 否则如果只有一个候选表，选择该表。
3. 如果没有候选表，报错并给出 Sheet 行号和来源字段。
4. 如果存在多个候选表且无法按默认事件表消歧，报错并列出候选表，不静默选择。

该规则满足当前 `event/user` 同名字段以 `event` 为主，同时保持平台逻辑对其他
行业和表名通用。

### 字段构造与校验

对每个有效行：

- 规范化 `JSON路径`。
- 根据 `来源字段 + JSON路径` 计算规范字段名。
- `生成字段名` 必须与规范字段名一致；不一致时直接报错并包含行号。
- 构造 `row_type=dictionary_field` 的内部行，复用 `_field_item(...)` 完成字段角色、
  来源字段、JSON 路径、注释和额外属性构造。
- `semantic_type=number` 时，运行时 SQL 编译器生成数值转换；其他类型使用文本
  JSON 提取表达式。
- `类型=空值` 时按文本语义保存，避免无依据的数值转换；原始观察类型保存在
  字段额外属性中，导出时仍可显示“空值”。

如果同一 `table_name + 生成字段名` 同时出现在物理表 Sheet 和独立 Sheet：

- 定义完全一致时去重。
- `source_field`、`json_path` 或类型不一致时导入失败并指出冲突，不能静默覆盖。

### 空路径确认行

当 `JSON路径` 或 `生成字段名` 为空时，该行不生成字段：

- 返回包含 Sheet 名、Excel 行号和来源字段的警告。
- 计入导入摘要的 `skipped_rows`。
- 不写入可查询字段，不生成 SQL 表达式。

这适用于当前 `power`、`abtest` 等仅确认来源字段存在、但采样为空对象的记录。

## 导出流程

导出当前配置时，从 `config.fields` 中选择同时具有 `source_field` 和 `json_path`
的普通 JSON 字典字段，生成 `JSON字段解析` Sheet：

| 输出列 | 数据来源 |
| --- | --- |
| 来源字段 | `field.source_field` |
| JSON路径 | `field.json_path` |
| 生成字段名 | `field.field_name` |
| 类型 | `field.semantic_type` 的中文类型；空值使用保存的原始观察类型 |
| 属性说明 | `field.field_comment` |

记录按物理表优先级、来源字段和 JSON 路径稳定排序。由于 Sheet 不包含来源表，
同名来源字段仍按导入规则由默认事件表优先解析。

如果配置中多个物理表拥有同名来源字段：

- 默认事件表中的 JSON 字段作为该来源字段的有效导出定义，符合“事件表优先”规则。
- 其他表中完全相同的重复定义不再重复输出。
- 如果没有默认事件表候选，或其他表存在不同的 JSON 子字段定义，导出必须明确失败，
  不能生成一个再次导入后会改变表归属的歧义工作簿。

`_attribute_sheet_rows_for_table(...)` 应排除上述 JSON 字典字段，确保其不再写入
`event/user` 属性 Sheet。通用表的旧格式可以继续导出 `dictionary_field/field_value`
兼容行，以保留五列总览无法表达的枚举值映射；存在独立 Sheet 时，导入后的 JSON
字段集合、来源字段和路径仍以独立 Sheet 为权威。没有 `source_field/json_path` 的
普通派生字段继续保留在原物理表 Sheet。

事件映射中的 `event_name_mappings[].properties` 继续只导出到 `事件参数对照`，
不重复写入 `JSON字段解析`。

模板导出和当前配置导出都保留 `JSON字段解析` 表头；无有效 JSON 字段时输出
空表头 Sheet。

## SQL 生成链路

本次不修改 `compile_tracking_json_expression(...)`。导入成功后的字段已包含：

- `table_name`
- `source_field`
- `json_path`
- `semantic_type`

现有字段列表、语义上下文和 SQL 构建器继续在运行时按 MySQL、PostgreSQL 或
ClickHouse 方言生成表达式。这样 Excel 不携带数据库方言相关 SQL，也不会把
某个客户数据源的表达式硬编码到平台配置中。

## 错误与警告

以下情况导入失败：

- 有效行的来源字段不存在于当前物理 schema。
- 来源字段命中多个表且默认事件表无法消歧。
- JSON 路径非法。
- 生成字段名与来源字段、JSON 路径计算结果不一致。
- 独立 Sheet 与物理表 Sheet 中的同名 JSON 字段定义冲突。
- 导出时发现独立 Sheet 无法表达的多表同名来源字段冲突。

以下情况仅警告并跳过：

- JSON 路径为空。
- 生成字段名为空。

警告和错误均包含 `JSON字段解析`、Excel 行号和来源字段，便于维护人员直接定位。

## 测试设计

在 `backend/tests/test_tracking_excel.py` 增加以下用例：

1. 独立 Sheet 的有效行导入为正确的表名、来源字段、JSON 路径、字段名和类型。
2. 来源字段同时存在于事件表和用户表时选择默认事件表。
3. 来源字段只存在于用户表时选择用户表。
4. 多表歧义且没有默认事件表候选时明确失败。
5. 空路径或空生成字段名行被警告、跳过并计入摘要。
6. 生成字段名与 JSON 路径不一致时明确失败。
7. `类型=空值` 按文本语义导入，并保留原始观察类型用于导出。
8. 独立 Sheet 不会产生名为 `JSON字段解析` 的业务表。
9. 导出包含固定五列表头，JSON 字段不再出现在 `event/user` Sheet。
10. 导入后再次导出、再导入，JSON 字段定义保持一致。
11. 使用导入字段调用现有 MySQL JSON 表达式编译器，验证生成字段可用于 SQL。
12. 没有独立 Sheet 的现有工作簿继续按原有物理表 Sheet 规则导入。
13. 导出遇到无法按默认事件表消歧的同名来源字段时明确失败。

## 预计修改范围

- `backend/apps/system/crud/tracking_excel.py`
- `backend/tests/test_tracking_excel.py`
- `docs/generic_tracking_excel_template.md`

不修改数据库模型、迁移、前端上传入口和 SQL 方言编译器。

## 验收标准

- 上传包含 `JSON字段解析` 的修仙工作簿后，160 条有效 JSON 路径进入字段配置；
  `power`、`abtest` 两条空路径记录被警告并跳过。
- 同名来源字段归属默认事件表，当前修仙配置中即 `event`。
- 字段列表和 SQL 生成链路能使用导入后的 JSON 字段。
- 平台再次导出时，JSON 字段只出现在 `JSON字段解析`，不出现在 `event/user`。
- 现有事件参数、事件分组和无独立 Sheet 的导入行为不回归。
