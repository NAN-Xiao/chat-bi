# ROI 看板表格铺满布局优化设计

## 背景

ROI 看板中的表格图表当前只使用卡片内容区的一部分宽度，右侧出现大面积空白。与此同时，卡片标题、日期范围和图标操作区虽然功能完整，但间距与视觉层级较机械，降低了数据阅读效率。

此前已通过固定卡片高度、固定表格行高和尺寸更新控制解决页面切换时逐行渲染、卡片闪烁的问题。本次优化必须保留这些稳定性措施，不能为了自适应高度重新引入布局抖动。

## 目标

- 表格使用卡片内容区的全部可用宽度，消除无意义的右侧空白。
- 优化卡片标题、日期范围和操作按钮的对齐、间距与视觉层级。
- 保持现有卡片固定高度和表格稳定渲染行为。
- 保持通用 BI 能力，不根据具体数据源、表名或业务字段进行特殊处理。

## 最终方案

采用“表格铺满型”布局：

1. 卡片标题栏保持单行结构，左侧显示标题，右侧依次放置日期范围和操作按钮。
2. 表格容器占满卡片内容区宽度，表格按容器宽度进行布局。
3. 可伸缩列使用剩余空间，避免数据列全部挤在左侧。
4. 当字段数量或最小可读宽度超过容器宽度时，保留横向滚动，不压缩到不可读，也不静默隐藏字段。
5. 保持当前卡片高度、表格行高和渲染尺寸控制，避免页面切换或刷新时逐行扩展和闪烁。

## 布局细节

### 卡片标题栏

- 标题保持左对齐并作为主要信息。
- 日期范围选择器靠右放置，与操作按钮形成清晰的工具区。
- 刷新、排序、宽度调整、编辑和删除按钮统一点击区域、图标尺寸和间距。
- 空间不足时优先保证标题可识别和日期选择器可操作，操作区不得覆盖标题或表格。

### 表格内容区

- 表格外层容器宽度为卡片可用宽度，不保留固定比例的右侧空白。
- 表头与数据行保持现有固定行高，避免内容加载后改变卡片高度。
- 列宽分配以当前 SQL 返回字段和显式表格配置为依据，不猜测业务含义，不替换无效字段。
- 对存在明确宽度配置的列保留配置；其余列参与剩余宽度分配。
- 当总最小列宽超过容器宽度时启用横向滚动，保证字段内容基本可读。

## 实现范围

预计涉及以下前端模块：

- `frontend/src/views/dashboard/roi/RoiChartCard.vue`：优化卡片标题栏布局和操作区间距。
- `frontend/src/views/dashboard/roi/RoiChartGrid.vue`：确认不同卡片宽度下内容区可以完整使用可用宽度。
- `frontend/src/views/chat/component/charts/Table.ts`：调整表格列宽分配或容器宽度策略，使表格铺满且保留溢出滚动。
- ROI 看板及图表尺寸相关测试：补充表格铺满、固定高度和无重复尺寸更新的回归验证。

具体修改文件以实施阶段的代码定位结果为准，不进行与本目标无关的组件重构。

## 状态与数据流

- 不增加新的后端接口或持久化字段。
- 不改变日期范围参数、单图刷新和重新执行 SQL 的现有流程。
- 不改变图表排序、宽度设置、编辑、删除和权限判断逻辑。
- 布局变化仅消费现有图表配置、SQL 返回字段和容器尺寸。

## 异常与边界处理

- 字段较多：显示横向滚动，不隐藏字段或替换字段。
- 字段较少：将剩余宽度分配给可伸缩列，避免表格集中在左侧。
- 长标题：使用现有可识别的截断方式，并保证工具区可操作。
- 小尺寸卡片：保证最小可读列宽，必要时滚动，不挤压操作按钮。
- 空数据或加载状态：继续占用稳定内容高度，避免卡片高度跳变。

## 测试与验证

- 验证表格容器和表格主体使用卡片全部可用宽度。
- 验证少字段场景不会出现大面积右侧空白。
- 验证多字段场景出现横向滚动且字段未被静默移除。
- 验证页面切换、日期刷新和重新执行 SQL 时卡片不会逐行扩展或闪烁。
- 验证全宽、半宽和三分之一宽卡片下标题栏与表格均可正常使用。
- 运行 ROI 相关测试、图表尺寸回归测试、前端类型检查和生产构建。

## 验收标准

- 表格视觉上铺满卡片内容区，不再出现当前截图中的大面积右侧空白。
- 卡片标题、日期范围和操作按钮保持单行且对齐清晰。
- 字段较多时可以横向滚动，字段较少时合理利用剩余宽度。
- 页面切换和刷新过程中不出现逐行渲染、卡片高度跳变或明显闪烁。
- 日期范围刷新、重新执行 SQL、排序、宽度调整、编辑和删除功能保持正常。
- 实现不包含具体数据源、业务字段或行业场景的硬编码。

## 非目标

- 不改为内容驱动的自适应卡片高度。
- 不改变 ROI 指标口径、SQL、数据源选择或日期范围默认值。
- 不重做整个看板页面头部或网格系统。
- 不新增图表类型、筛选能力或后端接口。
- 不通过自动替换字段、隐藏字段或猜测字段含义解决布局问题。
