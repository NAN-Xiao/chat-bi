# 看板 ROI 图表移动目标修复设计

## 背景

普通看板资产归属于当前工作空间绑定的数据源，但看板中的图表可以使用当前工作空间单独配置的 ROI 数据源执行 SQL。当前“移动到”弹窗优先使用图表执行数据源加载目标看板，导致 ROI 图表拿 ROI 数据源调用普通看板树接口，并触发普通数据源权限校验错误。

## 目标

- 目标看板列表始终按照当前看板的有效归属数据源加载。
- 移动后的图表继续保留原有执行数据源，包括 ROI 数据源。
- 不改变图表执行、SQL 权限、ROI 工作空间配置、看板渲染和普通看板树接口的权限语义。

## 设计

在前端看板选项工具中增加一个纯函数，用当前看板信息解析移动目标的数据源。该函数只读取后端返回的 `dashboardInfo.datasource`，不使用当前图表的 `datasource` 作为兼容回退。

“移动到”弹窗使用该解析结果调用现有 `list_resource` 接口。目标看板选中后的加载、目标看板保存、源看板保存及回滚流程保持不变。移动图表 payload 继续复制当前图表配置，因此图表的 ROI 执行数据源不会被替换。

如果当前看板没有有效归属数据源，弹窗返回空目标列表，不猜测或替换为图表执行数据源。这与仓库禁止静默兼容回退的约束一致。

## 权限边界

- 看板资产归属和目标看板树继续使用工作空间绑定数据源及普通数据源访问校验。
- 图表执行数据源继续由后端 `resolve_chart_execution_datasource` 校验，只允许当前空间绑定数据源或配置的 ROI 数据源。
- 不放宽 `list_resource` 对 ROI 数据源的普通访问限制，避免混淆资产归属与执行权限。

## 测试

先增加失败测试，再修改生产代码：

1. 普通图表场景解析为看板归属数据源。
2. ROI 图表场景仍解析为看板归属数据源，而不是图表执行数据源。
3. 后端已推导有效归属数据源的历史看板正常解析。
4. 缺少看板归属数据源时返回空值，不进行静默回退。
5. 运行看板选项单元测试、前端类型检查和构建验证。

## 非目标

- 不重构当前前端两阶段移动及回滚流程。
- 不新增后端移动目标接口。
- 不修改 ROI 数据源授权、绑定或 SQL 执行规则。
- 不迁移或修改现有看板数据。
