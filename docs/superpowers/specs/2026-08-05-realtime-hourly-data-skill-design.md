# “实时”小时粒度 Data Skill 设计

## 目标

统一产品内“实时”时间语义，避免 Smart Q&A、分析助手及复用同一 Data Skill 的入口把“实时收入”解释为默认历史窗口。

## 语义契约

- “实时”表示按小时聚合，不表示单个累计指标或默认多日趋势。
- 用户未指定日期时，“实时收入”解释为“今天按小时收入”。
- 用户明确指定日期或时间范围时，用户范围优先；例如“昨天实时收入”解释为“昨天按小时收入”。
- 今天的事件查询使用 `event_realtime`；已经结束的日期使用 `event`；包含今天的跨日范围沿用现有分表与合并规则。
- 规则只定义时间粒度、默认日期和通用选表，不引入收入字段、事件名或其他领域口径。

## 实现边界

1. 更新平台公共 Data Skill `platform:realtime-event-table-selection`，明确上述解释及优先级，并保留当前 Schema、权限和工作空间语义优先原则。
2. 扩展聊天日期归一化：只有问题包含“实时”且没有明确日期或时间范围时，才把日期表达式设为 `today`；显式日期不得被“实时”覆盖。
3. 修正结构化 SQL 选表校验的适用条件，使“实时”在无日期时约束今天使用 `event_realtime`，但不阻止明确历史日期使用 `event`。
4. 不增加跨数据库方言的小时函数硬编码校验。小时粒度由 Data Skill 指示模型根据当前数据源方言和时间字段生成，避免把 MySQL、PostgreSQL 等实现细节写进平台公共规则。

## 数据流

用户问题先经过平台 Data Skill 检索，得到“实时”的时间语义和选表约束。SQL 生成使用当前数据源 Schema 选择时间字段和方言对应的小时表达式；随后日期归一化根据用户显式范围或“实时”的默认规则生成看板日期表达式；结构化 SQL 校验再检查事件表选择是否与最终时间范围一致。

## 失败处理

- `event_realtime`、`event`、时间字段、权限或工作空间业务口径缺失时，继续遵循现有禁止静默回退规则，返回明确配置或权限错误。
- 无法可靠识别用户给出的日期时，不得用“实时”覆盖该日期；保留明确校验错误或要求用户澄清。
- Skill 发布继续使用现有备份、CAS 更新、embedding 刷新、发布后验证和失败恢复流程。

## 验证

- Data Skill 单元测试覆盖准确文案和触发词。
- 日期归一化测试覆盖“实时收入”默认今天，以及显式今天、昨天、绝对日期和相对范围优先。
- SQL 校验测试覆盖无日期实时查询使用 `event_realtime`、历史日期实时查询使用 `event`，并保持非事件表不受影响。
- 冲突回归测试覆盖 Skill 检索、日期模板和选表规则协同。
- 测试通过后以 dry-run 检查平台 Skill，再执行发布并验证目标 Skill、embedding 和备份结果。
