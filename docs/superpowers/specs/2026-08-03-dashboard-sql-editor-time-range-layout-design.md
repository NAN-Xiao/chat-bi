# 看板 SQL 编辑器时间范围布局设计

## 背景

“编辑图表”抽屉当前把时间范围放在“图表配置”页签内部，但日期范围同时影响图表配置生成的 SQL 和手写 SQL 明细。时间范围应作为 SQL 图表的公共配置，与执行数据源、图表标题和图表类型处于同一层级。

## 目标

- 保留“时间范围”名称。
- 将时间范围移出“图表配置 / SQL 明细”卡片，放到卡片下方的公共表单区域。
- SQL 数据源启用时，无论当前选择哪个页签，都显示同一个时间范围控件。
- 时间范围只显示日期范围选择器，不显示时间字段、时间粒度和日期参数类型下拉框。
- 编辑器内部固定使用 `dt`、`day`、`yyyymmdd_number`。

## 交互设计

公共表单区域按以下顺序展示：

1. 时间范围
2. 执行数据源
3. 图表标题与图表类型
4. 其他图表配置

时间范围沿用现有 `DashboardDateExpressionPicker`，保留预设日期和自定义日期能力。切换“图表配置 / SQL 明细”页签时，日期表达式状态不重置。

## 数据契约

SQL 图表编辑器在初始化、数据源切换、SQL 生成、预览和保存时统一使用：

- `timeField = "dt"`
- `timeGrain = "day"`
- `dateParameterType = "yyyymmdd_number"`

打开历史图表时，编辑器不再恢复这些字段的旧可选值，而是显式规范为固定契约。日期表达式仍从已保存的 `dateFilter.expression` 恢复。SQL 日期条件继续使用 `{{dashboard_start_yyyymmdd}}` 和 `{{dashboard_end_yyyymmdd}}`。

## 错误处理

- 日期表达式无效时，沿用现有明确校验提示并阻止生成或预览。
- SQL 未包含匹配的看板日期参数时，沿用现有日期参数校验，不自动改写用户 SQL。
- 数据源缺少 `dt` 字段时，不回退到其他日期字段；生成 SQL 前显示明确配置错误。

## 兼容边界

- 保留现有日期表达式、日期筛选请求和图表持久化结构。
- 保留工作区当前未提交的指标卡日期表达式兼容改动。
- 不修改 MCP 数据源的编辑流程。
- 不引入按数据源名称、ID 或业务领域分支。

## 测试

- 模板契约测试：时间范围位于页签卡片外，卡片内部不再包含时间范围区域。
- 固定值测试：初始化、恢复、生成载荷和保存均使用 `dt / day / yyyymmdd_number`。
- UI 契约测试：不再渲染时间字段、粒度和日期参数类型下拉框。
- 回归测试：日期表达式恢复、SQL 预览签名和构建器持久化测试继续通过。
- 前端类型检查与构建通过。
