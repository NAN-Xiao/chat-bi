# 移除 ROI 看板前端独立入口设计

## 背景

ROI 看板数据已经从所有工作空间物理清空，但左侧仍显示固定“ROI 看板”入口。该入口不是数据库记录，而是 `ResourceTree.vue` 构建推荐看板树时生成的虚拟节点；`SQPreviewShow.vue` 又根据 `dashboardMode=roi` 单独渲染 ROI 页面，因此删除数据不会移除产品入口。

## 目标

- 左侧推荐看板中不再显示固定“ROI 看板”入口。
- 前端不再提供 ROI 独立页面、图表编辑器或 `dashboardMode=roi` 渲染链路。
- 旧 ROI 链接进入时返回当前用户有权访问的普通看板落地页，不显示空白 ROI 页面。
- 推荐看板、我的看板、普通看板创建编辑、分享与排序行为保持不变。

## 非目标

- 不删除后端 ROI 表结构、Alembic 历史迁移、API、服务或数据源配置。
- 不修改普通看板对已配置数据源的权限校验与 SQL 执行逻辑。
- 不新增兼容性字段替换或把 ROI 路由静默映射为某个固定普通看板 ID。
- 不再次修改数据库中的业务数据。

## 前端移除范围

### 看板资源树

从 `ResourceTree.vue` 删除 ROI 虚拟节点的构造与注入，以及与该虚拟节点绑定的 scope、选中状态、点击、菜单、图标、拖动和样式分支。组合树只由推荐看板节点与我的看板节点构成。

### 看板预览

从 `SQPreviewShow.vue` 删除 `RoiDashboardPanel`、ROI Store、ROI 权限判断、ROI 落地协调器和 `dashboardMode=roi` 的专用渲染分支。普通预览继续只处理 `default` 与 `my` 两种模式。

### 无调用代码

删除不再有运行时调用的前端 ROI API、Pinia Store、ROI 页面组件与导航辅助文件，并同步删除只验证这些已移除能力的测试。删除前必须通过引用检索确认没有普通看板模块依赖这些文件。

保留通用 SQL 编辑器中的数据源角色与后端 ROI 数据源配置能力，因为它们可能被普通看板的数据源权限链路复用，不属于独立 ROI 页面。

## 旧链接处理

当 URL 含 `dashboardMode=roi` 时，前端不继续渲染 ROI 页面，也不沿用 ROI 查询参数加载普通看板。它应调用现有普通看板落地解析逻辑，跳转到当前用户有权访问的推荐看板或我的看板；若没有可访问看板，则使用现有空状态。

跳转必须使用现有权限与工作空间上下文，不硬编码看板 ID，也不跨工作空间选择看板。

## 错误与状态处理

- ROI 旧链接：替换为普通看板落地路由，避免浏览器历史中保留无效模式。
- 工作空间切换：继续清理普通看板预览状态，不再操作 ROI Store。
- 无普通看板：展示现有普通看板空状态，不自动创建任何看板。
- 后端 ROI API：保持现状，但前端不再调用。

## 测试范围

- `ResourceTree.vue` 不再包含 `ROI_GROUP_ID`、`ROI_SCOPE`、`createRoiDashboardEntry` 或 ROI Store。
- 组合树不再注入 ROI 虚拟节点，推荐看板和我的看板分组结构保持不变。
- `SQPreviewShow.vue` 不再导入或渲染 `RoiDashboardPanel`，也不再执行 ROI 权限与落地协调逻辑。
- 旧 `dashboardMode=roi` 路由会替换为现有普通看板落地目标。
- 推荐看板和我的看板的既有路由、选中、加载、编辑与权限测试继续通过。
- 前端构建与 TypeScript 检查不包含被删除 ROI 文件的悬空引用。

## 验收标准

- 刷新页面后左侧不再出现“ROI 看板”。
- 手动访问 `/#/dashboard/index?dashboardMode=roi` 不显示 ROI 页面，并进入有权限的普通看板落地页。
- 浏览器网络请求中不再出现 `/dashboard/roi/*`。
- 推荐看板和我的看板功能无回归。
- 后端服务启动、普通看板 API 和数据源权限链路保持正常。
