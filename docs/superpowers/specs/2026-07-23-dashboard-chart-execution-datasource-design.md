# 看板图表执行数据源选择设计

## 背景

看板图表的 SQL 当前以空间绑定数据源作为唯一默认上下文。空间同时可配置 ROI 数据源，但编辑图表时没有受控入口选择它，导致新建、复制或改名后的普通看板无法明确让 SQL 在 ROI 数据源执行。

不能通过看板名称、目录名称或 SQL 文本推断数据源。图表执行数据源必须是显式配置，并且后端必须按当前认证空间重新校验，不能信任前端提交的任意数据源 ID。

## 目标

- 所有具备 SQL 编辑权限的看板图表均可选择执行数据源，名称和看板类型不影响该能力。
- 选择器仅列出当前空间已配置的绑定数据源和 ROI 数据源。
- 未显式选择的图表默认使用绑定数据源。
- 选择结果随图表 SQL 配置持久化；预览、保存后的图表刷新和重新打开编辑器均使用同一数据源。
- 后端拒绝当前空间以外、未配置为绑定或 ROI 的数据源，不能仅依赖前端下拉框。

## 非目标

- 不把空间改造为可绑定多个普通数据源，不引入多对多空间/数据源绑定。
- 不允许用户搜索、输入或提交任意平台数据源 ID。
- 不改变 Smart Q&A、分析助手、语义层或外部 MCP 数据源的选择规则。
- 不支持跨数据源 JOIN；一张图表的一次 SQL 执行只使用一个数据源。
- 不根据看板名称、目录、SQL 表名或字段名自动选择 ROI 数据源。

## 方案比较

### 方案一：按 ROI 看板名称或目录开放

实现范围小，但重命名或复制看板后规则失效，且名称不是可靠的权限边界，因此不采用。

### 方案二：所有看板可任意选择平台数据源

灵活性最高，但会绕开空间所有权与语义上下文，容易造成跨空间访问和错误口径，也与当前单绑定模型冲突，因此不采用。

### 方案三：通用图表选择器，候选集限于空间绑定与 ROI 数据源

推荐采用。能力不依赖看板名称，且候选集由服务端根据当前空间配置生成。ROI 数据源作为受控的第二数据源，不改变普通空间绑定模型。

## 交互设计

在 SQL 图表编辑抽屉的图表配置区域、预览与保存操作之前增加一行“执行数据源”选择器。

- 当前空间只配置绑定数据源时，显示只读的“绑定数据源：{名称}”。
- 当前空间同时配置 ROI 数据源且其 ID 不同于绑定数据源时，显示下拉选项“绑定数据源：{名称}”与“ROI 数据源：{名称}”。
- 默认值为绑定数据源。历史图表未保存图表级数据源时，打开编辑器也以绑定数据源显示；用户保存后写入明确的图表数据源。
- 用户切换数据源后，立即清空 SQL、预览结果、图表字段映射、轴/列/系列、透视配置以及 SQL 构建器状态。不得把旧数据源字段静默映射到新数据源。
- 切换后要求重新预览，预览成功前不允许应用保存。预览区域显示本次执行的数据源名称。
- 外部 MCP 图表不显示 SQL 执行数据源选择器；混合来源图表仅对其 SQL 部分使用该选择。

## 数据与接口设计

### 候选数据源

新增一个仅供 SQL 图表编辑器使用的只读接口，服务端从当前登录用户的空间上下文构造候选集：

```text
当前空间 -> bound_datasource_id
当前空间 -> roi_datasource_id（存在且不同于绑定数据源时）
```

响应仅包含展示和执行所需的 `id`、`name`、`role`（`bound` 或 `roi`），不返回连接凭据或其他空间数据源。数据源不存在、被禁用或不再属于当前空间时不返回，且提供明确错误而不是替换为其他数据源。

### 图表配置

复用图表当前 SQL 配置中已有的图表级 `datasource` 字段保存实际执行的 `datasource_id`，不新增数据库列。图表没有该字段时，后端按当前空间绑定数据源解析，这是产品定义的默认值；编辑器下一次保存会写入明确值。

图表 SQL、数据源与预览校验状态共同构成一次可应用的配置：

```text
chart_id + datasource_id + sql_hash + preview_signature
```

任一项变化均使预览校验失效。保存和刷新不从 SQL 文字、看板名称或前端缓存推断数据源。

### 服务端解析与校验

抽取一个看板图表执行数据源解析入口，所有 SQL 相关路径复用它：

```text
resolve_chart_execution_datasource(current_user, dashboard, chart_datasource_id)
  -> 当前空间绑定数据源或 ROI 数据源
  -> 校验用户对结果数据源的 SQL 权限
  -> 返回获准执行的数据源
```

该入口用于：

- SQL 编辑器 schema/字段元数据加载。
- SQL 预览。
- 图表 SQL 配置保存。
- 加载或刷新已保存看板时的实际 SQL 执行。

请求中传入的 `datasource_id` 不属于当前空间候选集时返回明确的权限或配置错误。即使用户拥有另一个平台数据源的权限，也不能通过该图表执行路径访问它。

缓存键与结果失效必须保留空间、用户权限范围、看板、图表和实际数据源边界；数据源切换后不得命中旧数据源结果。

## 错误处理

- 空间没有有效绑定数据源：禁用 SQL 选择与预览，提示空间尚未配置绑定数据源。
- ROI 数据源未配置、已禁用或不可访问：不显示 ROI 选项；已保存的 ROI 图表执行时明确报错并提示重新配置，不回退至绑定数据源。
- 切换数据源后未预览：阻止保存，提示需在当前数据源重新预览。
- SQL 结果不包含已选字段：清空无效字段并显示验证信息，不替换为第一列或相似字段。
- 前端伪造其他数据源 ID：后端拒绝请求并不泄漏候选集之外的资源信息。

## 权限与兼容性

SQL 编辑入口继续要求既有的看板编辑权与数据源 SQL 权限。候选集的空间边界与实际执行边界均由服务端确定。图表级数据源只是一次请求的选择，不会改变空间绑定数据源，也不会赋予 ROI 数据源以外的访问能力。

已保存的普通图表保持默认绑定数据源行为。仅当图表明确保存 ROI 数据源时才使用 ROI 数据源；ROI 数据源被移除后，系统不进行静默兼容回退。

## 测试策略

- 后端：候选集仅含当前空间的绑定和 ROI 数据源；重复 ID 去重；伪造第三方数据源被拒绝。
- 后端：预览、保存和看板加载/刷新均使用同一个图表级数据源，并分别校验 SQL 权限。
- 后端：已保存 ROI 图表在 ROI 数据源失效后明确失败，不改用绑定数据源。
- 前端：默认显示绑定数据源；ROI 数据源存在时可选择；切换后清空 SQL、字段和预览状态。
- 前端：重新打开已保存图表可恢复已选数据源；切换后未重新预览不能保存。
- 回归：外部 MCP 和仅绑定数据源的空间行为不变。

## 验收标准

1. 任意名称的看板图表都可在当前空间绑定数据源与 ROI 数据源之间选择执行数据源。
2. 新图表默认使用绑定数据源。
3. 图表选择 ROI 数据源后，预览、保存和后续刷新均在 ROI 数据源执行。
4. 数据源切换清空旧 SQL 相关状态并要求重新预览。
5. 后端无法通过构造请求执行当前空间候选集以外的数据源。
6. ROI 数据源失效时明确报错，不隐式回退至绑定数据源。
