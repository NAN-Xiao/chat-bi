# 看板图表闪烁修复设计

## 背景

默认看板加载时，前端先请求不包含结果数据的看板结构，再异步查询各图表数据。现有实现会在查询前清空已保存的图表结果，同时预览层和卡片层的尺寸监听可能在尺寸没有变化时重复广播、销毁并重建图表。因此用户会看到坐标轴仍在、数据系列短暂消失，页面稳定后也可能再次闪烁。

本次修复只调整通用看板渲染和刷新状态，不改变指标口径、SQL、数据源权限或图表字段映射。

## 目标行为

1. 首次进入看板且没有可用图表数据时，卡片显示完整加载状态，不渲染空坐标轴。
2. 图表已有可用快照并在后台刷新时，保留当前图表；新结果成功返回后一次性替换。
3. 刷新失败时沿用现有错误和重试规则，不用旧数据伪装成新结果，也不永久停留在加载状态。
4. 容器宽高没有实际变化时，不广播全局重绘事件，也不销毁、重建图表。
5. 容器宽高确实变化时，图表仍能正确适配抽屉、窗口和看板布局变化。

## 设计

### 预览层尺寸监听

`SQPreview.vue` 统一使用组件拥有的 `previewCanvas` 元素作为尺寸来源。尺寸初始化函数记录上一次宽高，仅在宽高变化时更新网格计算并发送 `view-render-all`。移除对同一元素的重复尺寸检测路径，避免一次布局变化产生两组回调。

首次挂载仍执行一次尺寸初始化和必要广播，保证图表取得初始布局。

### 卡片层尺寸监听

`sq-view/index.vue` 的 `measureFrame()` 返回“尺寸是否变化”。卡片级 `ResizeObserver` 只有在真实宽高变化且当前图表不是表格时才调度图表重绘。现有 80ms 合并调度保留，用于吸收一次布局过程中的连续有效尺寸变化。

### 图表加载和刷新状态

看板初始化时区分两类状态：

- 没有可用快照：清理无效结果并显示完整加载状态，数据返回前不挂载空图表。
- 已有可用快照：保留数据和已渲染图表，将状态标记为后台刷新；数据成功返回后再应用完整结果。

结果替换以单个图表请求版本为边界。过期请求、已取消请求和已切换看板的结果不能覆盖当前图表。权限拒绝、配置错误和不可重试失败继续进入明确失败状态；瞬时失败按现有策略保留快照并重试。

## 测试

新增或扩展前端回归测试，覆盖：

1. `SQPreview` 首次测量会初始化，重复相同尺寸不会再次广播，实际尺寸变化只广播一次。
2. `sq-view` 收到无变化的 `ResizeObserver` 回调时不调度重绘，真实宽高变化时会调度。
3. 首次加载无快照时显示完整加载状态，不显示空坐标轴。
4. 已有快照后台刷新时保留图表，成功结果到达后替换数据。
5. 失败、取消和过期请求不会错误清空或覆盖当前图表。

完成后运行相关单元测试、前端构建，并在真实默认看板资源上同时验证首次加载和稳定后静置场景。

## 非目标

- 不关闭看板自动刷新。
- 不改变自动刷新周期或缓存时效策略。
- 不加入字段、坐标轴或数据源的兼容回退。
- 不修改业务数据、Data Skills 或看板保存内容。
