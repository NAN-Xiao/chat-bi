# 仪表盘筛选事件属性与用户属性设计

## 背景

仪表盘 SQL 配置器当前将事件参数、事件明细表物理字段和 JSON 子字段混合展示，用户无法清晰区分事件自身参数与随事件上报的用户属性。

本设计将筛选字段按业务来源分类，同时沿用现有跟踪字典、Schema 权限和 JSON SQL 表达式链路，不新增数据库结构或元数据接口。看板现有执行数据源元数据只包含物理字段，因此还需要通过现有权限受控的 `fieldList` 接口补齐默认事件表的工作空间字典字段。

## 目标

- 指标内筛选提供“全部”“事件属性”和“用户属性”三个标签。
- 全局筛选只提供“用户属性”标签。
- 所有候选字段严格限定在当前工作空间配置并授权的 `event` 事件明细表。
- 用户属性严格来自 `event.userinfo` 的已配置 JSON 子字段。
- 保留字段的 `sourceField`、`jsonPath` 和 `expression`，确保 SQL 生成使用配置中的 JSON 表达式。

## 非目标

- 不读取 `user` 表或其他用户快照表。
- 不展示 `uid`、`dt`、`event` 等公共物理字段。
- 不扫描 `userinfo` 的运行时 JSON 样本来发现字段。
- 不新增全局筛选与事件的关联关系。
- 不引入新的后端属性目录接口或数据库字段。

## 字段定义

### 事件属性

事件属性来自当前指标所选事件的跟踪事件目录 `properties`。候选项必须同时满足：

- 属性所属 `eventTable` 为当前有效的默认事件表；
- 默认事件表为 `event`；
- 属性属于当前指标所选事件；
- 属性通过当前用户的表级、字段级及 JSON 路径权限检查；
- 属性不是对象组、JSON 容器或数组容器，仅展示可直接用于筛选的叶子字段。

事件属性只出现在指标内筛选中。

### 用户属性

用户属性来自当前有效 Schema 字段候选。候选项必须同时满足：

- `table` 为当前有效的默认事件表 `event`；
- `sourceField` 规范化后严格等于 `userinfo`；
- 存在有效 `jsonPath`；
- 字段属于可选择的 JSON 叶子字段；
- 字段通过当前用户的表级、字段级及 JSON 路径权限检查。

用户属性同时用于指标内筛选和全局筛选。即使 `user` 表存在同名 `userinfo` 字段，也不得加入候选项。

## 交互设计

### 指标内筛选

字段弹窗顶部依次显示“全部”“事件属性”和“用户属性”三个横向文本标签，默认打开“全部”。当前标签使用深色文字和蓝色底部指示线，标签不使用卡片或圆角按钮外观。

- “全部”按固定顺序先展示“事件属性”分组，再展示“用户属性”分组；没有候选的分组不显示标题。
- “事件属性”展示当前指标事件对应的参数。
- “用户属性”展示 `event.userinfo` 的已配置 JSON 子字段。
- 搜索只过滤当前标签中的候选项。
- 当前标签没有候选项时，分别显示“暂无筛选属性”“暂无事件属性”或“暂无用户属性”。

### 全局筛选

字段弹窗顶部只显示一个相同样式的“用户属性”标签，不渲染、禁用或预留“事件属性”。候选项仅包含 `event.userinfo` 的已配置 JSON 子字段。

## 组件设计

扩展现有 `BuilderFieldPicker`，增加筛选属性展示模式，继续复用搜索、选中态、字段提示浮层和字段显示名称逻辑。

字段分类使用独立纯函数，根据结构化 `FieldOption` 元数据判断事件属性和 `event.userinfo` 用户属性。不得通过显示名称、字段注释或相似字段名猜测归属。

`DashboardSqlEditor` 负责提供经过事件表范围约束的候选项：

- 默认事件表通过现有 `fieldList` 接口取得物理字段与工作空间字典字段的权限受控合并结果；
- 指标筛选传入当前事件参数列表和 `event.userinfo` 用户属性列表；
- 全局筛选只传入 `event.userinfo` 用户属性列表；
- `BuilderFilterTree` 只负责将对应候选和展示模式传给字段选择器，不自行推断字段来源。

## 数据与 SQL 流程

1. 工作空间跟踪配置确定默认事件表和事件目录。
2. 看板先读取执行数据源表结构，再对默认事件表调用现有 `fieldList`，取得当前用户可见的物理字段和工作空间字典字段。
3. 前端用 `fieldList` 结果替换默认事件表的基础字段列表，保留服务端编译的 `sourceField`、`jsonPath`、`expression` 和 JSON 路径权限结果。
4. 前端按当前指标事件组装事件属性，并按 `event + userinfo + jsonPath` 组装用户属性。
5. 选中字段继续保存现有字段值；不增加重复的属性类型或事件状态字段。
6. 生成 SQL 上下文时，字段对象继续携带 `kind`、`eventName`、`sourceField`、`jsonPath` 和 `expression`。
7. 事件属性使用其配置表达式应用指标内筛选；用户属性使用 `event.userinfo` 对应的配置表达式应用指标内或全局筛选。

后端必须使用字段对象中的 JSON 表达式，不得自行改写宿主列、JSON 路径或跨表读取用户属性。

## 失效配置与错误处理

- 旧配置中的筛选字段如果不属于新的允许范围，保留原值并显示“字段不属于当前筛选范围”，不得自动替换或删除。
- 指标切换事件后，原事件属性如果不属于新事件，应标记失效；不得自动选择新事件的第一个参数。
- 指标切换事件后，合法的 `event.userinfo` 用户属性继续有效。
- `event.userinfo` 没有已配置 JSON 子字段时，显示空状态，不回退到物理字段或其他表。
- 默认事件表无效、无权限或不为 `event` 时，不提供筛选候选，并沿用现有事件范围错误提示阻止生成新的错误 SQL。

## 测试设计

前端采用测试先行方式覆盖：

- 事件属性只包含当前事件的可筛选叶子参数；
- 用户属性只包含 `event.userinfo` 的已配置 JSON 叶子字段；
- 默认事件表通过 `fieldList` 补齐字典字段，并保留字段表达式和权限过滤结果；
- `user.userinfo`、其他 JSON 宿主列和事件公共物理字段被排除；
- 指标筛选显示“全部 / 事件属性 / 用户属性”，全局筛选只显示“用户属性”；
- “全部”先渲染事件属性分组，再渲染用户属性分组；
- 标签切换、标签内搜索和空状态符合设计；
- 指标切换事件后，失效事件属性不会被静默替换；
- 旧配置中的越界字段产生明确校验错误；
- 字段序列化保留 `sourceField`、`jsonPath`、`expression` 和事件元数据。

后端测试覆盖：

- 指标内事件属性筛选仍使用当前事件及其 JSON 表达式；
- 指标内和全局用户属性筛选只使用 `event.userinfo` 的配置表达式；
- 越界表、无权限 JSON 路径和缺失表达式按现有校验机制失败关闭。

## 验收标准

- 指标筛选字段弹窗按设计显示“全部 / 事件属性 / 用户属性”，并默认选中“全部”。
- “全部”中的分组顺序固定为事件属性在前、用户属性在后。
- 全局筛选字段弹窗只显示“用户属性”。
- 两处用户属性候选完全一致，且只来自 `event.userinfo`。
- 已在数据字典配置的 `event.userinfo` JSON 叶子字段能够出现在筛选候选中。
- 事件属性随当前指标事件变化，不出现其他事件参数。
- 生成 SQL 正确使用已配置 JSON 表达式，且不引用 `user` 表。
- 旧配置和无效元数据不会被静默替换或跨表回退。
