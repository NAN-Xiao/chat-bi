# 图表 SQL 配置器事件表候选范围设计

## 背景

图表 SQL 配置器当前分别从数据源物理表元数据和工作空间埋点配置构造候选项。事件型工作空间中，时间范围、全局筛选和分组项可能出现 `user`、`event_realtime` 等非默认事件表字段，而配置 Agent 使用工作空间权威分析 Schema 校验，可能在用户选择后才阻断跨表或未授权字段。

本设计把事件模式下的候选范围收敛到工作空间埋点配置声明的默认事件表。修仙空间当前默认事件表为 `event`，但通用代码不得硬编码表名、工作空间或数据源 ID。

## 目标

- 当工作空间存在有效埋点配置和默认事件表时，图表 SQL 配置器进入事件模式。
- 事件模式中的时间范围、分析指标、指标筛选、全局筛选和分组项只提供默认事件表相关内容。
- 前端候选项与配置 Agent 的允许表范围保持一致，避免“可以选择但生成时被拒绝”。
- 非事件模式和没有默认事件表的工作空间保持现有通用字段选择行为。
- SQL 生成和执行仍经过后端权限、Schema 与只读校验，前端过滤不能替代安全校验。

## 非目标

- 不限制整个 BI 平台只能查询事件表。
- 不修改 Smart Q&A、分析助手或手写 SQL 的表选择能力。
- 不把 `event`、修仙、数据源 `6` 或具体事件名写入共享前后端逻辑。
- 不在本次需求中设计跨表关联、事件表与用户表 JOIN 或多事实表模型。
- 不改变图表字段映射、透视配置和数据预览逻辑；这些问题独立处理。

## 事件模式判定

同时满足以下条件时启用事件模式：

1. 当前工作空间存在启用的埋点配置；
2. 埋点配置包含非空 `default_event_table`；
3. 当前数据源与该埋点配置的数据源一致；
4. 默认事件表存在于当前用户可访问、工作空间权威 Schema 允许的表集合中。

`default_event_table` 是唯一表范围来源。修仙空间解析结果为 `event`，其他空间可以配置不同事件表名。

若配置缺失、表不存在或无权访问，不得回退到同名表或第一张表。界面退出事件模式并显示明确的配置不可用状态，避免静默扩大候选范围。

## 候选项规则

### 时间范围

- 只使用默认事件表中可访问的日期、时间或时间戳字段。
- 新建配置优先选择明确标记为业务日期或分区日期的字段；没有该元数据时使用默认事件时间字段。
- 已保存字段不属于默认事件表时清空该选择并提示用户重新选择，不自动替换。
- 修仙空间的业务日期字段为 `event.dt`，应作为按自然日统计和分区裁剪的首选字段。

### 分析指标

- 只显示埋点字典中 `event_table` 等于默认事件表的事件。
- 事件名称、分类和事件参数继续来自工作空间埋点配置，不扫描物理事件值。
- 选择事件后，指标内筛选仅显示该事件登记的参数和默认事件表公共字段。

### 全局筛选与分组项

- 只显示默认事件表的可访问物理字段和 JSON 叶子字段。
- 排除其他物理表、未进入权威 Schema 的表及无字段权限的字段。
- JSON 容器字段继续不可直接选择，仅允许已配置 `sourceField + jsonPath` 的叶子字段。

### 显示方式

- 候选字段唯一时只显示业务名称，保持界面简洁。
- 默认事件表内部存在同名字段时，增加宿主字段或 JSON 路径作为辅助信息。
- 因候选范围只有一张表，不要求每个字段持续显示物理表名。

## 前后端数据流

1. 后端基于当前工作空间、数据源、用户权限和埋点配置构造图表配置器元数据。
2. 元数据返回事件模式状态、默认事件表、允许表集合、允许字段及事件目录。
3. 前端只根据这份元数据构造各区域候选项，不再独立把所有 `tableList/fieldList` 结果加入事件模式。
4. 用户选择项继续携带 `table`、`field`、`sourceField`、`jsonPath`、`expression` 和事件标识等完整结构。
5. 配置 Agent 使用相同的允许表和允许字段集合做确定性校验。
6. 后端生成 SQL 后继续执行 JSON 映射、权限、只读和 SQL 安全校验。

短期实现可以在现有接口结果上求交集，但交集使用的允许表必须来自后端权威分析 Schema。长期应由单一图表配置器元数据接口直接返回可选项，消除前后端两套候选来源。

## 校验与错误处理

- 请求包含非默认事件表字段时，后端返回结构化错误码和具体配置位置，如 `group[0]` 或 `global_filter[1]`。
- 错误提示使用“当前事件模式不允许使用该表”，不要把“未进入分析 Schema”一律描述成权限不足。
- 修复建议只能引用允许表集合中的字段，不能把被阻断字段重新作为建议输出。
- 已保存图表包含跨表配置时允许查看原图表，但进入配置器后必须明确提示并要求用户处理，不能静默删除或替换。

## 兼容性

- 事件模式仅由工作空间配置触发，不根据表名猜测。
- 非事件模式继续展示当前用户有权访问的通用数据源字段。
- 已有手写 SQL 和已经物化的图表结果不因候选范围调整而自动改写。
- 恢复或扩展跨表能力时应引入显式数据模型或语义关联配置，不通过前端放开所有表实现。

## 测试方案

### 前端测试

- 默认事件表为 `event` 时，时间、全局筛选和分组候选不包含 `user`、`event_realtime`。
- 分析指标只包含 `event_table=event` 的事件。
- 指标筛选只包含当前事件参数和事件表公共字段。
- 同名 JSON 字段显示可区分的宿主字段或路径。
- 已保存的非事件表字段被清空并显示校验提示，不自动替换。
- 无埋点配置时保持通用模式。

### 后端测试

- 图表配置器元数据只返回默认事件表与允许字段的交集。
- 非默认事件表字段在确定性校验阶段被拒绝。
- 错误建议不包含被拒绝的表或字段。
- 工作空间、数据源和用户权限边界正确隔离。
- JSON 叶子字段保留完整宿主列、路径和受控表达式。

### 集成测试

- 修仙空间选择游戏启动、时间范围、事件参数筛选和分组后生成的 SQL 只引用 `event`。
- 生成 SQL 能在数据源执行并返回预期字段。
- 配置器中不再出现 `event_realtime.event` 和 `user.userinfo._platformType`。
- 其他非事件型数据源仍能选择其授权表字段。

## 验收标准

- 修仙空间截图所示五个配置区域的候选内容全部限定为 `event` 表相关内容。
- 用户不能通过候选控件选择 `user`、`event_realtime` 或其他表。
- 配置 Agent 不再出现“前端可选、后端拒绝”的表范围矛盾。
- 通用 BI 和非事件模式没有行为回归。
- 没有新增任何修仙、数据源 ID、事件名或 `event` 表名硬编码。
