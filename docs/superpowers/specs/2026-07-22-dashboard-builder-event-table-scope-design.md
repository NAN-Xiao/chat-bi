# 图表 SQL 配置器事件表候选范围设计

## 1. 结论

本需求只调整 `DashboardSqlEditor` 的事件模式：时间、分析指标、指标筛选、全局筛选和分组项的可选内容，只能来自当前工作空间 `default_event_table` 指定的默认事件表。

实现必须遵守以下边界：

- `default_event_table` 来自当前工作空间的埋点配置，不能在共享代码中写死为 `event`。
- 候选范围由 `DashboardSqlEditor` 的事件模式数据准备层收敛；共享 `BuilderFieldPicker` 只展示传入的候选项。
- 前端候选和配置 Agent 使用同一份工作空间、数据源、权限与 Schema 约束，不能出现“界面可选、Agent 又拒绝”的矛盾。
- JSON 字段按结构化来源校验，错误必须指出具体缺失的宿主字段和 JSON 路径，不能只返回总括性错误。
- 普通模式、Smart Q&A、分析助手、手写 SQL 和其他共享字段选择场景不受本需求影响。

修仙空间当前配置的默认事件表是 `event`，所以该空间进入事件模式后只显示 `event` 表相关内容。其他工作空间可以配置成 `event_log` 等其他表名，通用逻辑仍然读取各自配置。

## 2. 问题与目标

### 2.1 字段来源不明确

当前图表配置器会从数据源物理 Schema 和工作空间埋点配置构造字段候选。事件型工作空间中，候选项可能混入 `user`、`event_realtime` 等非默认事件表字段，用户无法判断哪些字段真正适用于当前事件 SQL。

目标是让事件模式的候选来源唯一且可解释：只使用当前工作空间默认事件表中，同时满足权限、物理 Schema 和工作空间权威字段字典约束的字段。

### 2.2 配置 Agent 建议矛盾

如果前端展示全数据源字段，而配置 Agent 只允许分析 Schema 中的字段，就会出现用户刚选择字段，Agent 又提示该字段不可用，甚至把已阻断字段重新放进修复建议。

目标是让前端候选、确定性校验和 Agent 建议共享同一允许集合；“当前配置摘要”和“修复建议”必须分开，已阻断字段不得再次作为建议。

### 2.3 JSON 映射误报

JSON 叶子字段同时包含物理表、宿主列、JSON 路径和表达式。如果只比较显示名、字段别名或 SQL 文本，容易把已生成的 JSON 提取误判为缺失，或者把同名路径认成同一字段。

目标是按结构化身份校验 JSON 字段，并把错误定位到具体配置项。例如：`事件时间 currentinfo.$._eventTime 未出现在 SQL`，而不是只显示“JSON 映射错误”。

### 2.4 默认表静默回退

当前代码仍存在 `default_event_table` 为空时回退到字符串 `event` 的实现，例如前端事件目录构造和后端事件目录构造路径。这是现状缺口，不是目标行为。

本需求实施后，涉及图表配置器事件模式的路径不得猜测默认表。配置缺失或失效时必须显示明确状态，不能静默使用 `event`、第一张表或全部字段。

## 3. 适用范围

### 3.1 受影响范围

- `DashboardSqlEditor` 中由配置器生成 SQL 的事件模式。
- 时间范围、分析指标、指标内筛选、全局筛选和分组项五个候选区域。
- 与上述配置对应的确定性校验、配置 Agent 上下文和修复建议。
- 已保存图表进入事件配置器时的范围校验。

### 3.2 不受影响范围

- 普通图表配置模式和没有启用埋点配置的工作空间。
- Smart Q&A、分析助手和文档助手的表选择能力。
- 手写 SQL、已保存 SQL 的直接执行和已经物化的图表结果。
- `BuilderFieldPicker`、`BuilderFilterTree` 等共享组件在其他调用方中的通用行为。
- 跨表 JOIN、事件表与用户表关联、多事实表模型；这些能力需要单独的显式语义关联设计。

## 4. `default_event_table` 的定义与来源

`default_event_table` 表示当前工作空间的默认事件明细表，是工作空间埋点配置的持久化字段：

- 系统库存储表：`sys_tenant_tracking_config`。
- 后端模型：`backend/apps/system/models/tenant.py` 中的 `default_event_table`。
- 配置来源：工作空间数据字典/埋点配置保存、埋点 Excel 导入推断，或数据源范围内的幂等 Seed 脚本显式设置。
- 前端读取：通过工作空间埋点配置接口取得，不从表名、数据源 ID、问题文本或历史选择推断。

`default_event_table` 只在当前工作空间及其绑定数据源上下文内有效。工作空间、数据源或权限上下文不一致时，该值不能用于生成候选项。

事件模式允许表可概括为：

```text
{default_event_table}
∩ 当前用户可访问表
∩ 当前工作空间权威 Schema
∩ 当前数据源物理 Schema
```

## 5. 模式判定与失败行为

| 配置状态 | 配置器行为 |
| --- | --- |
| 工作空间未启用埋点配置 | 使用现有普通模式，不应用事件表限制 |
| 埋点配置已启用，默认事件表有效 | 进入事件模式，只展示默认事件表候选 |
| 埋点配置已启用，但 `default_event_table` 为空 | 事件配置不可用，显示“未配置默认事件表” |
| 默认事件表不在当前物理 Schema | 事件配置不可用，显示“默认事件表不存在” |
| 默认事件表不在当前权限或工作空间允许范围 | 事件配置不可用，显示“默认事件表不可访问” |
| 埋点配置的数据源与当前数据源不一致 | 事件配置不可用，显示数据源上下文不一致 |

上述错误均不得回退到 `event`、同名表、第一张表或全部字段。

## 6. 五个候选区域的规则

| 配置区域 | 候选来源 | 事件模式规则 |
| --- | --- | --- |
| 时间范围 | 默认事件表的时间字段 | 只显示可访问的日期、时间戳和分区日期字段 |
| 分析指标 | 工作空间事件目录 | 只显示 `event_table` 等于 `default_event_table` 的事件 |
| 指标筛选 | 当前事件参数与公共字段 | 只显示该事件登记的参数，以及默认事件表的公共可筛选字段 |
| 全局筛选 | 默认事件表字段 | 只显示默认事件表的物理字段和已配置 JSON 叶子字段 |
| 分组项 | 默认事件表字段 | 只显示默认事件表的可分组物理字段和已配置 JSON 叶子字段 |

补充规则：

- JSON 容器字段不能直接作为叶子字段选择；可选 JSON 字段必须有明确的 `sourceField + jsonPath`。
- 事件名称、分类和事件参数来自工作空间埋点字典，不通过扫描业务库事件值临时生成。
- 候选项必须携带完整结构化来源，包括 `table`、`field`、`sourceField`、`jsonPath`、受控 `expression` 和事件标识。
- 修仙空间的 `event` 只是当前配置示例，不能进入通用过滤方法或共享组件的常量判断。

## 7. 字段显示与内部身份

事件模式只有一张候选表，因此界面不需要让每个字段持续显示 `表显示名(物理表).字段/JSON路径`。默认显示业务名称，避免重复的 `event.` 前缀造成视觉噪声。

仅在默认事件表内部出现同名字段时，增加宿主字段或 JSON 路径作为辅助信息。界面可以在详情或提示中展示完整来源，但内部选择值必须始终保留完整结构化身份，不能只保存显示名。

例如两个都叫“平台”的字段，应通过以下身份区分：

```text
event + deviceinfo + $._platform
event + userinfo + $._platformType
```

这既解决字段来源歧义，也不要求所有单表字段都显示冗长物理前缀。

## 8. 前端实现方案与决策

### 8.1 方案比较

| 方案 | 优点 | 风险 | 结论 |
| --- | --- | --- | --- |
| `DashboardSqlEditor` 上层专用过滤方法 | 影响范围明确，易测试，不改变共享组件职责 | 需要整理五个区域的候选入口 | 采用 |
| 在 `BuilderFieldPicker` 内判断事件模式 | 调用方改动少 | 共享组件耦合业务配置，可能影响其他页面 | 不采用 |
| 只依赖后端生成或 Agent 阶段拒绝 | 后端约束集中 | 用户仍能选择无效字段，矛盾发生得太晚 | 不采用 |

### 8.2 专用过滤方法

在 `DashboardSqlEditor` 的事件模式数据准备层新增独立方法，例如：

```text
getEventScopedFields(fields, defaultEventTable, allowedFields)
```

该方法职责为：

- 精确匹配 `default_event_table`，并与后端允许字段集合求交集。
- 返回新的候选数组，不修改原始通用候选集合。
- 缺失或无效配置时返回空集合，由上层展示具体错误。
- 不负责修改已保存配置、生成 SQL、构造 Agent 文案或绕过后端校验。

时间范围、全局筛选和分组项使用相同字段结构时复用该方法。分析指标和指标筛选按事件目录与事件参数规则构造，但必须使用同一个默认事件表边界。

`BuilderFieldPicker` 继续只接收 `options` 并负责展示、搜索与选择，不读取工作空间配置，也不包含 `event` 表名或事件模式过滤逻辑。

## 9. 前后端数据流

```text
工作空间 + 当前数据源 + 用户权限
                 ↓
埋点配置与 default_event_table
                 ↓
物理 Schema ∩ 工作空间权威 Schema ∩ 权限
                 ↓
后端允许表、允许字段与事件目录
                 ↓
DashboardSqlEditor 生成事件模式候选集合
                 ↓
BuilderFieldPicker 展示并返回结构化选择
                 ↓
确定性校验 → 配置 Agent → SQL 生成与安全校验
```

短期可以在现有接口结果上求交集，但允许集合必须来自后端权威上下文。长期应由单一图表配置器元数据接口直接返回事件模式状态、默认事件表、允许字段和事件目录，避免前后端各自拼装范围。

## 10. 配置 Agent 一致性

- 配置 Agent 接收的允许表和允许字段必须与前端候选集合使用同一来源。
- 先执行确定性范围校验，再调用 Agent 解释或提出修复建议；表范围错误不依赖模型判断。
- “当前配置摘要”只描述用户当前选择，“修复建议”只列允许集合中的替代项，两者不能混合。
- 已被范围校验阻断的表或字段不能再次出现在建议中。
- 错误必须包含配置位置，例如 `metric[0].filter[1]`、`global_filter[0]` 或 `group[1]`。
- “未进入当前事件模式允许范围”和“用户没有权限”是不同原因，提示文案不能混用。

## 11. JSON 字段校验

JSON 叶子字段使用以下结构化身份校验：

```text
table + sourceField + jsonPath
```

校验不能只搜索显示名、别名或 SQL 字符串。生成 SQL 后，应根据受控表达式或解析后的 SQL 结构确认宿主字段和路径均存在。

错误信息必须直接指出缺失项，例如：

```text
全局筛选[0]：event.currentinfo.$._eventTime 未出现在生成 SQL 中
```

同名 JSON 路径位于不同宿主列时必须视为不同字段；JSON 容器存在但目标路径缺失时仍应报错。

## 12. 时间字段语义

必须区分两类时间字段：

- 分析时间字段：决定数据按哪个业务时间统计、分组和解释。
- 分区裁剪字段：用于缩小扫描范围和下推查询条件。

可以同时用分区日期字段做范围下推，但不能静默替换用户选择的事件时间字段。新建配置可以根据明确的字段角色推荐默认值；若字段角色缺失，不得仅靠字段名猜测并覆盖用户选择。

## 13. 已保存配置处理

- 已保存图表仍可使用原 SQL 或已有结果正常查看，不自动重写 SQL。
- 进入事件配置器后，若发现非默认事件表字段，保留原配置值并标记具体位置无效。
- 无效配置不得运行预览或应用保存，直到用户明确删除或重新选择。
- 不自动替换成默认事件表的同名字段，也不在加载时静默删除持久化配置。

## 14. 测试方案

### 14.1 前端单元测试

- 专用过滤方法只保留 `default_event_table` 对应且已授权的字段，不修改原数组。
- `default_event_table` 缺失、表不存在、数据源不一致或无权访问时返回空集合和对应状态。
- 默认事件表为 `event` 时，时间、全局筛选和分组候选不包含 `user`、`event_realtime`。
- 分析指标只包含 `event_table=event` 的事件；指标筛选只包含当前事件参数和事件表公共字段。
- 共享 `BuilderFieldPicker` 不包含事件表名或事件模式判断，普通调用方继续接收完整授权候选集合。
- 已保存跨表配置被标记无效且阻止应用，不被静默删除或替换。

### 14.2 后端测试

- 图表配置器元数据只返回默认事件表、工作空间权威 Schema、物理 Schema 和权限的交集。
- 缺失或无效 `default_event_table` 不回退到 `event`。
- 非默认事件表字段在确定性校验阶段被拒绝，错误包含配置位置。
- 修复建议不包含被拒绝的表或字段。
- JSON 叶子字段保留宿主列、路径和受控表达式，同名路径不会串用。
- 工作空间、数据源和用户权限边界正确隔离。

### 14.3 集成测试

- 修仙空间五个配置区域只展示 `event` 表相关内容。
- 选择事件、时间范围、事件参数筛选和分组后，生成 SQL 只引用 `event`。
- JSON 字段存在时不误报；缺失时错误指出具体宿主字段和路径。
- 配置器中不再出现 `event_realtime.event` 和 `user.userinfo._platformType`。
- 其他工作空间按各自 `default_event_table` 过滤，非事件型数据源保持普通模式。

## 15. 验收标准

- 修仙空间截图所示五个配置区域只提供当前工作空间 `default_event_table=event` 的相关内容。
- 用户不能通过候选控件新增 `user`、`event_realtime` 或其他表字段。
- 字段来源可通过结构化身份准确追踪，界面不强制重复显示单一物理表前缀。
- 配置 Agent 不再出现“前端可选、后端拒绝”或“阻断后又建议”的矛盾。
- JSON 映射不误报，并能定位具体缺失路径。
- 普通模式和共享组件调用方没有行为回归。
- 没有新增修仙、数据源 ID、具体事件名或 `event` 表名硬编码。

## 16. 实施前检查项

- 枚举前后端所有 `default_event_table` 的默认值和 `event` 字符串回退，区分本需求路径与其他独立用途。
- 确认五个配置区域最终使用的候选集合，避免只过滤其中一部分。
- 确认配置 Agent 的允许 Schema 与前端候选元数据来自同一权限和工作空间上下文。
- 确认 JSON 校验使用结构化身份，不依赖展示文本或脆弱字符串匹配。
- 为共享 `BuilderFieldPicker` 的其他调用方建立回归边界后再实施。
