# ROI 数据源表禁止设计

## 背景

工作空间目前只有一个普通绑定数据源，但可以另行配置一个 ROI 数据源。权限配置页只读取普通绑定数据源，ROI 查询也明确跳过普通数据源的表、字段和行权限，因此管理员无法为 ROI 数据源配置或执行表禁止规则。

本次只让 ROI 数据源支持现有的表禁止能力。字段禁止和行禁止仍不适用于 ROI 查询。

## 目标

- 工作空间管理员可以在现有权限配置页为当前工作空间配置的 ROI 数据源创建表禁止规则。
- ROI 查询在执行和读取缓存前检查当前用户是否被禁止访问 SQL 引用的物理表。
- 命中任意禁止表时拒绝整条 ROI 查询，并返回明确的权限错误。
- 普通数据源、智能问答、普通看板和其他数据源选择入口的可见范围保持不变。

## 非目标

- 不为 ROI 启用字段禁止或行禁止。
- 不改变 ROI 数据源的 SaaS 工作空间配置入口。
- 不改变 ROI 仅允许工作空间拥有者和管理员访问的角色限制。
- 不改变 ROI 查询的只读校验、受控超时、不截断结果和数据源授权规则。
- 不把 ROI 数据源加入通用 `/datasource/accessible/list`。

## 方案选择

采用“复用现有权限规则，增加权限管理专用 ROI 数据源范围”的方案。

不采用以下方案：

- 扩大通用可访问数据源列表：会使 ROI 数据源泄漏到智能问答、普通看板等无关入口。
- 新建独立 ROI 表权限模型：会重复现有规则组、用户选择、白名单和权限记录能力。

## 架构

### 权限管理数据源范围

权限 API 提供专用的数据源列表和数据表列表。工作空间上下文中的可管理范围按权限类型计算：

- `table`：普通绑定数据源与当前活动 ROI 数据源的并集，按数据源 ID 去重。
- `column` 和 `row`：仅普通绑定数据源。
- 全局平台上下文：保持现有平台级数据源管理能力。

专用接口负责校验管理员角色、当前工作空间和 ROI 活动配置。通用数据源接口及其可见范围不变。

### 前端交互

权限配置页改用权限管理专用接口加载数据源和数据表。

- 新建表禁止时，如果工作空间同时存在普通数据源和 ROI 数据源，显示可选择的数据源下拉框。
- 新建字段禁止或行禁止时，仍固定使用普通绑定数据源。
- 编辑现有规则时按保存的 `ds_id` 回填；数据源已不在当前可管理范围时不静默替换，显示明确错误并阻止保存。
- ROI 数据源没有活动配置时，不展示 ROI 选项。

### 规则保存和读取

现有 `ds_rules` 与 `ds_permission` 继续作为唯一权限存储。

- 工作空间规则继续保存当前 `tenant_id` 和 `scope=tenant`。
- 在当前工作空间仅通过活动 ROI 配置可见的数据源，只允许保存 `type=table` 的权限记录。
- 对这种仅通过 ROI 配置可见的数据源提交 `column` 或 `row` 请求时，返回明确的 `400` 校验错误。
- 数据源是否属于 ROI 范围按当前工作空间的活动配置判断，不给物理数据源设置全局 ROI 类型。同一数据源如果也是当前工作空间的普通绑定数据源，仍可按普通数据源配置字段和行规则；全局平台上下文的现有能力不变。
- 规则列表只返回当前上下文可见的普通数据源权限，以及当前活动 ROI 数据源的表权限。
- 平台级规则继续只由全局平台管理员管理，并可在 ROI 执行时与工作空间规则共同生效。

### ROI 表权限执行

复用现有 SQLGlot 方言解析和物理表提取能力，只执行表级校验：

1. 按 ROI 数据源方言解析渲染后的 SQL。
2. 排除未限定的 CTE 名称，收集所有实际物理表。
3. 读取当前工作空间的活动平台级和租户级表禁止规则。
4. 仅应用包含当前用户且未将当前用户加入白名单的启用规则。
5. 将 SQL 物理表与被禁止的 `CoreTable` 记录比较。
6. 任一表命中时拒绝整条查询，不删除 SQL 片段，也不替换为其他表。

ROI 只允许工作空间拥有者和管理员访问，而普通数据源权限默认放行管理角色。为使 ROI 表禁止真正有效，ROI 调用必须显式要求表权限计算包含被规则选中的工作空间拥有者和管理员。该行为只用于 ROI 表级校验，不改变其他业务中的管理员放行规则。

SQL 无法可靠解析或引用未登记、未启用的数据表时保持关闭式失败，不猜测表名或静默放行。

### 缓存安全

ROI 图表缓存按工作空间、用户、数据源和图表隔离，但新增规则后可能存在旧缓存。因此：

- 缓存未命中时，查询执行器在访问数据库前完成表权限校验。
- 缓存命中时，在返回缓存内容前对当前 SQL 和当前用户重新执行相同的表权限校验。
- 权限拒绝优先于缓存返回，Redis 清理失败也不能造成数据泄漏。

权限解除后可以继续使用同一用户的有效缓存，因为 SQL、数据源、图表版本和用户边界均未变化。

### ROI 数据源更换

更换或清除 ROI 数据源时，沿用现有“存在活动 ROI 图表则拒绝换源”的规则。换源成功后：

- 如果旧 ROI 数据源不再是该工作空间的普通绑定数据源，删除该工作空间中指向旧 ROI 数据源的租户级表禁止记录，并同步整理规则组中的权限 ID。
- 不删除平台级规则。
- 如果旧 ROI 数据源仍是普通绑定数据源，保留其规则。

清理与 ROI 配置更新处于同一事务，避免配置与权限记录部分成功。

## 错误处理

- ROI 表禁止命中：返回 `403`，错误信息说明 ROI SQL 包含禁止访问的数据表。
- ROI 数据源上的字段或行规则：返回 `400`，说明 ROI 数据源仅支持表禁止。
- 数据源或数据表不属于当前权限管理范围：返回 `404` 或现有的归属校验错误。
- SQL 解析失败：返回 `400`，不执行数据库查询。
- 图表列表中的单个图表被禁止：保留图表结构，将 `can_execute`/查询结果状态和错误信息按现有单图表失败模式返回，不影响其他允许执行的图表。

## 测试策略

### 后端

- 权限管理数据源列表对 `table` 返回普通数据源与 ROI 数据源，对 `column`/`row` 不返回 ROI。
- 权限管理数据表接口拒绝不属于当前工作空间的 ROI 数据源。
- ROI 数据源接受表禁止，拒绝字段禁止和行禁止。
- 规则读取可见性包含当前 ROI 表规则，不泄漏其他工作空间 ROI 规则。
- 被规则选中的工作空间拥有者或管理员执行命中禁止表的 SQL 时收到 `403`。
- 未选中用户、白名单用户和未命中表的 SQL 正常执行。
- 多表 SQL 任一表命中即拒绝，CTE 名称不被误判为物理表。
- 字段禁止和行禁止不影响 ROI 查询。
- 缓存命中前仍执行表权限校验。
- ROI 换源按普通绑定关系决定是否清理旧租户级表规则。

### 前端

- 表禁止加载权限管理专用数据源列表，并允许选择 ROI 数据源。
- 字段禁止和行禁止不展示 ROI 数据源。
- 选择 ROI 数据源后加载其数据表并正确保存 `ds_id`/`table_id`。
- 编辑 ROI 表禁止规则正确回填；无效数据源不自动回退到第一项。

### 回归

- 现有普通数据源权限专项测试通过。
- 现有 ROI 查询安全、超时、不截断和缓存隔离测试通过。
- 前端权限页行为测试与构建通过。

## 验收标准

在“修仙”工作空间中，可以为 `ROI_修仙` 的指定表创建表禁止规则并选择受限用户。该用户访问引用该表的 ROI 图表或预览 SQL 时看到明确的禁止错误，数据库查询和旧缓存均不会返回；未被规则限制的用户仍能正常使用同一 ROI 图表。字段禁止、行禁止和其他通用 BI 数据源入口不出现 `ROI_修仙`。
