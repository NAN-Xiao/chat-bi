# 编辑图表默认打开图表配置设计

## 背景

当前 `DashboardSqlEditor` 在组件初始化和每次打开时都将活动页签重置为 `sql`，因此新建图表、编辑已有图表以及关闭后重新打开都会先展示“SQL 明细”。产品期望所有编辑图表入口统一先进入“图表配置”。

## 目标

- 新建图表时默认打开“图表配置”。
- 编辑已有图表时默认打开“图表配置”。
- 关闭编辑器后再次打开时仍默认打开“图表配置”，不记忆上次页签。
- 默认打开后复用现有按需加载流程，请求图表配置所需的字段和事件元数据。

## 非目标

- 不删除或隐藏“SQL 明细”页签。
- 不改变用户主动切换页签的行为。
- 不改变 AI 生成 SQL 后切换到“SQL 明细”的现有行为。
- 不新增父组件参数或页签持久化配置。

## 设计

由 `DashboardSqlEditor` 自身统一管理默认页签：

1. 将 `sqlBuilder.activeTab` 的初始值从 `sql` 改为 `builder`。
2. 将编辑器初始化函数中每次打开时的重置值从 `sql` 改为 `builder`。
3. 保留监听 `activeTab` 的现有按需加载逻辑。编辑器打开后处于 `builder`，因此加载当前图表对应的字段和事件元数据。
4. 保留生成 SQL、用户点击页签等显式切换到 `sql` 的逻辑。这些属于操作结果，不属于打开时的默认状态。

该方案把统一产品规则放在编辑器组件内，所有调用入口自动生效，避免父组件逐个传参造成遗漏。

## 状态流转

- 打开编辑器：重置状态为 `builder` -> 挂载图表配置面板 -> 请求图表配置元数据。
- 用户点击“SQL 明细”：切换为 `sql` -> 挂载 SQL 明细面板。
- 用户关闭后重开：再次重置为 `builder`，不沿用上次选择。
- AI 生成 SQL 需要展示结果：沿用现有逻辑显式切换为 `sql`。

## 测试

更新 `DashboardSqlEditor.lazy-open.test.mjs` 中固化旧默认行为的断言：

- 先让新断言在现有实现上失败，证明测试能捕获旧行为。
- 验证初始活动页签为 `builder`。
- 验证每次初始化编辑器都重置为 `builder`。
- 保留图表配置与 SQL 明细使用 `v-if` 独立懒挂载的断言。
- 保留进入图表配置后调用元数据按需加载入口的断言。

完成后运行该定向测试，并执行相关 `DashboardSqlEditor` 测试集合和前端类型/构建检查。

## 风险与控制

默认进入图表配置会把字段和事件元数据请求提前到编辑器打开时，这是本次需求要求的行为。现有请求序号、可见性和当前图表身份校验继续防止关闭、切换图表或旧请求返回时覆盖新状态。
