# 看板编辑页路由挂载闪烁修复设计

## 背景

从平台看板模板预览点击“编辑”会从 `/system/dashboard-template` 跳转到顶层 `/canvas` 路由。预览组件树在路由切换时正常卸载，但编辑页把 `dataInitState` 初始设为 `true`，导致编辑页先使用 Pinia 中残留的画布状态挂载一次 `DashboardEditor`。父组件挂载后才开始加载目标模板，并把 `dataInitState` 改为 `false`；模板返回后再改回 `true`。

一次点击因此确定性地产生“旧画布挂载、卸载、异步空档、目标画布重新挂载”。此前图表原子渲染和首帧遮罩修复只作用于同一个存活的图表实例，不能跨越这次父级卸载和重挂。

## 目标行为

1. 首次进入 `/canvas` 时，目标资源就绪前不挂载残留的工具栏或画布。
2. 目标资源加载完成后，`DashboardEditor` 只挂载一次，不再发生首帧挂载后立即卸载。
3. 在同一个编辑页切换资源时，旧画布在任何异步数据源或资源请求前退出；过期请求不能重新放行画布。
4. 当前创建态画布存在未保存草稿且来源键匹配时，继续复用内存中的草稿，不引入额外卸载。
5. 加载期间保持固定的编辑页背景，不增加新的加载圆环或会造成二次视觉交接的遮罩。

## 方案

采用单一的编辑资源就绪门，调整 `frontend/src/views/dashboard/editor/index.vue`：

- `dataInitState` 初始值改为 `false`，禁止编辑页用残留 store 状态完成第一次渲染。
- `loadCanvasFromRoute()` 同步解析路由并计算来源键，先处理匹配的未保存创建态草稿；该分支明确保持画布就绪并直接返回。
- 其他加载路径在第一次 `await` 之前把 `dataInitState` 设为 `false`，覆盖普通看板的数据源加载和平台模板资源加载。
- 仅当前 `loadVersion` 在加载结束后可以把 `dataInitState` 设回 `true`，沿用现有过期请求隔离规则。
- 用同一个 `v-if="dataInitState"` 同时控制 `Toolbar` 和 `DashboardEditor`。加载期间只保留尺寸稳定的 `.editor-content/.editor-main` 背景，避免旧标题、按钮或画布先出现。

不引入预览数据跨路由缓存。该方案虽然不能让预览画布无缝变成编辑画布，但能消除已经证实的双挂载根因，同时避免平台模板专属状态传递和缓存失效问题。

## 数据流

1. `/canvas` 组件创建，资源就绪门关闭。
2. `loadCanvasFromRoute()` 记录新的加载版本，保存当前合法草稿，取消旧刷新任务并同步路由参数。
3. 若当前来源键对应可复用的未保存创建态草稿，资源就绪门直接打开，结束本次加载。
4. 其他路径保持资源就绪门关闭，再执行数据源或看板资源请求。
5. 当前版本的资源写入 Pinia 后，资源就绪门打开，工具栏、网格和图表子树共同完成唯一一次挂载。
6. 旧版本请求即使稍后返回，也不能写入当前画布或改变资源就绪门。

## 错误处理

- 保留现有 API 错误处理和请求版本判断，不改变错误消息、权限处理或重试策略。
- 平台模板加载失败仍走现有空资源结果处理，本次修复不新增静默回退，也不展示旧画布冒充目标模板。
- 不改变 `beforeunload`、草稿持久化、图表刷新取消和权限拒绝记录的生命周期。

## 测试

先新增失败回归测试，再修改生产代码：

1. 断言编辑页资源就绪门初始关闭。
2. 断言非草稿加载路径在第一次异步等待前关闭资源就绪门。
3. 断言匹配的未保存创建态草稿可以直接恢复就绪，不被新门永久隐藏。
4. 断言工具栏和 `DashboardEditor` 由同一个资源就绪条件控制。
5. 断言只有当前加载版本能在 `finally` 中重新放行画布。
6. 运行编辑页、图表原子渲染、卡片状态机和尺寸生命周期相关测试，并执行前端构建。
7. 在平台管理员页面给模板加载请求加入可观察延迟，点击“编辑”后确认目标编辑器首次出现后不再消失，控制台无新增错误。

## 非目标

- 不修改图表数据、SQL、字段映射、Data Skills、模板保存结构或数据源权限。
- 不修改 `ChartComponent`、`SQView` 的原子绘制和首帧握手。
- 不增加平台模板专属的跨路由缓存、页面截图或 keep-alive。
- 不用 CSS 遮罩掩盖仍然存在的重复挂载。
