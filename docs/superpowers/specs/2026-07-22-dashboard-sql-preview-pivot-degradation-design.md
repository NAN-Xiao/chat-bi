# 看板 SQL 预览透视降级设计

## 背景

看板 SQL 编辑器执行预览时，会先执行原始 SQL，再根据图表透视配置执行第二次透视 SQL。当用户修改 SQL 返回字段后，旧透视字段可能失效。当前流程会把透视配置错误显示为 SQL 执行失败，使用户误以为原始 SQL 无法执行。

本次调整只修正预览和保存阶段的行为边界，不改变透视 SQL 的生成规则，也不自动替换用户配置的字段。

## 目标

- 原始 SQL 执行成功后，即使透视配置无效，也应展示原始结果。
- 透视配置无效或透视执行失败时，明确提示“SQL 成功、透视未应用”。
- 启用了无效透视配置时，继续阻止应用到画布，避免保存含义不确定的图表。
- 后端继续严格拒绝不完整的透视请求，保护其他调用方。

## 非目标

- 不自动使用维度轴、第一列或相似字段补全透视配置。
- 不静默关闭图表透视。
- 不修改透视聚合、日期转换、缓存或权限规则。
- 不拆分新的后端预览接口。

## 方案选择

采用“前端预览降级，后端严格校验”。

后端自动回退原始 SQL 会掩盖非法请求，不采用。拆分“执行 SQL”和“执行透视”两个按钮会增加交互成本，当前范围内也不采用。

## 数据流

1. 前端调用 `/dashboard/sql_preview` 执行不带透视配置的原始 SQL。
2. 原始 SQL 失败时，保持现有失败处理并停止。
3. 原始 SQL 成功时，立即保存原始快照并更新可选字段。
4. 未启用透视时，直接展示原始快照。
5. 启用透视时，使用最新原始字段校验透视配置。
6. 透视配置无效时，不发送第二次请求，展示原始快照和透视警告。
7. 透视配置有效时，发送带 `pivot` 的第二次请求。
8. 透视请求成功时，展示透视结果；失败时恢复并展示原始快照，同时显示透视警告。

## 透视配置校验

前端在获得最新原始 SQL 字段后校验：

- `time_field` 必须非空且存在于原始返回字段中。
- `metric_fields` 必须非空，且每个指标都存在于原始返回字段中。
- `time_field` 不能同时出现在 `metric_fields` 中。

校验不得自动选择替代字段。旧字段失效时可以按现有逻辑清空，但必须保留“启用透视”状态并提示用户重新配置或主动关闭透视。

## 前端状态与提示

SQL 预览结果需要区分以下状态：

- `raw_success`：原始 SQL 成功，未启用透视。
- `pivot_success`：原始 SQL 和透视预览均成功。
- `pivot_invalid`：原始 SQL 成功，但透视配置无效，未发起透视请求。
- `pivot_failed`：原始 SQL 成功，但透视请求执行失败。
- `raw_failed`：原始 SQL 执行失败。

`pivot_invalid` 提示：

> SQL 执行成功，但图表透视未应用：请选择有效的透视时间字段和图表指标。

`pivot_failed` 提示：

> SQL 执行成功，但图表透视执行失败：{后端错误信息}

透视相关提示使用警告级别，不再写入“SQL 执行失败”的提示状态。原始数据预览必须保持可见。

## 保存行为

应用到画布前继续执行严格校验：

- 未启用透视时，不受透视字段影响。
- 启用透视且配置有效时，允许保存。
- 启用透视但字段缺失、字段不存在或时间字段与指标重复时，阻止保存并提示修复或关闭透视。
- 最近一次透视执行失败不应被静默保存为有效透视结果。

保存校验和预览校验应复用同一套字段判断，避免两处规则漂移。

## 后端行为

保留 `dashboard_service.py` 中 `_build_dashboard_pivot_sql` 的严格校验。后端仍应对缺少时间字段或指标的透视请求返回失败，不负责自动执行原始 SQL 作为回退。

前端只有在原始 SQL 成功且透视配置通过本地校验后，才发送透视请求。

## 测试范围

- 原始 SQL 成功且未启用透视：只请求一次并展示原始结果。
- 原始 SQL 成功且透视有效：请求两次并展示透视结果。
- 原始 SQL 成功但透视时间字段为空：不发送第二次请求，展示原始结果和警告。
- 原始 SQL 成功但透视字段已不在返回列中：不发送第二次请求，不自动替换字段。
- 原始 SQL 成功但透视请求失败：恢复原始结果并显示透视警告。
- 原始 SQL 失败：显示 SQL 错误，不显示成功状态。
- 启用无效透视时应用到画布：阻止保存。
- 关闭透视后应用到画布：允许保存。
- 后端缺少透视时间字段或指标时：仍保持严格失败。

## 验收标准

- 修改 SQL 导致旧透视字段失效后，点击“执行 SQL”仍能看到原始查询结果。
- 页面明确说明失败的是透视配置或透视执行，而不是原始 SQL。
- 无效透视配置不能应用到画布。
- 系统不自动替换用户选择的时间字段、指标或维度。
- 有效透视预览、普通 SQL 预览和后端直接调用行为不回归。
