# ROI 专用看板设计

## 背景

当前看板页左侧包含“推荐看板”和“我的看板”两个顶层分组。普通看板依赖工作空间绑定数据源，并复用通用自由画布与 `DashboardSqlEditor.vue`。

本需求新增第三个顶层分组“ROI 看板”。ROI 看板属于当前工作空间，由空间拥有者和空间管理员共同维护；普通成员不可见、不可访问。ROI 看板使用工作空间级统一数据源，该数据源从当前账号有权使用的数据源中选择，不受当前工作空间绑定数据源限制。

ROI 功能使用专用页面、专用数据表和专用 SQL 编辑器，不复用普通看板自由画布。底层 SQL 执行、数据源元数据读取和图表渲染能力可以复用，但 ROI 编辑器后续修改不得影响推荐看板和我的看板编辑器。

## 目标

- 在左侧树中新增与“推荐看板”“我的看板”纵向并列的“ROI 看板”顶层分组。
- ROI 分组内允许创建多个工作空间共享的下属看板。
- 仅当前工作空间角色为 `owner` 或 `admin` 的用户可查看和管理 ROI 功能。
- 为每个工作空间配置一个 ROI 统一数据源，所有下属看板及图表继承该数据源。
- 数据源候选项为当前账号有权使用的全部数据源，不局限于当前工作空间绑定数据源。
- 新建下属看板后立即打开 ROI 专用 SQL 编辑器。
- 使用 ROI 专用图表表和固定响应式网格，不保存通用画布自由坐标或组件 JSON。
- ROI 专用 SQL 编辑器首期完整支持 SQL、预览、图表类型、字段映射、透视和洞察配置，并可独立演进。
- 保持推荐看板、我的看板及其 SQL 编辑器行为不变。

## 非目标

- 不把 ROI 业务指标、公式、字段名或 SQL 模板硬编码到平台运行时代码。
- 不复用 `CoreDashboard`、`CoreDashboardTree` 的资源记录承载 ROI 下属看板和图表。
- 不复用普通看板自由画布、`component_data` 或 `canvas_view_info`。
- 不允许普通成员通过隐藏入口、直接 URL 或构造 API 请求访问 ROI 功能。
- 不因共享 ROI 看板而自动授予其他拥有者或管理员数据源权限。
- 首期不支持 ROI 下属看板嵌套文件夹。
- 首期不支持下属看板分别选择数据源。
- 首期不支持在 ROI 专用 SQL 编辑器中配置 MCP 数据来源。
- 不为下属看板名称新增唯一约束，名称行为与“我的看板”保持一致。

## 整体架构

ROI 功能作为独立模块实现：

- 后端新增 `roi_dashboard` 模型、服务和 API。
- 前端新增 ROI 看板页面、响应式网格、专用图表组件、专用 SQL 编辑器、状态模块、类型和 API。
- 左侧通用资源树只负责按角色决定是否请求并聚合 ROI 分组，不承载 ROI 图表编辑状态。
- ROI API、数据库表和缓存使用独立命名空间。
- 通用 SQL 执行、字段元数据读取、数据源访问校验、图表渲染器和稳定纯函数可以复用。

左侧树固定顺序为：

1. 推荐看板
2. ROI 看板
3. 我的看板

ROI 路由使用 `dashboardMode=roi`，与 `default`、`my` 的选中、展开和加载状态隔离。

## 数据模型

### `core_roi_workspace_config`

保存当前工作空间唯一的 ROI 配置：

- `id`
- `tenant_id`：当前工作空间 ID，唯一且不可为空
- `datasource_id`：ROI 统一数据源，不可为空
- `version`：乐观锁版本
- `create_by`、`update_by`
- `create_time`、`update_time`
- `deleted`

对活动记录建立 `tenant_id` 唯一约束。数据源绑定只服务 ROI 模块，不修改 `CoreDatasource` 的工作空间主绑定关系。

### `core_roi_dashboard`

保存 ROI 分组下的直接子看板：

- `id`
- `tenant_id`
- `name`
- `sort`
- `status`
- `version`
- `create_by`、`update_by`
- `create_time`、`update_time`
- `deleted`

记录按 `tenant_id` 共享，不按 `create_by` 过滤。表中不保存数据源；有效数据源始终从当前工作空间的 `core_roi_workspace_config` 读取。

### `core_roi_dashboard_chart`

保存 ROI 专用图表：

- `id`
- `tenant_id`
- `roi_dashboard_id`
- `title`
- `sql`
- `chart_type`
- `chart_config`：字段映射、透视和洞察等经过结构校验的配置
- `layout_span`：`full`、`half` 或 `third`
- `sort`
- `status`
- `version`
- `create_by`、`update_by`
- `create_time`、`update_time`
- `deleted`

图表表不保存数据源，也不接受图表级数据源覆盖。所有查询根据 `tenant_id` 读取工作空间 ROI 数据源。

`tenant_id + roi_dashboard_id`、`tenant_id + status + sort` 建立查询索引。服务层必须确认下属看板、图表和当前认证工作空间一致。

## 工作空间共享与权限

ROI 看板是工作空间共享资源：

- `owner` 和 `admin` 看到相同的 ROI 配置、下属看板和图表。
- `member` 不显示 ROI 顶层分组，所有 ROI API 返回 `403`。
- 跨工作空间访问下属看板或图表按资源不存在处理，避免泄漏资源 ID。
- 创建人不拥有额外私有范围，删除或修改操作对同一工作空间其他管理员立即可见。

所有 API 必须先使用服务端认证上下文解析 `tenant_id` 和工作空间角色。请求体中的 `tenant_id`、工作空间 ID 或角色不参与授权判断。

## ROI 统一数据源

ROI 顶层分组提供“设置数据源”操作。候选列表使用当前账号已有的数据源授权结果，但不按当前工作空间的单绑定数据源再次收窄。

设置数据源时后端必须确认：

- 当前用户角色为 `owner` 或 `admin`。
- 数据源存在且处于可用状态。
- 当前用户拥有该数据源访问权限。

其他拥有者或管理员即使没有统一数据源权限，仍可看到共享的 ROI 分组、下属看板和图表结构，但：

- 图表不执行。
- SQL 编辑、预览、添加、修改和删除图表均禁用。
- 页面明确显示“当前账号无此数据源权限”。
- 不因看板共享自动增加数据源权限。

更换数据源时统计当前工作空间所有活动 ROI 图表。只要存在任意图表即拒绝更换，并提示先清空全部 ROI 图表。不存在图表时允许更换；空的下属看板可以保留。系统不自动迁移 SQL、字段映射、透视或洞察配置。

数据源被删除、停用或当前用户失去权限时保留已有 SQL 和图表配置，但停止执行。

## 创建与编辑流程

### 设置数据源

空间拥有者或管理员可从 ROI 分组操作菜单打开数据源设置弹窗。设置成功后刷新 ROI 配置，不切换当前工作空间绑定数据源。

### 新建下属看板

1. 用户点击 ROI 分组的“新建下属看板”。
2. 尚未配置 ROI 数据源时，先打开数据源设置弹窗。
3. 数据源设置成功后继续输入下属看板名称。
4. 后端创建空的 `core_roi_dashboard` 记录。
5. 前端导航到 `dashboardMode=roi` 对应路由。
6. 页面立即打开 ROI 专用 SQL 编辑器，进入创建第一张图表状态。
7. SQL 预览成功并保存后创建 `core_roi_dashboard_chart`，关闭编辑器并展示响应式网格。
8. 用户取消首次编辑时保留空看板，可稍后添加图表或删除看板。

### 添加和编辑图表

- “添加图表”打开 ROI 专用 SQL 编辑器的新建状态。
- 图表编辑操作打开同一编辑器的修改状态。
- SQL 预览失败时禁止保存，编辑内容保留。
- 保存请求携带图表 `version`；旧版本返回冲突，禁止静默覆盖。
- 删除图表和删除下属看板需要二次确认并执行软删除。

## 固定响应式网格

ROI 页面不使用普通看板自由画布。图表按 `sort` 排序，并按 `layout_span` 分配响应式宽度：

- `full`：桌面占整行。
- `half`：桌面每行两张。
- `third`：桌面每行三张。
- 小屏幕按可用宽度自动降为单列或双列，不保存移动端专用坐标。

用户可以调整宽度并拖动排序，但不能自由设置任意 X/Y 坐标。动态标题、错误状态和加载状态不得改变网格轨道宽度或造成布局重叠。

## ROI 专用 SQL 编辑器

ROI 不直接引用或修改 `DashboardSqlEditor.vue`。首期新增独立的 ROI 编辑器组件、表单状态、类型定义、API 协议和测试，支持：

- SQL 编辑
- SQL 预览
- 图表类型
- 字段和轴映射
- 表格列配置
- 透视配置
- 洞察配置
- 图表标题
- `layout_span`

编辑器不提供数据源选择；数据源只在 ROI 顶层分组设置。编辑器加载字段元数据、预览和保存时均由后端根据工作空间 ROI 配置解析数据源。

可以复用稳定的底层能力：

- SQL 只读校验与执行接口内部实现
- 数据源 schema、表和字段元数据查询
- 通用图表渲染组件
- 不包含普通看板状态的纯函数工具

ROI 编辑器不得导入 `DashboardSqlEditor.vue`，不得读写普通看板 Pinia 状态，也不得使用普通看板保存协议。以后修改 ROI 编辑器的字段、按钮、校验和流程时，不需要修改推荐看板或我的看板编辑器。

## 后端接口

ROI 使用独立接口：

- `GET /dashboard/roi/config`：读取当前工作空间 ROI 配置。
- `PUT /dashboard/roi/config`：设置或更换统一数据源。
- `GET /dashboard/roi/list`：读取共享下属看板。
- `POST /dashboard/roi`：新建下属看板。
- `PATCH /dashboard/roi/{id}`：重命名或更新状态。
- `DELETE /dashboard/roi/{id}`：软删除下属看板及其活动图表。
- `POST /dashboard/roi/reorder`：保存下属看板排序。
- `GET /dashboard/roi/{id}/charts`：加载响应式网格图表。
- `POST /dashboard/roi/{id}/charts/preview`：预览 SQL。
- `POST /dashboard/roi/{id}/charts`：保存新图表。
- `PUT /dashboard/roi/{id}/charts/{chart_id}`：更新图表。
- `DELETE /dashboard/roi/{id}/charts/{chart_id}`：软删除图表。
- `POST /dashboard/roi/{id}/charts/reorder`：保存图表顺序和宽度。

数据源 ID 只允许在 `PUT /dashboard/roi/config` 提交。SQL 预览和图表接口不得接受客户端数据源 ID；后端根据认证工作空间读取统一配置。

## SQL 执行规则

ROI SQL 执行与普通看板的应用级查询权限规则明确隔离：

- 保留当前账号的数据源访问权限校验。
- 保留只读 SQL 校验，禁止 DML、DDL、存储过程调用和多语句。
- 保留数据源查询超时和主动取消能力。
- 不应用结果行数限制，不自动截断结果。
- 不应用平台级表权限校验。
- 不应用平台级字段权限校验。
- 查询范围由数据源连接账号自身的数据库权限决定。

大结果集可能增加数据库、网络、后端序列化和浏览器内存压力。系统通过执行耗时、返回行数、响应体大小和失败状态进行日志与监控，不增加隐藏结果上限，也不改变查询结果。

## 缓存

ROI 使用独立缓存命名空间。缓存键至少包含：

```text
tenant_id + user_permission_scope + datasource_id
+ roi_dashboard_id + chart_id + chart_version + sql_hash
```

当数据源访问权限按用户区分时，`user_permission_scope` 必须包含用户边界。以下变化使相关缓存失效：

- ROI 数据源配置变化
- 图表 SQL 或配置变化
- 图表或下属看板删除
- 当前用户数据源权限变化
- 数据源被停用或删除

用户失去数据源权限后禁止使用旧缓存兜底。ROI 缓存不与普通看板共享键或权限结果。

## 错误处理

- 普通成员访问 ROI API：返回 `403`。
- 跨工作空间资源：返回 `404`。
- 未配置 ROI 数据源：新建流程要求先配置；执行接口返回明确配置错误。
- 配置无权访问的数据源：返回 `403`，不写入配置。
- 当前用户无统一数据源权限：结构可见，图表不执行，编辑和预览禁用。
- 存在任意 ROI 图表时更换数据源：返回冲突错误，不修改配置。
- SQL 不是单条只读查询：拒绝预览和保存。
- SQL 预览失败或超时：保留编辑内容，不创建或覆盖图表。
- 图表版本冲突：返回冲突错误，不覆盖新版本。
- 数据源停用或删除：保留图表配置并停止执行。

错误响应不得包含数据源密码、连接字符串或底层堆栈。

## 测试策略

### 后端测试

- `owner`、`admin` 可以访问 ROI 配置、看板和图表；`member` 的全部 ROI 请求返回 `403`。
- 两个工作空间的配置、下属看板、图表和缓存完全隔离。
- 下属看板按工作空间共享，不按创建人过滤。
- 只能配置当前账号有权限的数据源，并且不受当前工作空间绑定数据源限制。
- SQL 和图表请求无法通过请求体伪造数据源或工作空间。
- 没有统一数据源权限的管理员能读取结构，但不能执行、预览或编辑图表。
- 存在任意活动图表时禁止更换数据源；只有空看板时允许更换。
- 删除、排序、宽度设置、乐观锁冲突和缓存失效符合设计。
- ROI 查询保留只读校验与超时。
- ROI 查询不应用普通看板结果行数限制、平台表权限或平台字段权限。
- DML、DDL、存储过程调用和多语句仍被拒绝。

### 前端测试

- ROI 分组只对 `owner`、`admin` 显示，且位于推荐看板与我的看板之间。
- 未配置数据源时，新建流程先设置数据源。
- 新建下属看板后自动打开 ROI 专用 SQL 编辑器。
- ROI 编辑器使用独立组件、状态、类型和 API，不导入 `DashboardSqlEditor.vue`。
- ROI 编辑器数据源不可单独选择。
- 固定响应式网格正确处理 `full`、`half`、`third` 和排序。
- 没有数据源权限时保留结构展示并禁用图表执行与编辑。
- `dashboardMode=roi` 不污染推荐看板和我的看板状态。

### 回归测试

- 推荐看板和我的看板的数据源绑定、SQL 编辑、复制、加载和权限规则保持不变。
- 普通看板继续应用原有结果行数、表权限和字段权限规则。
- 普通成员访问现有看板不受影响。
- 后端 ROI 专项测试、看板回归测试、前端回归测试和生产构建全部通过。

## 验收标准

1. 左侧树按“推荐看板、ROI 看板、我的看板”纵向展示，普通成员不显示 ROI 分组。
2. 空间拥有者和管理员共享同一套 ROI 配置、下属看板和图表。
3. 工作空间可设置一个不受主绑定数据源限制、但当前操作者有权访问的 ROI 数据源。
4. 新建下属看板后立即打开独立的 ROI SQL 编辑器。
5. ROI 使用专用看板表、专用图表表和固定响应式网格，不写入通用画布数据。
6. ROI 编辑器完整支持已确认的 SQL 和图表配置能力，后续修改不影响普通看板编辑器。
7. 没有统一数据源权限的管理员能看到结构，但不能执行或编辑图表。
8. 只要存在任意 ROI 图表就不能更换统一数据源。
9. ROI SQL 保留数据源访问、只读和超时校验，但不应用结果行数、平台表权限和平台字段权限限制。
10. 推荐看板、我的看板及普通成员现有行为无回归。
