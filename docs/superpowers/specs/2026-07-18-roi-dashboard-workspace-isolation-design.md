# ROI 看板工作空间隔离设计

## 背景

ROI 看板的数据源由 SaaS 后台工作空间表单中的“ROI数据源”字段配置。该配置与普通“绑定数据源”相互独立。

需要进一步固化以下业务边界：ROI 下属看板和图表属于工作空间资产，不在工作空间之间共享；ROI 图表执行只能使用当前工作空间配置的 ROI 数据源。多个工作空间可以配置同一个 ROI 数据源，但这不会使它们共享 ROI 看板或图表。

## 目标

- ROI 下属看板按认证工作空间隔离创建、查询、修改、排序和删除。
- ROI 图表按认证工作空间及所属 ROI 看板隔离。
- ROI 图表预览、创建、更新、删除、重排和查询执行只使用当前工作空间的 ROI 数据源配置。
- 客户端不能通过请求体、路径参数或普通当前数据源覆盖 ROI 数据源。
- 工作空间切换时清空前端 ROI 状态，并拒绝发布上一工作空间的迟到响应。
- 增加双工作空间回归测试，包括两个工作空间配置同一个 ROI 数据源的合法场景。

## 明确规则

1. `core_roi_dashboard.tenant_id` 是 ROI 下属看板的工作空间归属边界。
2. `core_roi_dashboard_chart.tenant_id` 必须与所属 ROI 看板的 `tenant_id` 一致。
3. `core_roi_workspace_config` 以 `tenant_id` 保存每个工作空间唯一的 ROI 数据源配置。
4. 一个工作空间最多有一个活动 ROI 数据源配置。
5. 同一个数据源可以被多个工作空间配置为 ROI 数据源，不增加 `datasource_id` 唯一约束。
6. SaaS 后台“ROI数据源”字段是唯一写入口；ROI 看板页面只读取该配置。
7. ROI 图表接口不接受客户端提交 `datasource_id`，也不回退到普通绑定数据源或前端当前数据源。
8. 未配置 ROI 数据源时，禁止创建 ROI 看板以及预览、创建或修改 ROI 图表，并返回明确错误。
9. 现有“修仙”和 `flam` 配置、看板及图表不因本次修改被清理或迁移。

## 后端设计

ROI 服务统一从认证后的 `current_user` 解析管理工作空间 ID，并将该 ID用于所有看板、图表和配置查询。任何资源 ID 查询都必须同时带工作空间条件；跨工作空间资源统一表现为不存在，避免泄露资源信息。

图表执行链路先按当前工作空间读取活动的 `core_roi_workspace_config`，再使用其中的 `datasource_id` 做权限检查和只读 SQL 执行。请求 DTO 继续禁止 `tenant_id` 和 `datasource_id` 字段，避免客户端伪造上下文。

SaaS 工作空间新增或编辑接口继续在同一事务中维护 ROI 配置。配置有效性只校验数据源存在且可用，不要求数据源只能被一个工作空间使用，也不要求它等于普通绑定数据源。

## 前端设计

资源树只展示当前工作空间 API 返回的 ROI 看板。切换工作空间时立即：

- 递增请求序号，使旧请求失效；
- 清空 ROI Pinia 中的配置、看板、图表和编辑器状态；
- 清空当前选中节点；
- 在新工作空间及数据源上下文加载完成后重新请求资源树。

每次发布 ROI 列表响应前，同时校验请求序号和请求发起时的工作空间 ID。普通当前数据源变化只影响普通“我的看板”，不改变 ROI 数据源选择。

## 数据处理

本次不执行业务数据删除、迁移或自动纠正：

- 不删除“修仙”的 `Test` 看板和图表；
- 不清除“修仙”或 `flam` 的 `ROI_flam` 配置；
- 不按数据源名称推断工作空间；
- 不自动把普通绑定数据源写入 ROI 配置。

如需调整某个工作空间的 ROI 数据源，由 SaaS 管理员在工作空间表单中显式选择。已有活动图表时，沿用现有保护规则，先处理图表再更换或清除配置。

## 测试设计

### 后端

- 两个工作空间分别创建 ROI 看板，只能读取各自记录。
- 两个工作空间配置同一个 ROI 数据源时，看板和图表仍严格隔离。
- 跨工作空间读取、更新、删除、排序看板或图表返回 `404`。
- 图表执行读取当前工作空间 ROI 配置，不使用客户端或普通绑定数据源。
- 请求 DTO 拒绝 `tenant_id` 和 `datasource_id`。
- 未配置 ROI 数据源时，写操作和查询执行返回明确错误。

### 前端

- 工作空间切换事件会清空 ROI store 和资源树。
- 上一工作空间的迟到 ROI 列表响应不会发布到新工作空间。
- ROI 分组使用 ROI API 结果，普通“我的看板”仍使用当前普通数据源。
- 同一 ROI 数据源被多个空间配置时，前端仍只展示当前空间 API 返回的看板。

## 验收标准

- 在工作空间 A 创建 ROI 看板后，工作空间 B 不可见且不能通过已知 ID 访问。
- 工作空间 A、B 即使配置同一个 ROI 数据源，也只能看到各自的 ROI 看板和图表。
- 工作空间 A、B 配置不同 ROI 数据源时，各自图表查询只命中自己的配置。
- 快速切换工作空间不会出现上一空间 ROI 看板短暂覆盖当前空间的情况。
- 现有业务数据保持不变。
