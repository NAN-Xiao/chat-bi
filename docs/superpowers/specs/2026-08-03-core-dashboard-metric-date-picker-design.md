# 三个空间核心看板指标卡日期控件迁移设计

## 目标

仅迁移以下三个空间中名称为“核心看板”的现有指标卡：

- 修仙
- flam
- 模板_修仙

目标指标卡的编辑抽屉统一使用 `DashboardDateExpressionPicker`，默认日期表达式为“昨日”。日期选择必须实际作用于 SQL 查询，不能只替换控件外观。

## 范围

- 只处理上述三个空间的“核心看板”。
- 只处理当前仍进入旧日期控件分支的指标卡。
- 不修改三个空间中的其他看板。
- 不按空间名、数据源名或业务字段在共享运行时代码中硬编码分支。
- 不改变其他空间现有指标卡的日期控件行为。

## 方案

### 通用前端能力

扩展图表日期配置，使指标卡可通过持久化配置显式启用日期表达式控件。共享前端根据通用配置决定是否允许 `metric` 使用 `DashboardDateExpressionPicker`，而不是判断具体空间或业务名称。

未显式启用的指标卡继续保持现有行为，控制变更影响范围。

### 目标看板配置迁移

为三个目标“核心看板”中的指标卡写入：

- 明确的时间字段；
- 日期参数类型；
- `dateExpressionPickerEnabled = true`；
- 允许指标卡使用日期表达式控件的显式通用配置；
- `timeRange = expression`；
- `timeExpression = { version: 1, mode: preset, preset: yesterday }`；
- 与 builder 一致的 pivot/date filter 日期表达式。

指标卡 SQL 改为使用平台看板日期参数。迁移后选择其他日期表达式时，查询结果必须随控件变化。

### 持久化与可恢复性

实现一个目标明确、默认只读预演的迁移脚本：

- 按 tenant ID、看板 ID 和名称限定目标；
- 写入前校验图表身份和基线配置；
- 写入前备份原始看板数据到 `.codex-runtime`；
- 使用事务、行锁和 CAS 条件避免覆盖并发编辑；
- 写入后重新读取并逐图表验证；
- 支持根据备份恢复。

同步更新现有修复或生成脚本中的目标指标卡配置，保证后续幂等重建不会恢复旧控件。

## 测试

### 前端回归测试

- 显式启用时，`metric` 使用 `DashboardDateExpressionPicker`。
- 未显式启用时，其他指标卡仍保持现有行为。
- 保存后保留显式启用配置和“昨日”表达式。

### 迁移脚本测试

- 只修改三个目标“核心看板”的目标指标卡。
- 默认表达式为 `yesterday`。
- SQL 包含正确的看板日期参数。
- 非目标图表和非目标看板保持字节级配置不变。
- 重复执行结果一致。
- 基线、所有权或 CAS 不匹配时拒绝写入。

### 完成验证

- 运行相关前端 Node 测试和后端 pytest。
- 对迁移脚本先执行只读预演，再执行写入。
- 写入后从数据库重新统计三个空间的目标核心看板。
- 在本地页面分别打开目标指标卡抽屉，确认显示 `DashboardDateExpressionPicker` 且默认值为“昨日”。

## 非目标

- 不迁移其他空间或其他看板。
- 不删除旧版 `el-date-picker` 兼容分支。
- 不改变全平台默认日期表达式。
- 不修改普通表单日期控件、MCP 日期参数或透视配置日期输入。
