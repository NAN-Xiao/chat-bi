# 表格容器尺寸修复设计

## 问题

ROI 看板卡片正文有 `10px` 内边距。S2 表格当前监听 `.chart-container` 的父元素，并把父元素的 `borderBoxSize` 直接作为画布尺寸。页面实测父元素为 `943×270`，实际表格容器为 `923×250`，最终画布超过容器并被 `overflow: hidden` 裁切，导致滚动到底后最后一行和最右侧仍显示不完整。

## 方案

表格尺寸只以自身挂载容器 `.chart-container` 的 `clientWidth`、`clientHeight` 为准：

- `ResizeObserver` 监听表格挂载容器，而不是父元素。
- 回调中重新读取挂载容器的实际可用尺寸，不使用父元素的边框盒尺寸。
- 初始渲染和后续尺寸变化统一使用同一套尺寸解析逻辑。
- 保留现有 `scrollbarPosition: 'content'`、列宽自适应和防重复渲染逻辑。
- 不修改 ROI 卡片的 `10px` 内边距及整体布局。

## 验收标准

- S2 画布宽高不超过 `.chart-container` 的实际可用宽高。
- ROI 卡片中横向、纵向滚动到底后，最后一行和最右列完整可见。
- 普通 ChatBI 表格和其他看板表格继续随自身容器缩放。
- 相关静态回归测试、前端类型检查及构建通过。
