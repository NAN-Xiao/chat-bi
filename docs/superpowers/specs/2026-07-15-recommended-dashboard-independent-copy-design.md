# 推荐看板独立复制设计

## 背景

当前“我的看板”执行“加入推荐看板”时，后端直接把原看板标记为推荐看板，并在“我的看板”和“推荐看板”两棵树中复用同一个 `dashboard_id`。因此，两处实际引用同一条 `core_dashboard` 记录，任一处编辑都会影响另一处。

本次改造把“加入推荐看板”定义为快照复制：每次成功操作都创建一个新的推荐看板记录，原看板和推荐副本在创建后不再互相同步。

## 目标

- 每次成功加入推荐看板时创建全新的看板记录和 ID。
- 完整复制通用看板配置，包括布局、组件、图表、SQL、数据源及移动端布局等可复用信息。
- 原看板的内容、状态、树位置和更新时间均不因复制而改变。
- 推荐副本只出现在“推荐看板”树中，不复用原看板在“我的看板”树中的位置。
- 当前工作空间内，启用中的推荐看板名称必须唯一。
- 移出推荐看板时只移除推荐副本，不影响原看板。

## 非目标

- 不建立原看板与推荐副本之间的持续同步关系。
- 不在重名时覆盖或刷新已有推荐看板。
- 不自动给副本名称追加序号或后缀。
- 不改变“从推荐看板复制到我的看板”的现有行为。
- 不处理与本功能无关的看板树重构或历史数据清理。

## 名称唯一规则

推荐看板名称在同一 `tenant_id` 下唯一，比较时遵循以下规则：

- 去除名称首尾空白。
- 英文字母忽略大小写。
- 只约束未删除、叶子类型且处于推荐状态的看板记录。
- 已移出的独立推荐副本不再占用该名称。

若同名推荐看板已存在，接口拒绝本次复制并返回明确的名称冲突错误；已有推荐看板和源看板都不发生变化。

服务层在复制前执行重名检查，以便返回可理解的业务错误。数据库增加相同语义的部分唯一索引，防止多实例或并发请求绕过服务层检查。

## 后端数据流

### 加入推荐看板

1. 校验操作者具有管理推荐看板的权限。
2. 加载源看板并确认其为可用的叶子看板，校验数据源或外部 MCP 的工作空间边界。
3. 规范化源看板名称，检查当前工作空间是否已有同名推荐看板。
4. 使用现有画布克隆逻辑深拷贝 `component_data`、`canvas_style_data` 和 `canvas_view_info`，确保内部组件/视图 ID 不与源看板复用。
5. 创建新的 `CoreDashboard`：使用新 UUID，设置 `is_default=1`，复制通用配置，并把创建者和更新时间设置为当前操作者与当前时间。
6. 只为新记录写入 `scope=default` 的 `CoreDashboardTree` 位置，不给它写入 `scope=my` 的位置。
7. 在同一事务中提交看板记录和树位置，并返回新推荐副本。

源看板的 `is_default`、`sort`、`update_by`、`update_time` 以及“我的看板”树位置保持不变。

### 移出推荐看板

对于只存在于推荐树中的独立副本，移出操作删除推荐树位置并软删除该副本，使其不再占用推荐名称。源看板不做任何修改。

对于历史上同时存在于“我的看板”和“推荐看板”树中的旧记录，保留兼容处理：仅移除推荐树位置并清除推荐状态，继续保留“我的看板”记录，避免历史数据丢失。

## 前端行为

- 继续使用现有“加入推荐看板”菜单和接口，不新增交互入口。
- 复制成功后刷新两棵树，当前选中的源看板保持不变。
- 因源看板保持非推荐状态，菜单仍允许再次执行“加入推荐看板”；若名称未释放，后端以同名冲突拒绝。
- 重名失败时显示明确提示，不自动改名、不切换选中节点。
- 推荐副本仍使用推荐树现有的编辑、排序和移出能力。

## 数据库约束与迁移

新增 PostgreSQL 部分唯一索引，约束当前工作空间内规范化后的推荐看板名称。索引范围限定为启用中的推荐叶子看板，语义与服务层校验一致。

迁移不得静默重命名、删除或合并已有数据。若升级前已存在同一工作空间内的同名推荐看板，迁移应明确失败并报告冲突，由维护人员确认业务含义后清理，再重新执行迁移。

## 错误与事务处理

- 无管理权限：保持现有权限错误。
- 源看板不存在或不是叶子看板：返回现有的资源错误。
- 数据源不属于当前工作空间：保持现有边界错误。
- 推荐名称冲突：返回业务冲突错误，不创建任何记录或树位置。
- 数据库唯一索引在并发下触发：回滚事务，并转换为与预检查一致的名称冲突错误。
- 克隆或持久化失败：整体回滚，禁止产生半成品推荐看板。

## 测试策略

后端回归测试覆盖：

- 加入后返回新 ID，源看板仍为非推荐状态。
- 新副本只存在于推荐树，源看板只存在于我的树。
- 画布、组件、图表、SQL、数据源和通用配置被完整复制，内部组件/视图 ID 已重新生成。
- 修改源看板或推荐副本后，另一侧内容不变。
- 同一工作空间内的规范化同名推荐看板被拒绝，且无残留记录或树位置。
- 不同工作空间允许使用相同推荐看板名称。
- 并发唯一约束异常被转换为稳定的业务错误。
- 移出独立副本只软删除副本，源看板仍存在。
- 历史双树记录移出推荐后仍保留在我的看板。

前端测试覆盖：

- 加入成功后刷新树且保持源看板选中。
- 名称冲突时不切换节点、不产生自动改名行为。

## 验收标准

1. “我的看板”加入推荐后，两处看板 ID 不同。
2. 任一侧后续编辑、排序、重命名或删除均不影响另一侧。
3. 同一工作空间的推荐看板中不存在规范化同名的启用中叶子看板。
4. 重复加入同名看板时操作失败并给出明确提示，已有数据保持不变。
5. 所有相关后端与前端回归测试通过。
