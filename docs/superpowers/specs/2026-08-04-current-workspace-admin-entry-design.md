# 当前工作空间管理入口权限设计

状态：已确认

日期：2026-08-04

## 背景

顶部“工作空间管理”入口当前会从用户拥有管理权限的全部工作空间中选择目标。若当前工作空间不是 `owner` 或 `admin`，实现会静默回退到第一个可管理工作空间，并在点击入口时切换全局工作空间。这会让用户从“示例工作空间”进入管理页时被自动切换到“修仙”。

## 目标

- “工作空间管理”入口只依据当前工作空间的权限显示。
- 当前工作空间角色不是 `owner` 或 `admin` 时隐藏入口。
- 不从其他工作空间选择默认管理目标，也不因点击管理入口静默切换工作空间。
- 用户明确切换到可管理工作空间后，入口随当前上下文重新出现。
- 保留平台工作空间代理在其明确代理工作空间内的管理入口。

## 方案比较

1. **按当前工作空间权限隐藏入口（采用）**：上下文唯一、改动最小，符合无静默回退约束。
2. **保留入口并弹出可管理工作空间列表**：可以管理其他空间，但入口含义不再是当前工作空间，且用户已经明确要求无权限时不显示。
3. **为管理页建立独立工作空间上下文**：能保持业务页选择不变，但会让顶部选择器和管理对象同时存在两个空间语义，范围和风险过大。

## 设计

`workspaceAdminEntry.ts` 通过 `canManageCurrentWorkspace(state)` 和当前工作空间 ID 解析唯一的管理目标。目标对象只由当前用户 Store 的工作空间字段构造，不再扫描所有工作空间，也不保留 `adminWorkspaceTenants[0]` 回退。`Menu.vue` 使用该策略决定是否生成入口。

`MenuItem.vue` 点击后通过同一策略再次校验当前工作空间，记录返回业务页所需的当前空间并进入管理页。该路径不接受其他租户目标，也不调用 `switchTenant()`。

## 测试

新增菜单权限回归测试，验证：

- 普通成员隐藏入口，`owner/admin` 显示入口，平台代理保留当前代理空间入口。
- 管理目标来自当前工作空间字段。
- 源码中不再存在“第一个可管理工作空间”回退。
- 模拟点击入口时不调用 Store 的 `switchTenant()`；无权限时不记录或导航。
- 既有菜单布局测试和前端类型检查继续通过。

## 验收标准

- 当前为“示例工作空间”且角色为普通成员时，不显示“工作空间管理”。
- 明确切换到“修仙”且角色为 `owner/admin` 后，显示入口。
- 点击入口不改变当前工作空间。
