# 聊天 AI 图表日期参数设计

## 目标

让聊天 AI 生成的可变时间范围图表保存看板日期参数模板；聊天预览先由后端渲染模板再执行，转存到“我的看板”后可直接由日期控件驱动。

## 范围

- 仅覆盖聊天问数生成的 SQL 图表及其添加到我的看板流程。
- 用户未指定时间范围时，使用截至昨天的过去 7 个完整自然日，即版本化日期表达式 `past_7_days`。
- 用户明确日期范围时，保存与用户语义一致的日期表达式。
- 仅对具备时间字段的非单值指标图表启用日期参数。
- 固定语义指标卡和无时间维度图表不生成日期参数或日期控件。

## 不在范围内

- 不修改 Data Skills；其日期规则由后续单独同步。
- 不改写历史聊天记录中的 SQL。
- 不在转存时自动把 `CURDATE()`、`CURRENT_DATE` 或其他动态函数猜测性转换为日期参数。

## 数据契约

聊天记录的 `sql` 保存未渲染的模板 SQL，例如：

```sql
WHERE e.dt BETWEEN {{dashboard_start_yyyymmdd}} AND {{dashboard_end_yyyymmdd}}
```

聊天图表 JSON 的 `pivot` 保存以下配置：

- `time_field`：已确认的时间字段。
- `date_parameter_type`：日期参数类型，例如 `yyyymmdd_number`。
- `date_expression`：版本化表达式，默认 `{"version": 1, "mode": "preset", "preset": "past_7_days"}`。

不新增 `ChatRecord` 数据库字段。图表 JSON 已是聊天图表转存看板配置的来源，承载 `pivot` 后可被现有转存逻辑保留。

## 执行流程

1. 聊天 SQL 生成路径判定当前图表是否是具备时间字段的非单值指标图。
2. 对该类图表，生成器必须返回完整的日期 token 和日期配置；缺失、不完整或日期类型不匹配时明确拒绝结果并要求重新生成。
3. 聊天首次执行及图表实时刷新均调用现有看板日期模板渲染器，以 `pivot` 解析日期范围并得到实际 SQL。
4. 仅将渲染后的 SQL 发送到数据源；保存和展示的 SQL 保持为模板 SQL。
5. 转存到我的看板时，已有 `chart.pivot` 原样保留；看板使用同一渲染器响应日期控件。

## 错误与边界

- 带日期 token 但没有完整 `pivot` 配置：拒绝执行并返回明确配置错误。
- 不具备时间字段的图表：不要求 token，不创建日期配置。
- 固定指标卡：不要求 token，并清理错误遗留的日期配置。
- 实时数据源：沿用现有“不支持自定义日期范围”语义。
- 未更新 Data Skills 前，若模型仍输出数据库当前日期函数，日期参数化图表生成会明确失败并请求重新生成；不进行静默 SQL 改写。

## 验证

- 后端测试覆盖：默认过去 7 天、用户指定时间、固定指标卡、无时间维度图表、日期 token 与参数类型不匹配、聊天执行渲染。
- 前端契约测试覆盖：聊天图表 JSON 保留 `pivot`，转存到我的看板后不丢失日期配置。
- 回归验证：聊天生成趋势图的模板 SQL 使用日期 token，预览数据来自渲染后的 SQL；转存后修改日期控件可刷新同一图表。
