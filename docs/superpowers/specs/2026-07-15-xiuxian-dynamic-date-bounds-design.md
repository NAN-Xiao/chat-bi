# 修仙 Data Skill 动态日期边界设计

## 目标

修仙数据源的日期过滤不再通过 `MAX(dt)` 探测业务截止日期，避免为确定时间边界执行额外聚合扫描。所有查询应先生成单行 `bounds` CTE，再使用原始整数分区字段 `dt` 进行范围过滤。

## 日期规则

1. 用户指定绝对起止日期时，`bounds.start_dt` 和 `bounds.end_dt` 直接使用用户给定日期，并转换成 `YYYYMMDD` 整数。
2. 用户指定相对窗口时，根据窗口长度动态计算边界，截止日默认为昨天。例如“近 30 天”以问题要求的窗口长度生成对应开始日期，示例只用于说明写法，不作为固定范围。
3. 用户未指定日期窗口时，默认查询截至昨天的最近 28 个自然日。
4. 起止日期均包含在查询范围内。生成开始日期时必须按包含端点的天数计算，避免少一天或多一天。
5. 后续 CTE 必须通过 `JOIN bounds b` 或 `CROSS JOIN bounds b` 引用边界，并使用 `e.dt BETWEEN b.start_dt AND b.end_dt` 等原始分区条件。
6. 修仙 Data Skill 中不得再出现 `MAX(dt)`、`MAX(e.dt)` 或以最大业务日期为锚点的兼容说明和参考 SQL。

## 修改范围

- 更新 `tools/seed_xiuxian_data_skills.py` 中“修仙业务日期与按日聚合口径”：删除“标准聚合 SQL”章节和最大业务日期规则，补充动态边界规则、默认 28 天规则及非固定示例。
- 更新同文件的“修仙付费收入与 ARPPU 口径”：保留“近七天”业务含义，但改用系统日期推导的七天边界，不再计算 `MAX(e.dt)`。
- 更新相关测试，使其验证动态边界、默认窗口和整个 Data Skill 不包含 `MAX(dt)`。
- 运行种子脚本，将修改后的工作空间级 Data Skill 幂等写入系统数据库并刷新 embedding。

## 验证

1. 先增加会因现有 `MAX(dt)` 内容而失败的回归测试。
2. 修改 Data Skill 后运行修仙种子脚本相关测试。
3. 运行受影响的 Smart Q&A / 看板 SQL 提示词测试，确认没有破坏通用动态日期能力。
4. 回写数据库后查询当前工作空间、数据源 `6` 的启用 Data Skill，确认所有 prompt 均不包含 `MAX(dt)` 或 `MAX(e.dt)`。

## 非目标

- 不修改全平台通用 SQL 生成逻辑。
- 不为其他数据源引入修仙日期口径。
- 不在代码中硬编码业务表之外的指标公式或事件含义。
