# 本地启动与任务队列隔离实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让无修饰的“启动/重启”只操作当前本地工作区，并默认启动前端、API、MCP 和使用独立队列的本地 Worker。

**Architecture:** 复用现有 `tools/stack-local.ps1`、`tools/backend-local.ps1` 与 `tools/worker-local.ps1` 的本地队列生成和进程管理能力，不修改 Python 任务队列实现。更新仓库约定与已安装的 `starting-chat-bi-local` 技能，使运行手册统一调用现有脚本，并单独管理前端 Vite。

**Tech Stack:** PowerShell、Codex Skill Markdown、Redis 任务队列、Vite、Uvicorn

## Global Constraints

- 无修饰的“启动”“重启”只允许操作 `D:\AIWork3\chat-bi` 本地进程。
- 默认服务为前端 `5173`、API `8000`、MCP `8001` 和一个本地 Worker。
- 本地 API 与 Worker 必须使用同一个 `local-<计算机名>-chat-bi` 队列。
- 不得操作 SSH、Jenkins、Docker 或生产容器，除非用户明确指定生产范围。
- 所有 `stack-local.ps1` 启动、重启和状态命令必须显式传入 `-SkipDatabase -SkipRedis -SkipNginx`，不得启动或停止远程 PostgreSQL、远程 Redis 或本地 Nginx。
- 本地大模型配置必须解析为 `LLM_REQUEST_TIMEOUT=120`、`LLM_TASK_MAX_WAIT_SECONDS=900`、`LLM_MAX_RETRIES=1`。
- 前端进程归属判断必须将正规化后的当前工作区 `frontend` 目录构造成带末尾 `/` 的路径前缀，再匹配 `Win32_Process.CommandLine`；不得让 `frontend-copy` 等同名前缀目录获得停止权限。
- 状态检查必须在 `stack-local.ps1 -Action status` 之外独立输出前端 `5173` 的监听状态，并与 API、MCP、Worker 一起构成四服务报告。
- 保留工作区中与本任务无关的现有修改。

### Task 3: 修复本地编排脚本的可移植性与重启接管

**Files:**
- Modify: `tools/backend-local.ps1`
- Modify: `tools/stack-local.ps1`

**Interfaces:**

- Produces: 可正常检查状态、拒绝生产 `default` 队列、验证进程所有权与队列元数据，并能在父级 `restart` 时安全接管旧本地 Uvicorn 端口进程的本地编排脚本。

- [ ] **Step 3: 编写并运行重启接管契约的失败测试**

```powershell
$backendParams.ForcePortStop = $true
```

Expected before fix: 失败，因为旧手工进程没有 PID 文件时不会被停止。

- [ ] **Step 4: 实现安全停止、队列元数据与监听地址约束**

实现以下最小行为：

```text
1. backend-local、worker-local、stack-local 只接受 local-* 队列并拒绝 default。
2. API、MCP 和 Worker 写入队列元数据；复用现有进程前校验 PID、命令行和队列。
3. 陈旧 PID 文件不得终止 PID 已复用的无关进程。
4. 强制端口停止只允许匹配预期 Uvicorn 入口的进程。
5. API/MCP 默认监听 0.0.0.0，并等待实际监听 PID 后再写 PID 文件。
6. API/MCP 与 Worker 的启动环境都显式固定 `LLM_REQUEST_TIMEOUT=120`、`LLM_TASK_MAX_WAIT_SECONDS=900`、`LLM_MAX_RETRIES=1`。
7. 默认 Worker 是必需服务；未使用 `-SkipWorker` 时 Redis 不可达必须抛错并返回非零，不能只告警后继续。
8. `stack-local.ps1 -Action status` 必须调用 `worker-local.ps1 -Action status`，复用当前工作区命令行和队列一致性校验，不能只按 PID 判断运行状态。
9. Worker 启动后必须等待最短稳定窗口；若进程已退出，清理 PID/队列元数据并抛错。
```
