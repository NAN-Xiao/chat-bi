# 日期规则执行校验与趋势结果修复方案

> 实施时按任务逐项执行，并使用 executing-plans 或 subagent-driven-development 工作流；本文件是修复方案，不代表修复已经实施。

**Goal:** 日期转换违反已有配置时进入受控修复；无有效时间维度的结果不能作为成功趋势图展示。

**Architecture:** Data Skills 和当前工作空间元数据继续定义规则。共享 SQL 校验器验证可证明的日期编码冲突，共享结果校验器验证实际输出，问答编排负责有限重试，渲染入口负责拦截历史无效配置与数据。

**Tech Stack:** Python、SQLGlot、现有 LangGraph SQL 修复流程、Vue/TypeScript、现有 pytest 和前端测试设施。

**Spec:** 本文“问题证据、规则边界、验收矩阵”共同构成实施规格。

## 规则边界

1. 不另建日期业务口径，不硬编码字段名、指标名、数据源 ID 或日期范围。
2. 读取当前工作空间授权元数据中的字段类型、编码、角色；复用现有解析方式。Data Skills 的规则若只有自然语言，不声称已全部转成可执行规则，也不让另一次模型推测成为校验依据。
3. 日期筛选参数类型只能约束对应参数，不能证明 SQL 中所有字段或派生列使用相同编码。
4. 从明确的 DATE_FORMAT、字面量、CAST、别名、CTE/子查询投影追踪实际输入格式；表达式改变格式后必须更新其编码。来源不明、联合分支格式冲突时标记未知，不套用默认格式。
5. 只对可证明的输入编码与解析格式冲突自动修复。日期全空只能证明趋势不可用，不能单独证明 SQL 写错。
6. 空结果、零指标、合法指标 NULL、相同日期下不同系列均需保留原有业务语义。不得补猜测日期、替换横轴、把 NULL 指标一律改零或静默丢行。
7. 修复继续受原权限、数据源、日期范围、粒度、指标定义、重试次数和任务时限约束；不得额外获得独立重试预算。
8. 实施使用现有 linked worktree D:/AIWork6/release_1.3.0，分支 release/release_1.3.0；保留其他未提交工作。当前阶段仅新增方案文档。

## 任务 2：结果校验接入现有修复状态机

**修改位置：** backend/apps/chat/task/smart_qa_graph.py、backend/apps/chat/task/llm.py、backend/apps/chat/task/sql_repair.py；新增 backend/common/utils/chart_result_validation.py 和 backend/tests/test_chart_result_validation.py；扩展现有图流程测试，保留已有改动。

**接口设计（拟新增）：**

```python
def validate_chart_dimensions(chart_type: str, axes: dict, fields: list[str], rows: list[dict], temporal_fields: set[str]) -> list[dict]:
    ...
```

返回结构化问题列表，每项含 code、field、row_count、invalid_count；不修改输入。temporal_fields 由授权配置和可证明的 SQL 投影来源构成，不按“日期”字样猜字段。分类图与时间趋势的校验要求应区分。

- [ ] 添加七行日期全 NULL 的失败用例：不能保存为成功趋势图，不能产生成功图表事件。
- [ ] 在 _execute_sql 完成列名归一化之后、end_log/save_sql_data/execute-success 之前，校验已能明确识别的时间维度。
- [ ] 图表生成后再检查真实轴绑定；将 check_save_chart 的解析、校验和保存边界理清，确保无效配置不会先落库再报错。
- [ ] 有日期转换冲突证据的失败进入 _queue_sql_repair → _repair_sql → _prepare_sql → _execute_sql；图表阶段发现可修复失败时增加相应条件边，不能继续固定跳转 END。
- [ ] 空维度但无 SQL 错误证据时，返回“日期列为空，无法展示趋势，请检查数据或日期配置”；不推测错误原因或无限重试。
- [ ] 全空/缺列/部分无效时间维度均给出明确状态；部分无效时保留原始表格供查看并阻止该时间趋势图，不能悄悄过滤后展示不完整趋势。
- [ ] 修复成功后清除当前尝试的旧图表结果与错误状态，成功事件只对应已验证结果；尝试失败可保存诊断信息，但不得当作成功数据发布。
- [ ] 验证流式和非流式调用、SQL-only、QUERY_DATA 提前结束、权限拒绝、重试耗尽、任务超时及重复错误指纹。

SQL-only 路径只执行 SQL 静态校验；QUERY_DATA 路径只校验有明确时间契约的结果，不凭所有 NULL 列拒绝普通表格查询。

## 验收矩阵

| 场景 | 预期 |
| --- | --- |
| 本次 CTE 的 YYYYMMDD → 错误解析模板 | 执行前拦截，受控修复后重新执行 |
| YYYYMMDD/ISO/原生日期/时间戳合法转换 | 通过，不统一替换格式 |
| 元数据未知或 CTE 来源无法证明 | 不猜格式；依据真实结果决定可展示性 |
| 七行指标非空、日期全部 NULL | 明确失败，不展示竖线或趋势摘要 |
| 返回零行 | 正常无数据提示，不触发日期修复 |
| 日期有效、指标为 0 或合法 NULL | 按原口径展示，不误判日期错误 |
| 部分时间值无效 | 明确告知数量，保留原表，暂停趋势展示 |
| 分类维度含空值 | 按分类图规则处理，不套时间解析规则 |
| 同一天多系列、只有一天有效数据 | 不因日期重复或点数少而误判 |
| 自动修复 SQL 更改权限/数据源/范围 | 原有权限和范围校验拒绝 |
| 重试耗尽/超时/相同错误重复 | 终止并提示，不发送成功图表事件 |
| 历史回显/全屏/看板复制与刷新 | 所有入口一致拦截无效图表 |
