## 本轮发现并修复的问题

### 1. 未填筛选值被静默丢弃

F10：已选全局“用户ID”但值为空，原页面仍提示生成成功，SQL 与未配置该筛选时相同。F08 的 JSON 字段缺值则因为 SQL 中缺少 JSON 表达式，被误报为“字段映射不一致”。

根因：共用 `filterContext` 序列化会剔除不完整规则，生成入口没有在剔除之前检查原始筛选树。

修复：共用生成入口先校验当前模型、全局及公式/指标中的原始筛选树，缺少字段或值时明确阻止发起请求并清空旧预览。`0`、`false` 和 `is_null/is_not_null` 正确区分。保存和恢复草稿也保留不完整节点，避免重开后丢失用户配置。F14、F15、R11 已在页面复测。

### 2. 保存重开后普通条件被误认成空条件组

保存后的普通规则带有 `type='rule', children=[]`；旧渲染、有效性判定和字段权限遍历用“存在 children 数组”判断分组，导致正常条件被隐藏或剔除。

修复：这些相关入口统一按明确的 `type` 判断规则/组。复测 F13 中保存重开并重新生成的 SQL 与 F12 **逐字相同**，仍含全局 OR 和第二步 Organic 条件。

### 3. 合法数值 JSON 参数的 AVG 被拒绝

R04：页面选中 `int` 类型的“大本等级”事件参数后，AVG 返回 `retention.simultaneous.metricField：表达式与授权字段映射不一致`。

根因：Schema 解析将 int/double/decimal 等归一化为 number，而请求字段表达式生成只识别字面 `number`，同一授权字段产生了文本提取与数值 CAST 两种表达式。

修复：在共用 JSON 表达式模块统一声明类型归一化，Schema 解析、字段解析器和运行时表达式使用同一规则。不根据业务字段名称推断类型。R05—R09 实际完成 AVG、SUM、MAX、MIN、COUNT DISTINCT 生成和执行。
