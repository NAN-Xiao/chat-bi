## 2026-10-08：付费资格与收入口径事件独立

用户确认“付费事件”用于确定付费用户，“收入口径”独立选择事件和数值属性；两处均保留。

- `initialEvent` 仍定义按日期、主体和分组去重的同期群；`cohort_size` 不因付费资格收缩。
- `paymentEvent` 确定该同期群观察期内的付费主体；新增必填 `metricEvent` 独立指定口径事件。对符合付费资格的主体，在同一观察期内按口径事件日期统计九种指标。此处没有额外引入“收入事件必须发生在付费事件之后”的时刻条件。

## 统计契约

1. 初始事件按 `cohort_date + entity_id + 配置分组` 形成唯一同期群，然后关联付费明细。主体可以进入不同日期的同期群；重复初始事件不放大收入，真实的同金额支付明细全部保留。
2. 观察时长 N 为 1—365 的整数，输出 `day_0` 至 `day_N`，包括初始当天。按业务自然日计算，金额归属以初始日期为起点，不增加页面未配置的“全历史首次事件”或同日精确时刻限制。
3. 每日总次数为事件数；每日触发主体数为主体去重数；人均次数为每日总次数除以当日触发主体数，零分母为 NULL。
4. 周期累计次数及主体数为每日值之和；累计主体数保持既有“每日去重数之和”的定义。周期均值用累计值除以 N+1 个已覆盖自然日，包含无行为日期。
5. 属性 SUM/AVG 仅使用所选数值属性。成熟且无行为时计数和 SUM 为 0，AVG 和零分母人均值为 NULL。当前 SUM 模板也将全 NULL 聚合结果展示为 0；AVG 保留 NULL。
6. 各 `day_N` 以配置的看板结束 token 判断成熟，未成熟为 NULL；YYYYMMDD 先解析为 DATE，timestamp 使用排他结束边界，不使用当前时间或支付最大日期替换截止日。
7. 成本按用户确认的口径，为同期群观察期内匹配付费明细的成本字段总和。完整观察期未成熟时 `cost_value` 为 NULL。
8. 全局筛选与强制表条件分别落实在初始和付费事件来源中；用户 OR 条件保持独立括号组，与工作空间条件用 AND 连接。分组固定在初始事件侧，NULL 分组使用空值安全的关联。
9. 只为实际存在的同期群输出行；全局条件不匹配时返回空结果，不虚构零人数同期群。

当前页面使用默认事件表；收入编译支持同一授权事件表的初始和付费事件，未配置的跨表关联明确拒绝。方言提供 PostgreSQL、MySQL、StarRocks 和 Doris 模板。后两者通过构造与方言解析测试，未进行真实引擎执行验收。

## 元数据与权限

事件必须与当前工作空间字典来源一致且定义唯一，字段来源列必须授权。数值类型按服务端真实 SQL 类型判断；无 JSON 路径的事件参数不能用语义标签覆盖物理文本类型。

JSON 参数按选中的可信映射校验来源、路径、宿主类型和表达式，覆盖显式事件参数、无 kind 的虚拟引用及工作空间 JSON 属性。未使用参数的来源列被隐藏，不阻止不依赖该列的合法计数查询；选中该参数仍会被拒绝。

编译器保证配置生成路径的契约，不把任意手写 SQL 当作与配置等价。已有保存 SQL 不批量重写；手工执行仍经过既有权限及 SQL 安全入口。
