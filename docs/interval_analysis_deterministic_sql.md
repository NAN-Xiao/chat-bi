## 生成与执行

- 配置先形成不可变 `IntervalSqlPlan`，可信字段解析、元数据及表级强制筛选均在编译前确定。成功、失败和修复入口都不会调用 LLM 或 Embedding。
- SQL 只编译一次，校验实际输出的 SQL 与保留的编译快照，并独立检查固定结果列及起点日期血缘；校验阶段不改写 SQL。
- 不同事件配对相邻 A→B，A1,A2,B1,B2 只得到 A2-B1；同事件按候选流相邻记录配对。关联键为空的事件不参与关联配对，日期和分组来自实际起点。
- 在同一条 SQL 内检查主体/关联键、绝对事件时间及全部排序字段组成的完整键。排序字段 NULL 或完整键重复时，整个查询明确失败，不选择任意顺序、不静默去重。
- 日期参数保留动态窗口：日期两端包含，timestamp 左闭右开。按业务时区归属日期，按绝对秒计算时长；timestamp 同样补齐日期。
- 无分组且无事件时按日返回零计数、NULL 时长；有分组时仅补齐真实起点形成的分组元组。没有起点维度时返回空结果，不制造“未知分组”。
- 保留平台结果规模限制：读取至配置上限加一行检测超限，超限时明确要求缩小范围或分组，不返回被截断的日期结果，也不无界加载结果集。
- 无时区日期时间的查询范围跨源时区 DST 切换时明确阻断；epoch/带时区字段支持实际时间差计算。MySQL 原生 TIMESTAMP 含精度类型统一按 UTC 连接读值处理，仅在表达式实际需要时验证命名时区转换能力。

## 执行契约与缓存

SQL 的注释携带服务器签名的执行契约，覆盖查询 AST、工作空间、数据源、元数据摘要和时区要求；只有指定日期边界参数的替换允许变化。不能删除签名、修改查询结构或丢弃排序守卫后继续作为新版间隔图表执行。

执行契约随原有 SQL 字符串保存和传递，无需前端增加请求字段。公共执行入口检查权限、元数据和签名，再执行查询；成功后删除内部 `__interval_order_error` 列才向表格返回业务字段。真实错误不能显示成空数据。

成功缓存保留服务器验证信封，缓存键包含 SQL、用户、工作空间和数据源边界。失效契约/信封不能复用；查询失败会失效旧缓存，间隔请求不会回退到过期成功缓存。结果转换保留该信封，复制、重开和刷新共用同一执行规则。

签名依赖平台 `SECRET_KEY`，密钥轮换会使旧签名失效，需要重新生成对应新版间隔 SQL。没有引入新的密钥、权限或后台模型服务。
