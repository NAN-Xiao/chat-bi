# 知识库与 RAG 调用链路需求文档

## 1. 文档信息

- 文档类型：产品需求文档（PRD）
- 日期：2026-08-02
- 适用产品：星通数智通用 BI / ChatBI 平台
- 需求状态：待复审
- 本期范围：知识库管理、结构化知识维护、RAG 检索，以及 Smart Q&A、AI 看板、综合分析助手的统一接入

## 2. 背景与问题

系统当前已经存在工作空间数据字典、事件参数、JSON 字段解析、Data Skills、SQL 示例及普通业务文档等不同形态的业务语义配置。知识内容缺少统一管理入口，各 AI 场景也尚未统一复用知识、Skills 和权限上下文。

主要问题包括：

1. 知识分散在不同页面、文件和配置中，缺少统一的展示、编辑、版本和发布能力；Skills 已有独立管理入口，不纳入知识库发布体系。
2. 现有知识库主要面向文件上传和正文展示，缺少切片、向量化、检索和引用能力。
3. Smart Q&A、AI 看板和综合分析助手没有统一使用同一套知识检索和权限边界。
4. 事件参数和 JSON 路径属于确定性配置，不能仅依赖向量召回；Data Skills 也必须继续使用现有结构化选择和 SQL 约束能力，不能退化为普通文档。
5. 平台公共知识和工作空间知识需要明确隔离、冲突处理和工作空间级停用机制。

## 3. 建设目标

建设一个统一的知识库管理与 RAG 服务，使业务人员能够在页面中展示、逐条结构化编辑、校验、发布和回滚知识，并让所有 AI 分析场景在相同的数据源、权限和语义边界下融合已发布知识与现有 Data Skills。

核心原则：

> RAG 负责找到相关知识并帮助模型理解；结构化语义层负责保证表、字段、JSON 路径、指标口径和 SQL 规则准确。

知识库是四类知识内容的统一管理入口，但不把确定性的结构化知识降级为只供向量检索的普通文档。Data Skills 保留独立管理入口、存储和生命周期，只在运行时进入统一语义上下文。

## 4. 知识范围

第一期支持以下四类知识。

### 4.1 普通知识文档

用于维护制度、业务说明、操作规范、分析方法和其他非结构化资料。

主要内容：

- 名称、摘要和标签。
- Markdown 正文。
- Markdown、Word 文件上传及解析。
- 来源、作用域、状态和版本信息。

### 4.2 业务知识

业务术语和 SQL 示例合并为一种“业务知识”。一条业务知识可以只有术语定义、同时包含术语和 SQL 示例，或者只有问题和 SQL 示例。

业务定义字段包括：

- 名称、别名和标签。
- 业务含义和计算口径。
- 使用条件、限制和注意事项。
- 关联表、字段、事件、指标或 JSON 字段。
- 示例问题。

SQL 示例字段包括：

- 示例名称和对应问题。
- SQL 正文。
- 数据库方言。
- 涉及的表、字段和 JSON 路径。
- 使用说明和适用条件。
- Schema 校验、只读校验和规则校验结果。

一条业务知识允许包含零到多条 SQL 示例。仅通过当前数据源 Schema、权限、SQL 只读安全和 Data Skills 规则校验的 SQL 示例，才能作为 SQL 生成参考。

### 4.3 事件参数对照

用于维护事件和事件参数的确定性定义，包括：

- 事件名称、显示名称、别名和业务含义。
- 参数名称、显示名称、数据类型和是否必填。
- 参数所属事件、参数来源和取值说明。
- 枚举值、更新方式、示例值和备注。
- 关联物理表、事件字段和时间字段。

事件名称在同一工作空间的跟踪规范内必须唯一，不使用表名作为事件名称的命名空间。

### 4.4 JSON 字段解析

用于维护 JSON 子字段到可查询字段的确定性映射，包括：

- 物理 Schema、物理表和 JSON 宿主字段。
- JSON Path。
- 展开后的字段名和显示名称。
- 数据类型、空值处理和必要的类型转换。
- 数据库方言及确定性解析表达式。
- 字段含义、枚举和值域说明。

SQL 生成必须使用已发布且通过当前数据源 Schema 校验的映射，不允许在映射缺失或失效时自动选择相似字段或猜测 JSON 路径。

### 4.5 Data Skills（独立能力，不属于知识类型）

Data Skills 继续用于维护可执行的业务分析规则和 SQL 约束，包括：

- Skill 名称、稳定标识、说明和标签。
- 触发问题、关键词、同义表达和使用条件。
- 指标定义、时间规则、分子分母和过滤条件。
- 必须使用或禁止使用的表、字段、条件和 SQL 模式。
- SQL 示例、图表建议和回答要求。
- 优先级、启用状态和验证规则。

Data Skills 继续使用现有页面、API、`custom_prompt` 存储、启停状态、场景范围、三级作用域和 `find_data_skills` 选择链路。用户传入 `data_skill_id` 时沿用显式选择；未传入时沿用现有自动匹配、foundation Skill、覆盖去重和数量限制。第一期不把 Skill 建成知识库条目，不为 Skill 增加知识库草稿、发布、版本或回滚状态，也不生成一套并行的 Skill 路由和 RAG 主数据。

允许为 Skills 建立独立、可重建的对象引用安全投影，但不复制 Skill 正文或改变主数据。现有 Skill 必须先完成与当前内容哈希一致的对象扫描，才能进入原选择链路；已确认不引用物理对象的 Skill 允许以“READY、零引用”状态参与匹配，未扫描、扫描失败或已失效不能被当作零引用放行。

## 5. 统一管理、双形态使用

事件参数、JSON 字段解析和业务知识采用“结构化记录 + 检索切片”双形态：

1. 页面编辑和发布的是结构化记录，作为准确性和校验的权威来源。
2. 发布后根据结构化记录生成标准化检索文本、切片和向量，供 RAG 召回。
3. SQL 生成读取结构化映射和规则，不能仅依赖召回文本。
4. 普通知识文档以版本化正文、切片和向量为主要运行形态。
5. 结构化记录与其检索切片必须共享同一个知识条目 ID 和发布版本，保证可追踪。
6. Data Skills 不使用知识库发布版本；统一调用链记录实际选中的 Skill ID、作用域、选择模式和内容哈希，保证可追踪。

## 6. 知识作用域

所有四类知识都必须区分以下两级作用域。

### 6.1 平台公共知识

- 由平台管理员创建、编辑、校验、发布和回滚。
- 可以维护普通文档、业务知识、事件参数和 JSON 字段解析。
- 平台事件参数、JSON 映射和业务知识中的 SQL 示例允许包含具体物理 Schema、表、字段及 JSON Path。
- 平台公共知识不固定绑定某一个工作空间的数据源。
- 被某个工作空间使用时，动态采用该工作空间当前绑定的数据源进行 Schema 和权限校验。
- 只有在当前数据源中校验通过的结构化映射才能进入 SQL 上下文。

### 6.2 工作空间知识

- 由工作空间管理员在当前工作空间内维护。
- 只允许当前工作空间成员在授权范围内使用。
- 使用当前工作空间当前绑定的数据源作为唯一业务数据源上下文。
- 不能被其他工作空间检索、引用或用于 SQL 生成。

### 6.3 平台映射的动态应用规则

平台公共事件、JSON 映射或 SQL 示例中包含具体物理对象时，使用流程为：

```text
平台公共结构化知识
  -> 当前发起请求的工作空间
  -> 取得该工作空间当前绑定的数据源
  -> 校验数据源访问权限
  -> 校验物理表、字段、JSON Path 和方言表达式
  -> 校验通过后进入当前请求的结构化 SQL 上下文和 RAG 上下文
```

约束如下：

- 当前数据源结构不匹配时，相关映射或 SQL 示例不参与 SQL 生成，并显示明确的不适用原因。
- 不得自动替换成相似表、相似字段或其他 JSON Path。
- 工作空间重新绑定数据源后，平台公共映射和工作空间映射都需要重新校验。
- 其他工作空间的校验结果不能直接复用于当前工作空间。

### 6.4 Data Skills 作用域

- Skills 保留平台公共、工作空间和个人空间三级作用域。
- 平台公共 Skill 由平台管理员维护；工作空间 Skill 由当前工作空间按既有权限维护；个人 Skill 仅创建者日常查看、编辑和使用。
- Skill 被选中后仍需针对当前工作空间绑定的数据源校验其必需 Schema、表、字段、事件和 JSON Path；不适用或无权的 Skill 不进入 Prompt。
- Skill 权限过滤在 `find_data_skills` 拼装 Prompt 正文前完成，只能缩小候选集合，不能改变现有显式选择、自动匹配、foundation、覆盖去重或数量限制；显式选择无权/不适用 Skill 时明确报错，不回退到其他 Skill。
- Skills 的管理入口和生命周期独立于知识库，知识库页面不提供 Skill 编辑器。

## 7. 平台与工作空间冲突规则

1. 工作空间知识不能修改或覆盖平台公共知识。
2. 同名或同稳定标识但定义冲突时，工作空间条目发布失败，并展示冲突字段和平台条目。
3. 工作空间可以引用平台知识，并增加不改变平台原定义的补充说明。
4. 系统不能以“工作空间优先”静默解决定义、字段、路径或规则冲突。
5. 工作空间管理员可以在本工作空间停用某条平台公共知识。
6. 工作空间停用只生成工作空间级禁用记录，不修改平台条目，也不影响其他工作空间。
7. 停用和重新启用必须记录操作人、时间和原因。
8. 该工作空间的 RAG 召回和结构化上下文加载都必须排除已停用的平台知识。

## 8. 知识库页面需求

### 8.1 页面总体结构

知识库提供独立管理页面，至少包含：

- 知识列表。
- 知识详情。
- 新增和编辑页面。
- 校验结果。
- 发布确认。
- 历史版本和回滚。
- 平台知识的工作空间级停用管理。

页面需同时支持平台公共知识和工作空间知识，但根据当前用户角色限制可见操作。

### 8.2 列表展示

列表至少展示：

- 知识名称和知识类型。
- 平台公共或工作空间来源。
- 当前状态：草稿、校验失败、待发布、发布处理中、已发布、发布失败、已停用或已归档。
- 当前发布版本和草稿版本。
- 最后修改人、修改时间和发布时间。
- 当前工作空间对平台知识的启用状态。
- 结构化校验和向量化状态。

列表支持按名称、正文、别名、标签、物理表、字段和事件搜索，并支持按类型、来源和状态筛选。

### 8.3 逐条结构化编辑

- 四类知识均提供与类型匹配的编辑表单。
- 事件参数、JSON 字段和 SQL 示例中的表字段优先通过当前数据源 Schema 选择器选择。
- JSON 字段编辑器支持配置 JSON Path、目标类型和解析表达式。
- 业务知识支持零到多条 SQL 示例，也允许只有问题和 SQL 的条目。
- 普通知识文档支持在线 Markdown 编辑以及 Markdown、Word 文件上传。
- 上传和在线编辑都必须进入相同的草稿、校验和发布流程。
- 重新上传文件按“完整替换当前草稿文档”处理，不与上一文件正文自动合并；新文档中不存在的章节在新版本成功发布后不再进入当前知识和 RAG，发布前线上仍使用上一版本。
- 当前发布版本和有权查看的历史版本均可下载其原始上传文件；草稿源文件仅对具有编辑权限的用户开放。下载保留原文件名，不暴露服务器路径或内部 file ID。
- 重新上传和发布新版本不得删除历史版本源文件；历史版本仍可查看、下载和用于回滚审计。
- Data Skills 继续在原 Skills 页面编辑，不跳转到知识库，也不改变现有编辑逻辑。

### 8.4 详情和预览

详情页同时展示：

- 人工维护的结构化内容。
- 发布后供 RAG 使用的标准化文本预览。
- 切片数量、向量化状态和最近处理结果。
- 当前适用性校验结果及不适用原因。
- 当前发布版本、草稿差异和历史版本。
- 被哪些 AI 场景检索使用的审计摘要，不展示其他工作空间的敏感内容。

### 8.5 页面样式一致性

- 知识库页面必须与现有系统管理区保持统一的页面头部、工具栏、表格、抽屉、表单、按钮、状态标签和反馈样式。
- 复用现有 Element Plus Secondary 组件、主题变量、字号、间距、边框和图标体系，不为知识库单独建立一套视觉规范。
- 页面定位为高频管理工具，采用紧凑、可扫描的表格和无嵌套卡片布局，不使用营销式大标题、装饰性渐变或大面积卡片墙。
- 四类编辑器共享一致的字段标签、必填标识、校验提示、底部操作区和保存/校验/发布按钮顺序。
- 草稿、校验失败、待发布、发布中、已发布、停用和归档状态使用全平台一致的语义色和文案。
- 页面在常用桌面宽度下不得出现文字截断失控、按钮挤压、控件跳动或内容重叠；窄屏时工具栏和表单应按现有响应式规则换行。
- 继续遵守当前浅色主题默认策略，不新增主题切换入口或绕过现有主题开关。
- 所有新增页面文案必须进入现有国际化资源，至少覆盖简体中文、繁体中文、英文和韩文。

## 9. 草稿、校验与发布流程

### 9.1 生效方式

采用“保存草稿，校验通过后手动发布”。保存不直接影响线上 AI 调用链。

```text
新增或编辑
  -> 保存草稿
  -> 执行结构和业务校验
  -> 管理员单条发布
  -> 生成标准化检索文本和切片
  -> 生成向量
  -> 原子切换为新发布版本
```

### 9.2 第一期发布粒度

- 第一期只支持单条发布。
- 不支持批量发布、发布批次和批量回滚。
- 可以保留文件批量导入能力，但导入后形成的条目仍需逐条校验、逐条发布。
- 单条发布失败不能影响其他知识，也不能替换当前已发布版本。

### 9.3 校验要求

通用校验：

- 必填字段、稳定标识、作用域和格式正确。
- 同一作用域内唯一性和跨作用域冲突校验。
- 当前用户具有编辑和发布权限。
- 引用的知识条目存在且处于允许引用的状态。

结构化知识校验：

- 表和字段存在于当前工作空间绑定的数据源。
- JSON 宿主字段、JSON Path、数据类型和解析表达式有效。
- 事件名称和参数关系符合工作空间跟踪规范。
- SQL 示例符合对应数据库方言，只读且通过字段权限、行权限和 Data Skills 规则检查。
- 当前调用选中的 Data Skills 中，涉及权限裁剪的 Schema、表、字段、事件和 JSON Path 可以被确定性解析；无法解析其必需对象时，该 Skill 不得进入运行上下文。

平台公共结构化知识发布时允许在平台层保存包含具体物理对象的定义；实际被某工作空间使用前，还必须在该工作空间当前数据源上执行适用性校验。

### 9.4 原子发布与失败处理

- 结构化记录、检索文本、切片和向量准备完成后才能切换发布版本。
- 任一步失败时保留上一已发布版本继续服务。
- 页面展示失败阶段、错误原因和可操作的修复建议。
- 不允许出现部分新结构化配置已生效、但向量或检索内容仍是旧版本的状态。

### 9.5 历史版本与回滚

- 每次发布形成独立版本，记录发布人、发布时间和变更摘要。
- 支持查看任意历史版本及与当前草稿/发布版本的差异。
- 支持单条回滚；回滚也需要校验并形成新的发布版本。
- 条目已有未发布草稿时拒绝回滚并显示“该知识已有未发布草稿，请先处理当前草稿后再回滚。”，不得覆盖或静默删除当前草稿。
- 删除默认采用停用或归档，保留历史问答引用所需的版本信息。

### 9.6 并发与发布恢复

- 第一期同一知识条目只允许一个活动草稿；保存必须携带读取时的草稿版本和 revision。
- 两个用户同时保存时只能一个成功，失败方保留本地编辑内容并看到“该知识已被其他用户更新，请刷新后重新编辑。”，系统不得自动覆盖或静默合并。
- 发布期间不允许保存、重新校验、删除、归档或回滚，并显示“该知识正在发布中，请稍后再试。”。
- 发布任务必须具有数据库权威状态、心跳和截止时间；API 入队失败、Worker 崩溃、任务过期或重复投递后都能自动恢复或失败收敛，不能永久停留在发布中。
- 发布成功后清理活动草稿和发布中指针；发布失败后保留上一发布版本和失败草稿，允许修改后重试。
- 新发布链路只能使用注册任务队列，不允许静默降级到 API 进程内后台任务。
- Worker 处理长文档时必须在每个向量批次确认发布作业仍有效；任务已超时、终止或失去版本所有权后停止后续外部调用和写入。
- Redis 任务早于 API 更新排队状态开始执行时，数据库条件更新仍能正确认领和收敛，不能把已运行或已成功的作业回退为失败。
- Redis 超时或连接中断后无法证明任务是否已入队时，发布保持“任务确认中”并由系统对账，不得立即显示失败或重复创建任务；只有确定性拒绝或确认期限耗尽后才能失败收敛。

## 10. RAG 检索需求

### 10.1 检索范围

每次检索必须先确定：

- 当前用户。
- 当前工作空间。
- 当前工作空间绑定的数据源。
- 用户的数据源、表、字段和行权限。
- 当前工作空间停用的平台知识。

可召回范围为：

```text
当前工作空间未停用且适用于当前数据源的平台已发布知识
+ 当前工作空间已发布知识
```

草稿、校验失败、发布失败、已停用或已归档知识不得进入线上检索。

### 10.2 全部场景默认可用

第一期不提供逐条适用场景配置。所有已发布且通过当前上下文校验的知识默认用于全部场景：

1. Smart Q&A 的问题理解、SQL 生成、SQL 修复和结果回答。
2. AI 看板的 AI SQL 生成。
3. AI 看板中的 AI 问答和看板报告解读。
4. 综合分析助手的分析规划、SQL 生成与修复、结果解释和最终总结。

不同场景共享统一检索服务，但可以根据任务类型构建不同的检索问题和上下文预算。

### 10.3 检索与结构化加载

统一调用流程：

```text
用户问题或分析任务
  -> 确认工作空间、当前数据源和权限
  -> 加载授权后的 Schema
  -> 按当前项目逻辑选择并裁剪 Data Skills
  -> 加载已发布的结构化事件和 JSON 映射
  -> RAG 检索相关业务知识与文档切片
  -> 合并统一语义上下文
  -> 生成 SQL、分析计划或解释
  -> 执行权限、安全、Schema 和 Data Skills 校验
  -> 返回结果及知识引用
```

同一次请求应固定使用同一个知识版本快照，不能在计划、SQL 修复和最终总结阶段分别召回不同版本。

### 10.4 信息权威顺序

发生冲突时必须遵循以下顺序：

```text
权限与当前工作空间/数据源上下文
  > 用户明确选择的字段、指标、筛选和时间配置
  > 授权后的物理 Schema
  > 已发布的结构化事件和 JSON 映射
  > 当前请求选中且通过权限裁剪的 Data Skills
  > 业务知识和普通知识文档
  > 模型自身常识
```

知识文档和 SQL 示例不能绕过权限、替换当前数据源、修改结构化字段映射或覆盖 Data Skills 口径。

### 10.5 引用与可追踪性

AI 结果需保留以下内部引用信息：

- 知识条目 ID、类型和作用域。
- 发布版本和切片 ID。
- 检索得分和命中时间。
- 当前工作空间和数据源上下文哈希。

面向用户的回答在适合的场景展示知识名称、章节和版本，不暴露服务器文件路径、内部租户信息或其他工作空间内容。

## 11. 各 AI 场景接入要求

### 11.1 Smart Q&A

- 在生成 SQL 前加载统一语义上下文。
- 事件参数、JSON 字段和当前请求选中的 Data Skills 同时参与 SQL 生成及校验。
- 业务知识中的已验证 SQL 示例可以作为参考，但不能绕过当前 Schema 和权限校验直接执行。
- 回答中可引用普通文档和业务知识解释指标或业务背景。

### 11.2 AI 看板 SQL 生成

- 根据看板问题、选定字段、指标、筛选和图表配置检索知识。
- 生成的 SQL 必须使用当前工作空间数据源上有效的结构化映射。
- 知识只能补充定义和示例，不能替换用户已明确选择的图表字段或配置。

### 11.3 AI 看板问答与报告解读

- 只解释当前用户有权访问且当前可见的看板数据。
- 可以使用业务术语、背景说明和当前请求选中的 Data Skills 解释数据。
- 不得根据知识库内容重算或篡改图表中的事实数据。
- 知识与可见数据冲突时，以可见数据为事实，并明确提示知识不足或不适用。

### 11.4 综合分析助手

- 知识库参与问题拆解、分析计划、SQL 生成与修复、结果解释和最终总结。
- 同一轮分析复用固定知识版本快照。
- SQL 结果中的事实数值优先于知识文档中的描述或历史示例。
- 知识库不能决定未经授权的数据源、表、字段或跨工作空间访问。

## 12. 权限要求

### 12.1 平台管理员

- 管理所有类型的平台公共知识。
- 查看平台知识的版本、发布状态和各工作空间适用性摘要。
- 不能借助知识管理页面读取工作空间业务数据。
- 平台 Skills 继续通过原 Skills 管理入口维护，不进入知识库发布状态机。

### 12.2 工作空间管理员

- 管理当前工作空间的所有知识类型。
- 查看当前工作空间可用的平台公共知识。
- 在当前工作空间停用或重新启用平台公共知识。
- 不能修改平台公共知识正文和结构化配置。
- 工作空间和个人 Skills 继续遵循原 Skills 页面及既有权限规则。

### 12.3 普通成员

- 可查看其权限允许展示的已发布知识。
- 默认不能新增、编辑、发布、回滚或停用知识。
- AI 调用仍需服从其个人数据源、表、字段和行权限。

### 12.4 Schema、事件和对象引用权限

- 在现有权限管理页面增加 Schema、事件和事件属性权限配置，不建立第二套授权页面。
- Schema 权限必须使用完整 Catalog/Schema 标识；不同 Schema 中的同名表不能共享授权，多 Schema 下的歧义表名不得自动选择默认 Schema。
- 事件权限与当前工作空间 tracking 规范绑定。禁止事件在 SQL 执行前转换为可验证的事件行约束；无法安全注入或无法证明 SQL 只读取允许事件时阻断执行。
- 事件属性同时继承事件、来源表、字段和 JSON Path 权限；事件专属属性只有在 SQL 明确且可验证地限定到允许事件时才能使用。
- 知识版本、切片和当前调用选中的 Skills 必须具有结构化对象引用索引。任一引用无权、歧义、失效或无法解析时，该内容不得进入 Prompt。
- 权限、用户角色、工作空间成员关系、tracking、数据源绑定或 Schema 变化后，权限版本必须立即变化，使旧缓存不能继续扩大访问范围。
- 权限版本必须根据数据库中的 epoch、角色、成员状态、数据源绑定和 Schema 一致性快照生成，不能先读取旧权限缓存再计算缓存键。
- 召回前过滤和 SQL 执行后校验必须使用同一服务端权限快照，不能依赖前端隐藏或模型自行遵守。

## 13. 非功能与安全要求

- 检索查询必须在数据库层包含工作空间、发布版本、状态和禁用过滤，不能全局召回后再做应用层隔离。
- 知识内容属于非可信输入，不能通过文档内容覆盖系统指令、权限或 SQL 安全规则。
- 日志不记录完整敏感正文、完整 SQL 结果或数据库凭据。
- 记录检索耗时、召回条目、版本、得分、失败类型和模型信息，支持问题追踪。
- 知识检索故障时不得静默忽略。非强制参考知识故障可以降级使用结构化上下文，但必须记录并向调用链返回告警。
- 向量生成失败不能影响上一已发布版本继续提供服务。
- 工作空间和数据源重新绑定、Schema 变化后，应触发相关结构化知识适用性重新校验。
- 物理对象目录必须持久化完整 Catalog/Schema/表/字段身份。不同 Schema 的同名表不得共用元数据、适用性结果或权限；无法确定 Schema 时失败关闭。
- 权限规则、系统角色、用户状态、工作空间成员、数据源访问、项目角色、tracking、数据源绑定或物理 Schema 任一变化都必须使权限版本变化；SQL 执行前发现权限版本变化时重新校验或阻断，不能继续使用旧权限快照。
- API 与发布 Worker 必须共享同一源文件存储；探针 generation 由数据库单例权威管理，多个 API 启动不能各自轮换。启动检查必须由 API 写入探针文件、所有活动发布 Worker 实际读取并校验后回执，仅比较路径配置或进程自读不算验证。无法确认所有活动发布 Worker 可读取上传文件时不得接受文档发布。
- 旧写接口开放期间，历史数据回填必须记录来源指纹并持续增量追平；正式切换前通过数据库屏障等待在途旧写完成、暂时拒绝新旧写，并完成最终追平。旧解析 Worker 和进程内后台任务的每次正文/状态回写同样受屏障约束，不能在最终扫描后迟到修改旧记录。
- 数据库迁移阶段是新旧写路由的最高权威：`LEGACY_OPEN` 只开放旧写，`CUTOVER_BARRIER` 暂停新旧写，`V2_ACTIVE` 永久关闭旧写。关闭环境功能开关只能让 V2 管理进入维护态，不能重新开放旧接口。

## 14. 第一期范围

第一期必须交付：

1. 四类知识的统一列表、详情和逐条结构化编辑，Skills 保留独立管理入口。
2. 平台公共知识与工作空间知识两级管理。
3. 草稿、校验、单条发布、历史版本和单条回滚。
4. 工作空间级停用和重新启用平台公共知识。
5. 文档切片、向量化、权限过滤检索和引用追踪。
6. 结构化知识发布后自动生成对应的 RAG 检索内容。
7. Smart Q&A、AI 看板 SQL 生成、AI 看板问答/报告解读和综合分析助手接入统一知识上下文。
8. 平台结构化知识中的物理映射、SQL 示例，以及当前请求选中的 Data Skills，在使用时动态校验当前工作空间绑定的数据源和用户权限。

## 15. 第一期非目标

- 不支持批量发布、发布批次和批量回滚。
- 不支持逐条配置 AI 适用场景，第一期默认全部场景可用。
- 不允许工作空间覆盖平台公共知识。
- 不使用纯向量文档替代事件参数、JSON 映射或 Data Skills 的现有结构化规则。
- 不把 Data Skills 迁移、复制或改造成知识库知识类型。
- 不因知识缺失而自动猜测表、字段、JSON Path、指标公式或数据源。
- 不引入跨工作空间共享或一个工作空间默认绑定多个数据源的行为。
- 不在第一期引入独立向量数据库；优先复用现有 PostgreSQL、pgvector、Embedding 模型和本地任务队列。

## 16. 验收标准

### 16.1 管理页面

- 平台管理员和工作空间管理员能在同一知识库产品中查看权限范围内的四类知识。
- 四类知识均可逐条新增、编辑、查看、校验和发布。
- Skills 保留原页面、三级作用域、显式选择和自动匹配能力，知识库改造不改变其管理和选择语义。
- 现有 Skills 的对象安全投影可幂等补建并随 Skill 内容变化失效重建；投影缺失或过期时不会把 Skill 内容加入 Prompt。
- 业务知识可以没有术语定义，仅保存问题和 SQL 示例。
- 草稿修改不会影响当前线上版本。
- 重新上传文档后，缺失章节只在新版本发布成功后从当前知识中移除，旧版本正文和源文件仍可按权限查看和下载。
- 发布失败后仍使用上一已发布版本，并能看到明确失败原因。
- 可以查看历史版本并完成单条回滚。
- 已有活动草稿时回滚被明确拒绝，当前草稿内容保持不变。
- 知识库列表、详情、编辑、校验、发布和版本页面与现有系统管理区的组件、间距、颜色、交互反馈和响应式行为保持一致。

### 16.2 作用域与冲突

- 任何工作空间都不能检索到其他工作空间的知识。
- 工作空间不能修改或覆盖平台公共知识。
- 同名或同稳定标识冲突会阻止发布，不会静默选取其中一条。
- 工作空间停用平台知识后，该知识不再进入该工作空间的 RAG 和结构化上下文，但其他工作空间不受影响。

### 16.3 平台结构化知识

- 同一平台公共映射在工作空间 A 使用时校验 A 的数据源，在工作空间 B 使用时校验 B 的数据源。
- 平台知识和平台 Skills 只保存物理对象声明，使用时按当前工作空间的数据源和最新 Schema 指纹生成独立解析结果；不得固化平台发布人的数据源上下文或沿用旧 Schema 解析结果。
- 平台公共 SQL 示例和当前请求选中的、引用具体物理对象的 Data Skills 都遵循相同的动态数据源与权限校验规则。
- 数据源缺少所需表、字段或 JSON Path 时，该映射不会参与 SQL 生成，并返回明确原因。
- 系统不会用相似字段、默认字段或其他数据源配置代替无效映射。
- 两个 Schema 中存在同名表时，各自具有独立稳定身份；无法确定 Catalog/Schema 的平台映射不会进入当前工作空间上下文。

### 16.4 AI 调用链

- 四类 AI 场景均能使用相同的已发布知识范围和权限规则。
- SQL 生成能使用已发布的事件、JSON 映射、已验证 SQL 示例和当前请求选中的 Data Skills。
- SQL 仍通过数据源权限、Schema、只读和 Data Skills 校验。
- 综合分析助手在单次任务内使用固定知识版本快照。
- AI 回答能够追踪到实际使用的知识条目和发布版本。

### 16.5 可靠性

- 新版本解析、切片或向量化失败时，上一发布版本持续可用。
- Schema 或工作空间数据源绑定变化后，相关映射会被重新校验。
- 检索异常有结构化日志和告警，不会被伪装成“没有配置”。
- 并发保存不会覆盖其他用户内容；确定性入队拒绝、入队结果不确定、Worker 崩溃和任务过期都能收敛，且响应丢失不会把已入队任务误标为失败。
- 在线回填与旧接口并发修改时不会覆盖最新正文或源文件；切换屏障覆盖旧接口、旧 Worker 和后台任务的所有写回，屏障前后的边界可验证且无遗漏，屏障期间显示“知识库升级中，请稍后重试。”。
- 数据库已经 `V2_ACTIVE` 时，无论环境开关为何值，旧写都不能恢复；滚动部署中存在不识别屏障的旧实例时禁止切换。
- 权限、系统角色、用户状态、成员、数据源访问/项目角色、tracking、绑定或 Schema 变化后，旧权限缓存不会继续用于新的 SQL 执行。
- 跨 Schema 同名表、禁止事件和事件专属属性都通过生成后 SQL 权限校验。
- 多 API 并发启动只能使用同一个数据库权威探针 generation；任一活动 Worker 的读取回执失败或过期时，文档发布在处理前失败并显示中文安全提示。

## 17. 后续迭代方向

以下能力不属于第一期，但数据模型和接口应保留扩展空间：

- 批量选择、批量校验、原子批量发布和批次回滚。
- 按知识条目配置适用的 AI 场景。
- 发布审批流和多人协作。
- 检索效果评测集、召回调试和命中解释面板。
- 多数据源工作空间下的显式活动数据源范围。
- 大规模知识量下的独立向量检索基础设施。
