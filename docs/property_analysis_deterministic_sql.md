# 属性分析确定性 SQL 编译

属性分析现在根据页面结构化配置与工作空间授权元数据直接编译 SQL。生成成功、配置失败、SQL 校验失败均不调用 LLM，也不会进入模型修复循环。接口仍为 `/dashboard/ai_sql_generate`。

## 工作空间表级强制筛选

2026-09-29 修正：直接编译链路此前没有消费工作空间 SQL 约束中的固定表筛选。现在通过既有表元数据 `tables[].extra_properties.required_filters` 保存可执行条件，由手动分析的共用配置处理按当前租户、数据源和引用表读取，再与页面条件用 AND 合并。页面 OR 条件保留为独立括号组，不能绕过强制条件；未配置的表不自动套用其他表或其他工作空间的条件。

结构示例（字段和值由对应工作空间配置）：

```json
{"required_filters":{"logic":"and","rules":[{"field":"scope_id","operator":"eq","value":123}]}}
```

本次将当前工作空间已有文字规则中的产品过滤结构化到原来的三个表记录，未新增接口、前端入口或数据库列。任意自然语言 `sql_rules` 不由正则猜测转换；这些文字仍保留为共享语义上下文，结构化条件也会出现在表的语义说明中。

当前共用合并逻辑用于单源表分析（可包含多个 CTE、人群分支和指标）。跨表配置若无法明确逐表作用域，会报错，不把一张表的条件错误施加给其他表。此处是生成阶段约束，不是新的行权限系统；已有保存/手写 SQL 不会被批量改写，需要重新生成才能带入最新条件。

## 配置与结果

- 支持同一授权源表的 COUNT、COUNT DISTINCT、SUM、AVG、MIN、MAX，及各自独立的指标筛选。
- 支持全局嵌套 AND/OR、属性分组、时间属性分组、独立人群分支。重叠人群独立统计，空人群保留；名称必须唯一。
- 后端按请求中的时间字段、参数类型和粒度编译；周从周一开始，周/月去重直接对明细计算。此次不调整前端可选项和保存恢复逻辑。
- 日粒度的 date/yyyymmdd_number/yyyymmdd_text 使用连续日期骨架；仅计数缺失补零，其他聚合保留 NULL。
- 后端周/月和 timestamp 当前不补齐空时间桶，生成建议会说明该限制。
- 后端 `none` 输入不生成日期输出列；本次不在既有界面提供对应入口或修改列映射。
- JSON 子属性以服务端映射为准。时间戳秒/毫秒需声明 encoding；无时区时间字段需声明与业务时区一致的 timezone。主时间与时间属性分组遵循同一业务时区。
- `contains` 为字面包含；百分号和下划线不会扩大为通配符。布尔筛选接受布尔值或明确的 true/false 文本。

后端对收到的跨表关联、公式指标、近似计算、未知字段、非法类型组合、失效 JSON 映射、残缺条件和非法配置别名明确报错。前端原有校验、条件序列化及聚合选择行为保持不变。
