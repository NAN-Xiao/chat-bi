# 路径分析：固定 SQL 模板与配置编译器

日期：2026-09-29。代码已实现；下文区分自动化、原生数据库和浏览器的实际覆盖。

## 实现结果

路径模型通过工作空间授权元数据构建不可变计划，由固定 CTE 编译 SQL。原页面仍调用 `/api/v1/dashboard/ai_sql_generate`，后端对 path 分流；通用 `/api/v1/dashboard/sql_compile` 和新增 `/api/v1/dashboard/path/sql_compile` 使用同一服务。服务直调也采用相同分流。

上下文读取、生成、校验失败、重试和修复禁入均不调用 LLM、Embedding 或 Data Skill 检索。编译预算为 60 秒，沿用取消及同步元数据读取收尾机制。原有响应、四个结果列和桑基图类型保持不变。

没有修改前端文件。任务前记录了 805 个前端文件的内容哈希，实施后的复核一致；原工作树此前已有的前端改动完整保留。

## 语义和边界

- 主体来自当前工作空间明确的默认主体字段，不能按 uid 等字段名猜测。
- 参与事件 1–30 个且不得重复；每事件最多一个拆分属性；起始事件来自参与事件；会话间隔为 1–86400 整数秒。
- 在指定日期、权限、强制筛选、用户筛选后的参与事件流中构造会话。间隔严格大于阈值才断开；不按自然日强行切断。
- 会话首节点必须是初始事件，中途出现初始事件不另开一条路径。最多 10 个节点、9 条边；path_value 是对应位置相邻边的会话数，不是去重主体数。
- 事件时间和已配置的 event_sequence/event_id 排序字段共同确定顺序；真实排序键为空或重复时明确报错，不按事件名猜顺序、不静默去重。
- 原页面隐藏独立分组，因此非空 groups 明确拒绝；不会把残留分组悄悄加入会话键。
- 同一数值的不同 decimal scale 不形成不同节点。NULL、空字符串和文本 `null` 保持不同；字符串中的引号、反斜线、控制字符和 Unicode 有可逆编码。
- 日期仍用原有 dashboard 参数。参数槽在执行前限制为相应类型的日期常量，不能夹带负号或函数表达式改变实际窗口。
- SQL 内部排序列只供执行校验使用，不进入图表业务字段或成功数据缓存；超出结果行数上限明确失败，不返回缺边的桑基图。
- 旧保存 SQL 不批量改写；重新生成才获得新编译及执行契约。手工 SQL 的既有读权限验证保持有效。

## 验证中修正的问题

1. MySQL 兼容方言将错误结果分支的未限定字段判为同层别名引用：明确使用 `path_guard.__path_order_error`，四方言安全校验回归通过。
2. 旧路径校验错误拒绝页面提供的物理/公共属性：统一交由授权字段解析器核验，保留事件参数归属检查。
3. JSON 布尔属性被错误视为文本，以及未知/容器类型被当成字符串：保留声明类型，非法类型明确失败。
4. MySQL 时间除法会损失微秒，数值 epoch 的固定 scale 也会舍入更细精度：整数提升防溢出，decimal 保留原始精度，毫秒采用精确数值缩放；相关原生边界用例先失败再修正。
5. PostgreSQL numeric 的 `1`、`1.0`、`1.00` 文本形式会错误拆成三个节点：只规范小数文本的末尾零，不转为浮点。
6. 当前 MySQL 兼容数据源不提供 JSON_QUOTE，且 JSON null 的转码行为不同：使用通用字符串函数编码，先检查 JSON_TYPE 再转换标量类型。原生测试区分 JSON null、字符串 `null`、空字符串、数值零，并按目标节点验证没有交换标签。

- 现有页面首次生成新的 SQL 后可能清空“分类”。测试使用原有控件选中“目标步骤”后完成桑基图展示和保存；此为已有前端行为，本任务没有修改或以后台伪字段掩盖。
- 画布图表菜单只有预览、编辑 SQL、共享和删除；未找到复制入口，因此没有声称完成浏览器复制测试。
- 已触发“导出图表原始表格”，但内置浏览器在 60 秒内没有提供下载事件，也未确认文件交付，不能记为导出成功。
- 断连/超时及同步元数据收尾由自动化测试验证；没有把未完成的浏览器快速取消尝试记为通过。
- 浏览器没有覆盖全部 AND/OR、为空/非空组合；这些组合的配置解析和结果语义由自动化测试补充。

## 能力限制与实施取舍

- PostgreSQL JSON 布尔类型及 false 筛选已验证。MySQL 系 JSON 布尔属性目前明确拒绝，不静默当文本或转为错误的 0/1；普通物理布尔字段按其声明类型处理。
- StarRocks、Doris 有基础编译/解析检查，没有本轮原生执行环境，不能视为完整实测。
- 执行层复用现有连接时区控制参数，保留 interval 既有协议格式；没有为了改名字重构整个连接 API。
- 用户显式替换为普通手写只读 SQL 的入口继续受原有权限和 SQL 安全校验约束；不会把没有编译契约的普通 SQL 宣称为已验证编译结果。
- 依赖此工作树中此前已有、尚未提交的编译上下文、属性解析和间隔执行模块；未整体暂存或提交这些已有修改。
