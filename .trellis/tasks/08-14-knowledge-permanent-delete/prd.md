# 知识库永久删除与文件清理

## Goal

为知识库补齐“归档可恢复、永久删除不可恢复”的完整生命周期，避免已归档知识库、历史版本、检索切片和源文件无限累积，同时保证仍被其他版本引用的源文件不会误删。

## Background

- 当前 `DELETE /knowledge-base/{id}` 对从未发布的知识库执行数据库删除，对已发布知识库只归档；已归档知识库只能恢复，没有永久删除入口。
- 已发布知识库归档后仍保留全部版本、发布任务、检索投影和源文件，因此会持续占用数据库与文件存储。
- 草稿替换源文件时会更新当前版本的 `file_id`，但旧文件没有统一的无引用回收机制；从未发布知识库删除时也只删除数据库记录。
- 检索切片、适用性、来源引用和语义对象引用已有版本级级联外键；发布任务对版本使用 `RESTRICT`，永久删除必须先清理发布任务。

## Requirements

- 保留现有归档与恢复行为；普通列表仍只提供“归档”，不把不可恢复操作放到当前知识列表。
- 已归档列表和已归档详情仅对 `can_manage` 管理员显示“永久删除”。
- 永久删除前要求输入完整知识库名称确认，并明确提示版本、切片和源文件不可恢复。
- 后端提供独立的 V2 永久删除接口；只允许删除 `archived=true` 的知识库，未归档请求返回明确冲突错误。
- 永久删除继续使用现有平台/工作空间管理权限边界，不允许普通只读用户或跨工作空间用户删除。
- 永久删除必须在同一数据库事务内删除发布任务、所有版本和知识库主记录；依赖版本或知识库的切片、适用性、来源引用、语义对象投影和工作空间覆盖配置由现有级联约束清理。
- 删除数据库记录前收集该知识库所有版本及旧记录上的源文件 ID；数据库提交成功后，仅删除在数据库中已无任何知识库或版本引用的物理文件。
- 草稿源文件替换成功后，回收被替换且已无引用的旧物理文件；解析失败、并发冲突或数据库回滚时保留原文件并删除暂存文件。
- 从未发布知识库通过现有删除入口硬删时，同样回收无引用源文件。
- 物理文件不存在视为已经清理；实际文件删除失败必须记录并在永久删除响应中显式返回失败数量，不能把数据库删除伪装成整体失败。
- 不新增数据迁移；沿用当前外键关系并在服务层按依赖顺序删除。

## Acceptance Criteria

- [ ] 当前知识列表仍显示“归档”，已归档列表同时显示“恢复”和“永久删除”。
- [ ] 已归档详情提供相同的恢复和永久删除操作，普通只读用户看不到永久删除入口。
- [ ] 永久删除必须输入完整知识库名称；输入不匹配或取消时不调用接口。
- [ ] 未归档知识库调用永久删除接口返回明确的 409 冲突，归档知识库在有管理权限时可成功删除。
- [ ] 永久删除后知识库、版本、发布任务、切片、适用性、来源引用、语义对象引用和工作空间覆盖配置均不可再查询。
- [ ] 同一文件仍被其他版本引用时不会删除；最后一个引用消失后物理文件被清理。
- [ ] 替换草稿源文件会清理无引用旧文件，不影响回滚版本共享的源文件。
- [ ] 删除从未发布的带源文件知识库会同时清理无引用物理文件。
- [ ] 后端状态机、接口和文件引用测试通过；前端聚焦测试、构建及已归档页面桌面/移动端浏览器验证通过。

## Out Of Scope

- 按 30/90 天保留期自动清理归档知识库。
- 批量永久删除、回收站定时任务或管理员可配置保留期。
- 删除或裁剪仍在使用的非归档知识库历史发布版本。
- 改变旧版知识库管理模式的删除协议。
