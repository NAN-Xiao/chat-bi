# 实施记录

## 数据流

1. 新建普通文档时可选源文件；系统先创建知识库与草稿，再调用 `/knowledge-base/{id}/draft/file` 上传。
2. 已有普通文档草稿可在编辑抽屉中替换源文件。
3. 列表操作列在“编辑”后提供行级上传和下载；上传使用该行明确草稿 revision，没有草稿时基于明确发布版本创建草稿。
4. 行级下载依次检查明确的草稿版本和当前发布版本，不猜测其他版本；无源文件时明确提示。
5. 后端校验扩展名和 50 MB 限制，解析 Markdown、Word 或 Excel。
6. Excel 以非空工作表为知识块边界，保留单元格文本与公式；空工作表跳过。
7. 解析结果替换草稿 blocks，后续沿用校验、发布、向量切片流程。

## 关键约束

- 上传只更新草稿，不覆盖已发布版本。
- `.xlsx` 使用只读工作簿模式，并检查压缩包解压总量和异常压缩比。
- V2 与旧版扩展名选择器保持一致。
- 行级操作使用逐行 busy 状态；Blob 下载统一清理临时节点并延迟撤销 Object URL。

## 新建上传空知识块问题

- 根因：新建弹窗使用 `destroy-on-close`。创建成功后先关闭弹窗，再异步读取
  `createSourceFile.value`，组件销毁已清空该引用，所选文件因此没有进入上传接口，页面只保留默认空草稿。
- 修复：关闭弹窗前把 `File` 保存到局部变量；打开新知识库后，若需要创建草稿，先等待草稿创建并刷新版本状态，再调用源文件上传。
- 上传仍沿用统一请求层的错误展示；只有上传接口成功后才显示成功消息，不增加静默兜底。
- 浏览器回归发现纯 SaaS 平台管理员打开平台公共知识时会在上传前触发工作空间数据源适用性检查，403 中断后续流程。平台管理员没有工作空间数据源上下文，因此在适用性检查入口显式跳过；工作空间用户的检查行为保持不变。
