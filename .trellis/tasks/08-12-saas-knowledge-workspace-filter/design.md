# 技术设计

## 边界

知识库记录已通过 `knowledge_base.tenant_id` 归属工作空间。新增的 `tenant_id` 仅作为平台管理员知识库管理查询和创建上下文；非平台管理员始终由认证后的当前工作空间上下文确定目标租户。

权限矩阵：

| 角色 | 平台知识库 | 当前工作空间知识库 | 其他工作空间知识库 |
| --- | --- | --- | --- |
| SaaS 平台管理员 | 查看、编辑 | 查看、编辑 | 选择后查看、编辑 |
| 工作空间管理员 | 只读 | 查看、编辑 | 不可见 |
| 普通成员 | 只读 | 只读 | 不可见 |

## 后端

- `GET /knowledge-base/list` 增加可选 `tenant_id`。
- 非平台管理员传入任何工作空间 ID 时都必须与当前工作空间一致，否则返回显式权限错误。
- 平台管理员传入具体工作空间 ID 时按该 ID 过滤；平台公共知识固定查询默认平台租户。
- 详情、版本和发布链路使用平台管理员的全局知识库解析与管理权限，使 SaaS 后台选择的工作空间记录可以继续操作。
- `POST /knowledge-base/create` 增加可选 `tenant_id`，平台管理员创建工作空间知识时必须明确目标工作空间；平台公共知识固定使用默认平台租户。
- LEGACY 列表/保存入口也接收目标工作空间上下文，避免能力模式切换后筛选失效。

## 前端

- V2 与 LEGACY 页面都显示范围下拉框，选项为“平台知识库”和“工作空间知识库”。
- 选择工作空间知识库时显示工作空间下拉框。平台管理员加载全部工作空间并可切换；非平台管理员显示当前工作空间且控件禁用。
- 范围或工作空间切换时清空当前详情并重新加载列表；平台管理员创建工作空间知识时必须有明确目标工作空间。
- 新建、编辑、归档、发布等写入口以接口返回的 `can_manage` 和用户角色共同控制；普通成员不渲染写入口。
- 知识库管理路由属于工作空间业务页面，但不是管理员专属页面，普通成员可进入只读查看。
