# 修复工作空间知识库创建缺少工作空间选择

## Goal

创建“工作空间知识”时，让操作者明确选择知识库所属工作空间，并保证创建、列表、详情和后续编辑使用同一套工作空间归属与权限规则，避免知识被写入隐含或错误的工作空间。

## Background

- 当前 V2 创建弹窗只有名称、描述和知识范围；选择“工作空间知识”后没有工作空间选择控件。
- 当前前端创建请求不包含工作空间 ID。
- 当前后端创建接口从登录上下文推导工作空间，平台管理员没有当前工作空间时无法创建工作空间知识。
- 当前权限服务明确禁止全局平台管理员读取或管理工作空间知识；如果只给创建接口增加工作空间 ID，平台管理员创建后仍无法在列表中看到或继续编辑。
- 已有 `/system/tenant/list` 接口会向全局平台管理员返回有效工作空间，向普通用户返回其加入的工作空间，可复用为选择数据源。

## Requirements

- R1：当知识范围为“工作空间知识”时，创建弹窗必须显示“所属工作空间”必选项。
- R2：全局平台管理员可以从有效工作空间列表中选择目标工作空间；不得默认隐含选择第一个工作空间。
- R3：工作空间管理员只能在当前工作空间创建知识，所属工作空间显示当前值且不可切换。
- R4：切换为“平台公共知识”时不显示也不提交工作空间 ID；平台公共知识仍归平台默认租户。
- R5：创建请求对工作空间知识携带明确的 `tenant_id`，后端验证目标工作空间存在、有效，并验证操作者有权在该工作空间创建。
- R6：全局平台管理员对其创建目标范围内的工作空间知识具备列表、查看、编辑和归档权限；工作空间管理员和成员仍只能访问当前工作空间，不能跨工作空间读取或管理。
- R7：未选择工作空间、工作空间列表加载失败、目标工作空间不存在/已停用或操作者无权访问时，必须显示明确错误并阻止创建，不得静默回退到当前或第一个工作空间。
- R8：保留现有工具栏未提交修改，不进行无关布局重构。

## Acceptance Criteria

- [ ] AC1：平台管理员打开创建弹窗、选择“工作空间知识”后可见工作空间下拉框，未选择时“创建并编辑”不可成功提交。
- [ ] AC2：平台管理员选择工作空间 A 后，请求携带 A 的 ID，后端记录的 `tenant_id` 为 A，创建后可在当前管理页打开并继续编辑该知识库。
- [ ] AC3：工作空间管理员打开创建弹窗时只能看到当前工作空间，不能选择其他工作空间，创建记录归属当前工作空间。
- [ ] AC4：选择“平台公共知识”时工作空间控件隐藏，请求不携带工作空间 ID，原有平台知识创建行为不变。
- [ ] AC5：伪造、无效或已停用的工作空间 ID 被后端拒绝；普通工作空间用户不能借请求参数跨空间创建、读取或管理知识。
- [ ] AC6：新增前端和后端回归测试覆盖范围切换、必选校验、请求字段、平台管理员跨工作空间管理和普通用户隔离。
- [ ] AC7：前端构建、相关后端测试通过，并通过实际页面在桌面和移动视口验证弹窗、选择、创建链路及无水平溢出。

## Out Of Scope

- 不改变一个工作空间最多绑定一个数据源的产品模型。
- 不增加知识库跨多个工作空间共享或多对多绑定。
- 不改变平台公共知识的工作空间启停机制。
- 不修改旧版知识库创建流程，除非验证发现 V2 路由仍会回落且必须保持请求兼容。

## Risks And Constraints

- 权限改动必须仅放宽全局平台管理员对显式目标工作空间知识的管理能力，不能放宽普通用户的跨工作空间访问。
- 列表接口需要让平台管理员管理工作空间知识，同时维持其他角色的当前工作空间过滤。
- 当前组件已有用户未提交的工具栏布局修改，实施时必须在其基础上做局部修改。
