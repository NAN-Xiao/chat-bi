# 接入 Trellis Codex 工作流

## Goal

为 chat-bi_ver 接入 Trellis：保留现有 AGENTS.md 约束，启用 Codex hooks 与工作流 skills，补充项目专属前后端质量门禁和运行验证规范，并完成有效性检查。

## Requirements

- Preserve the existing repository-level `AGENTS.md` instructions and append the guarded Trellis/Codex workflow block without overwriting project-specific rules.
- Initialize Trellis for the Codex platform in this repository, including `.trellis/`, `.agents/skills/`, `.codex/hooks.json`, and `.codex/config.toml`.
- Keep Codex project instructions sourced from `AGENTS.md` and document the user-level hook prerequisites that cannot be proven by repository files.
- Record the repository's actual backend and frontend quality gates in `.trellis/spec/` so future sessions can discover them before implementation.
- Do not alter the user's pre-existing knowledge-base changes or unrelated working-tree files.

## Acceptance Criteria

- [x] `trellis platforms` reports Codex as configured.
- [x] `.trellis/` contains the workflow, task scripts, specs, and workspace/task directories generated by Trellis.
- [x] `.agents/skills/` contains `trellis-start`, `trellis-before-dev`, `trellis-check`, and `trellis-update-spec`.
- [x] `.codex/hooks.json` calls `inject-workflow-state.py`, and `.codex/config.toml` preserves `AGENTS.md` as the project instruction source.
- [x] `AGENTS.md` contains the guarded Trellis/Codex workflow block, and the block validation script passes.
- [x] Project-specific backend and frontend specs document the real commands and runtime checks used by this repository.
- [x] `task.py validate` passes for the active task, and the effectiveness checker reports no repository-file failures.

## Notes

- Keep `prd.md` focused on requirements, constraints, and acceptance criteria.
- Lightweight tasks can remain PRD-only.
- For complex tasks, add `design.md` for technical design and `implement.md` for execution planning before `task.py start`.
- Repository checks: frontend `npm run build` passed. Backend checks were not runnable because `backend/.venv` is absent and the system Python lacks project dependencies.
- Manual Codex activation remains required: set `[features].hooks = true` in the user-level Codex config and approve the project hooks with `/hooks` when prompted by the Codex client.
