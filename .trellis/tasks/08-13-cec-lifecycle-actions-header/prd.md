# 调整 CEC 知识库生命周期操作位置

## Goal

让用户明确理解“保存草稿 / 校验 / 发布”作用于整个知识库草稿版本（CEC），而不是当前单个知识块。

## Background

- 当前三个动作位于 `KnowledgePayloadEditor` 之后，紧邻知识块编辑内容，容易被理解为知识块级动作。
- `saveDraft`、`validateDraft`、`publishDraft` 实际操作整个知识库草稿版本；一个普通文档草稿可包含多个知识块。
- 抽屉顶部已有知识库范围、参与检索、适用性和草稿状态等知识库级元信息。

## Requirements

- 将“保存草稿 / 校验 / 发布”提升到知识库编辑抽屉顶部的知识库级头部区域。
- 动作区与知识库范围、草稿状态等元信息建立清晰分组，不能继续贴在知识块内容编辑器下方。
- 保持现有按钮权限、禁用、加载状态和调用逻辑不变。
- “创建草稿”和归档知识库的“恢复知识库”同属知识库生命周期动作，也在同一知识库级动作区展示。
- 在窄屏下允许元信息和动作区独立换行，按钮不得挤压、截断或与其他内容重叠。

## Out Of Scope

- 不修改知识库版本状态机、API 或后端发布逻辑。
- 不增加单知识块的保存、校验或发布能力。
- 不改变知识块编辑器本身的字段和交互。

## Acceptance Criteria

- [x] “保存草稿 / 校验 / 发布”只出现在知识库级头部动作区，知识块内容编辑器下方不再出现该动作组。
- [x] 用户可从布局上识别按钮作用对象是当前知识库草稿版本。
- [x] 现有 `actionState` 权限、禁用状态、loading 状态和点击处理函数保持不变。
- [x] 归档恢复和创建草稿入口按原有条件正常展示。
- [x] 响应式规则和布局回归断言覆盖窄屏按钮宽度与换行。
- [x] 前端构建/类型检查和布局回归测试通过；实际抽屉浏览器检查受能力探测 405 阻塞，详见 `check.md`。

## Key Decisions

- 采用知识库级顶部工具栏，不新增悬浮底栏或知识块级动作。
- 这是单组件布局调整，按轻量任务执行。
