# 技术设计

## 整合边界

- 发布整合分支从 `origin/release/release_2.0.0` 创建，避免把本地旧基线或其他用户变更带入。
- 每个候选 worktree 分支先与远端 2.0.0 做提交和文件差异审查，再决定是否合入；已在远端的提交不重复合并。
- 当前主检出的未提交变更不通过 `git add .` 带入，只有经文件级确认属于本次交付的内容才以补丁形式复制到整合 worktree。

## 冲突与回滚

- 合并按功能依赖顺序进行，优先底层上传/文档类型能力，再合入界面和任务记录。
- 冲突按双方变更意图和现有 2.0.0 代码处理；每次合并后检查 `git status` 和 diff。
- 任何阶段可在整合分支上中止当前合并，不触碰主检出或其他链接 worktree。

## 验证

- 运行受影响前端测试/构建，并执行 `git diff --check`。
- 最终确认整合分支相对 `origin/release/release_2.0.0` 的提交列表、工作区状态和远端推送结果。
