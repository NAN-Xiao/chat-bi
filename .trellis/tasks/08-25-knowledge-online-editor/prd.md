# 知识库在线文档编辑器

## Goal

将知识库现有抽屉式 Markdown 文本框改造成浅色、全页的在线文档编辑体验，使知识维护人员能够在统一的文档画布中浏览、编辑和发布一份知识文档，同时完整保留现有工作空间权限、块级并发、草稿、校验、发布、回滚和 RAG 切片契约。

## Background

- 当前列表点击“编辑/查看”后打开 `760px` 抽屉，正文使用原始 Markdown `textarea`，入口位于 `frontend/src/views/knowledge-base/KnowledgeBaseV2Panel.vue:994` 和 `frontend/src/views/knowledge-base/editors/DocumentEditor.vue:139`。
- 后端已经以 `blocks[] + block_revision + structure_revision` 保存普通文档，并提供块级内容、结构保存和 409 冲突接口，不需要修改存储模型或发布链路。
- 已确认的目标样式是浅色在线文档：应用导航保持不变，编辑区域包含文档顶部操作区、左侧知识块目录、精简格式工具栏和居中文档画布。
- 用户明确要求移除加粗、斜体、下划线、表格和链接工具栏入口。

## Requirements

- R1：点击知识库列表的“编辑/查看”后，在当前知识库内容区域切换到全页编辑视图，不再打开 `el-drawer`；返回后恢复原列表筛选和滚动上下文。
- R2：编辑视图固定使用项目当前浅色主题，顶部操作区、目录、工具栏和画布使用一致的尺寸、间距、颜色和交互反馈。
- R3：左侧目录展示当前文档全部知识块；正文画布按顺序展示全部块，点击目录或正文块后激活该块。
- R4：任意时刻只挂载一个可编辑富文本实例；非活动块渲染为 Markdown 预览。该策略不得改变稳定块 ID、块顺序或现有块级并发边界。
- R5：编辑器以 Markdown 为唯一持久化格式。富文本编辑过程必须转换回当前块的 `markdown` 字段，不得改为存储 HTML。
- R6：工具栏仅提供撤销、重做、段落格式、无序列表、有序列表和引用。不得显示加粗、斜体、下划线、表格或链接入口。
- R7：R6 只限制新增编辑入口。已有 Markdown 中的加粗、斜体、链接、表格、代码块等内容必须能够读取和预览；仅打开、切换或保存未修改文档不能静默删除或改写这些内容。
- R8：继续支持新增、重命名、复制、上移、下移、启用/停用和删除知识块；至少保留一个知识块，危险操作保留明确确认。
- R9：草稿编辑采用防抖自动保存，同一时刻最多一个保存请求；页面显示“有未保存更改 / 保存中 / 已保存 / 保存冲突 / 保存失败”。编辑过程中产生的新修改不得被较早保存响应覆盖。
- R10：离开编辑页、校验或发布前必须先完成当前自动保存；保存失败或冲突时停留当前页面，不得继续校验或发布。
- R11：创建草稿、校验、发布、源文件上传、版本历史、下载、回滚、工作空间开关、适用性提示、归档只读、恢复和永久删除能力继续可用，但重新编排到全页顶部或辅助面板。
- R12：现有 409 块冲突、块删除冲突和结构冲突继续保留本地内容和人工处理入口，不引入静默覆盖或自动合并。
- R13：桌面布局采用目录与文档画布并列；窄屏目录横向滚动、工具栏可横向滚动、画布单列展示，页面级不得产生水平溢出。
- R14：权限边界保持不变。无管理权限或已归档文档只能阅读，不能通过富文本组件、快捷键或前端状态触发写接口。
- R15：此次实现不修改后端 payload、数据库表、发布任务、切片、向量或检索权限逻辑。

## Acceptance Criteria

- [ ] AC1：知识库列表编辑入口打开全页编辑视图，DOM 中不再使用知识编辑抽屉；返回后仍处于原作用域和工作空间列表。
- [ ] AC2：桌面编辑页具有顶部生命周期操作区、左侧知识块目录、精简工具栏和居中文档画布；浅色样式与现有管理页一致。
- [ ] AC3：正文画布展示全部知识块，目录点击和正文点击可切换活动块，页面同时最多存在一个富文本编辑器实例。
- [ ] AC4：工具栏只出现撤销、重做、段落格式、无序列表、有序列表和引用；被移除的五类入口在桌面和移动端均不存在。
- [ ] AC5：普通文本、标题、列表和引用编辑后保存并重新进入，生成的 Markdown 与显示内容一致。
- [ ] AC6：包含加粗、斜体、链接、表格、代码块的既有 Markdown 在未编辑保存和编辑其他块时保持不变；预览内容可读。
- [ ] AC7：新增、重命名、复制、排序、启停和删除知识块保存后重新进入仍保持正确 ID、顺序、状态和正文。
- [ ] AC8：连续输入期间自动保存串行执行；较早响应不会覆盖请求发出后的新输入，最终状态变为“已保存”。
- [ ] AC9：校验、发布和返回操作会等待保存完成；冲突或失败时阻止后续操作并显示可恢复状态。
- [ ] AC10：同块和结构并发冲突仍显示本地/服务端对比，载入服务端、本地重试、恢复删除块和刷新结构路径继续有效。
- [ ] AC11：无草稿、只读、已归档、发布中、校验失败和发布失败状态均有可理解的界面与正确的禁用行为。
- [ ] AC12：桌面与 `390x844` 视口无页面级水平溢出，目录、顶部操作和工具栏文字/图标不重叠。
- [ ] AC13：前端构建、知识库契约测试和新增编辑器测试通过；本地四服务启动后真实浏览器完成编辑、自动保存、校验、发布前置保存和返回路径验收。

## Out Of Scope

- 字符级多人实时协作、多人光标、评论、@成员、CRDT 或 OT。
- 修改知识库名称/描述的后端接口；画布顶部文档名一期只读。
- 新增单块独立发布、独立回滚或跨文档移动。
- 修改 Markdown 上传格式、后端校验规则、发布状态机或 RAG 切片算法。
- 删除已有 Markdown 语法支持；本次只移除指定工具栏入口。

## Risks And Deferred Items

- 富文本与 Markdown 往返可能造成格式漂移；实现必须用官方 Markdown 扩展，并用包含链接、表格、代码块和嵌套列表的夹具验证无修改不写回、修改时可预期序列化。
- 自动保存与块级乐观并发叠加后，响应合并必须保留请求期间的新输入；不得用禁用整个编辑器或覆盖本地 payload 规避。
- 大文档一期通过“全部预览 + 单活动编辑器”控制实例数量；虚拟滚动后续单独评估。
