# 修复知识块列表滚动导致详情不可见

## Goal

修复知识库文档编辑抽屉中长知识块列表撑高整个抽屉内容、导致滚动到后半段时右侧当前知识块详情不可见的问题。用户应能在浏览任意目录项时持续查看和编辑对应知识块内容。

## Background

- 当前 `DocumentEditor.vue` 使用两列网格：左侧渲染全部目录项，右侧只渲染一个当前知识块详情。
- 桌面端左侧目录没有独立纵向滚动约束，长列表会撑高网格及抽屉正文。
- 截图中抽屉正文滚动到第 56 项附近后，右侧详情仍位于网格顶部并已滚出视口，因此出现大片空白。
- 移动端现有设计将目录改为横向滚动，应继续保留。

## Requirements

- 桌面端知识块目录必须拥有独立的纵向滚动容器和适合当前视口的高度上限。
- 目录滚动不得带动右侧当前知识块详情离开其正常顶部位置。
- 点击任意目录项后，右侧继续展示该知识块标题与 Markdown 正文。
- 保持单个当前知识块详情渲染、保存数据流、只读状态和冲突处理不变。
- 保持 `680px` 及以下移动端目录横向滚动行为，不引入页面级横向溢出。

## Acceptance Criteria

- [x] 桌面端存在大量知识块时，纵向滚动条出现在左侧知识块目录而不是由目录撑高整个编辑抽屉正文。
- [x] 滚动到后半段并选择知识块后，右侧立即且持续可见所选知识块内容。
- [x] 少量知识块时布局保持正常，不出现无意义的页面级滚动或内容截断。
- [x] 移动端目录仍可横向滚动，详情位于目录下方，页面无横向溢出。
- [x] `DocumentEditor.layout.test.mjs` 覆盖桌面目录纵向滚动约束与移动端覆盖规则。
- [x] 前端生产构建通过，并通过真实页面桌面与移动视口验证及截图检查。

## Out Of Scope

- 不调整知识块增删、排序、重命名或发布流程。
- 不改变知识块载荷、接口或后端逻辑。
- 不恢复一次渲染全部知识块详情的旧交互。

## Key Decisions

- 滚动职责归属知识块目录；详情区保持与目录顶部并排。
- 使用响应式 CSS 在移动端显式取消桌面纵向高度/滚动约束，继续使用横向目录。
- 本任务范围轻量且集中，采用 PRD-only，不新增设计文档。
