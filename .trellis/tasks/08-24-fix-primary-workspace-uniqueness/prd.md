# 修复用户多主工作空间

## Goal

保证每个用户最多一个有效主工作空间，清理历史重复标记并增加数据库约束。

## Requirements

- 每个用户最多只能有一条 `status=1 AND is_primary=true` 的工作空间成员关系。
- 将一个工作空间设置为用户主工作空间时，必须在同一事务中取消该用户其他工作空间的主标记。
- 创建工作空间所有者、创建或编辑用户、审批创建工作空间、转移所有权和示例空间初始化必须遵循同一规则。
- 数据库迁移只修复重复的主标记，不删除工作空间、成员关系、角色或管理员创建的数据。
- 历史重复记录优先保留有效且非默认租户；仍有多个时按工作空间名称和 ID 稳定选择。
- 数据库必须提供唯一约束，防止遗漏入口或并发请求再次写入重复主空间。

## Acceptance Criteria

- [x] 连续将同一用户加入多个工作空间并设为主空间后，只有最后指定的工作空间保持主标记。
- [x] `is_primary=false` 的普通成员更新不会意外清除现有主工作空间。
- [x] 转移工作空间所有权时，新所有者的目标工作空间成为唯一主工作空间。
- [x] 示例工作空间只在用户没有主工作空间时成为主空间。
- [x] 迁移确定性清理历史重复标记，并在清理后创建活动主空间唯一索引。
- [x] 数据库拒绝同一用户再次插入第二条活动主空间记录，但允许不同用户各自拥有主空间。
- [ ] 多租户相关定向测试、迁移测试、Ruff 和 MyPy 通过。

## Notes

- `is_primary` 表示用户级默认工作空间，不表示工作空间所有者或空间内主要成员。
