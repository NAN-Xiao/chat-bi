# 统一知识库普通文档与 Markdown 上传校验

## Goal

将知识库统一为普通 Markdown 知识文档，移除用户可见的知识类型选择和类型分支；上传时接受符合内容结构要求的 Markdown 文件，并在格式不符合契约时明确提示“格式错误”。模板类型和解析器版本由平台内部管理，不写入用户文档。

## Background

- 当前新建弹窗允许选择 `DOCUMENT / BUSINESS / EVENT / JSON_FIELD` 四种知识类型，列表也展示“知识类型”列。
- 当前源文件上传支持 `.md / .markdown / .docx / .xlsx`，前端只校验扩展名和大小，后端解析四种文件格式。
- 当前“下载 Markdown 模板”提供普通文档、业务术语与 SQL、事件参数、表字段与 JSON Path 四种内容模板；这些模板只是可编辑的内容示例，不承担运行时类型或版本标记职责。
- 后端知识类型会影响 payload 分支、结构化编辑器、校验、标准化、对象引用投影和发布流程；不能仅隐藏下拉框而保留可创建其他类型的 API。
- 2026-08-14 对核心系统库只读统计：2 个知识库和 2 个知识版本均为 `DOCUMENT`，没有现存 `BUSINESS / EVENT / JSON_FIELD` 数据需要转换。

## Requirements

- 新建知识库不再显示或要求选择“知识类型”，所有新知识库均创建为普通知识文档。
- 知识库列表移除“知识类型”列，不再向用户展示该概念。
- 创建 API 不再接受客户端选择知识类型，服务端只创建普通文档知识库；旧的非文档类型值不得通过 API 继续创建。
- 编辑、保存草稿、校验、上传、发布和检索统一走普通文档路径，移除不再可达的业务术语、事件参数和 JSON 字段专用编辑分支。
- 新建弹窗、列表行上传和编辑页替换源文件三个入口统一只接受 `.md / .markdown`，移除 Word 和 Excel 上传提示及解析入口。
- 平台下载的四种 Markdown 内容模板继续保留，但都属于同一种“普通知识文档”，不再对应知识类型。
- 上传前端提供即时格式校验，后端在文件落库和草稿替换前执行权威校验；任一入口上传不合格文件时均明确提示“格式错误”，且不得修改现有草稿、源文件或版本修订号。
- 下载模板与上传校验共享同一份 Markdown 内容结构契约，避免前后端各自依赖易漂移的中文标题或文件名判断。
- 文档不得被要求携带 `template_type`、`template_version` 等平台内部元数据；服务端在解析成功后自动把稳定的解析器版本写入知识版本的 `parser_version` 字段。
- 保留普通文档已有的知识块编辑、对象引用、并发控制、版本历史、下载源文件、发布和权限能力。
- `DOCUMENT` 可作为不对外暴露的固定存储判别值保留，用于维持现有版本数据结构和数据库约束；它不再是用户可选择、API 可传入或页面可展示的知识类型。

## Acceptance Criteria

- [ ] 新建知识库弹窗没有“知识类型”控件，知识库列表没有“知识类型”列。
- [ ] 新建请求不包含可选知识类型；后端创建结果固定进入普通文档流程，构造旧类型请求不能创建结构化知识。
- [ ] 三处源文件上传入口只允许 Markdown 文件，界面不再声称支持 Word 或 Excel。
- [ ] 从页面下载的四种模板不含平台内部元数据，均可填写后通过上传格式校验，并作为普通文档生成知识块。
- [ ] 扩展名错误、编码错误或 Markdown 结构不完整时，前端或后端返回包含“格式错误”的明确提示。
- [ ] 任意符合结构要求的纯 Markdown 文档无需模板标记即可上传；服务端自动把当前解析器版本写入 `knowledge_base_version.parser_version`。
- [ ] 格式校验失败后，知识库、活动草稿内容、源文件引用和 revision 均保持不变。
- [ ] 直接绕过前端调用上传 API 仍不能上传不合格文件。
- [ ] 普通知识块编辑、校验、发布、源文件下载、对象引用和检索回归通过。
- [ ] 前端构建、相关前后端测试、真实上传点击路径及桌面/移动布局验证通过。

## Key Decisions

- 合法文件必须是 UTF-8 编码的 `.md / .markdown`，包含非空一级标题、至少一个二级章节及有效正文；围栏代码块必须闭合。
- 四种下载模板只是内容示例分类，不携带类型或版本 front matter。
- 解析器版本由服务端常量管理并写入现有 `parser_version` 字段，客户端和上传文件均不能指定或覆盖。
- 编码错误或 Markdown 结构不完整均返回以“格式错误”开头的明确提示。
- 前端执行即时校验以减少无效请求，后端执行相同契约的权威校验；不能依赖文件名或固定中文标题判断模板合法性。

## Out Of Scope

- 不从 Markdown 标题自动生成事件、字段或 JSON Path 结构化对象；对象引用继续使用普通文档现有配置能力。
- 不改变知识范围、工作空间绑定、发布状态机、检索权限和 Data Skills 语义配置。
- 不新增 Word、Excel 到 Markdown 的转换服务。
