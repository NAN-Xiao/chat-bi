# 技术设计

## 范围与边界

本任务只做发布前验收和必要的通用缺陷修复，复用现有知识库目录、RAG 检索服务、三类助手调用链、权限服务和管理页面。MCP 保持关闭；原 Skills 与个人空间 Skills 保持现状，不迁移、不删除、不新增显式 Agent-Skill 绑定。

## 验收数据流

```text
鉴权用户/当前工作空间
  -> 当前授权数据源与权限快照
  -> 知识库候选过滤（空间类型、数据源、版本状态）
  -> RAG 检索与上下文拼装
  -> 助手场景（报告解读/综合分析）
  -> SQL 执行/报告生成
  -> 中文安全响应 + RAG 审计
```

每次真实链路必须能从请求、工作空间、数据源、知识库版本、chunk、权限 epoch 和 `surface` 追溯；不得因检索失败静默使用跨空间或未授权示例。

## 联调策略

- 先直接调用后端接口确认鉴权、请求体和响应合同，再通过前端真实点击路径复核。
- 使用已配置的应用系统数据库和当前工作空间绑定数据源；测试数据限定在可授权范围内。
- 综合分析失败时按“请求参数 -> RAG 上下文 -> SQL 生成 -> SQL 执行 -> 结果解释”逐段记录，不把具体业务字段写入共享代码。

## 页面验收策略

复用现有 Element Plus 页面框架和统一布局；通过浏览器检查知识库列表、编辑、发布/更新、检索预览、空间/数据源权限入口。每个视口保存截图并执行 `scrollWidth <= clientWidth + 2`，同时检查顶部操作区 `scrollWidth/clientWidth`。

## 迁移与发布策略

迁移只读检查必须带真实 Worker 标识和兼容构建确认参数。数据库已为 `V2_ACTIVE`，任何状态改变命令均不属于本任务。分支合并前比较 `git diff release/release_2.0.0...HEAD` 与主工作区未提交文件，若有冲突先停止并报告，不覆盖用户内容。
