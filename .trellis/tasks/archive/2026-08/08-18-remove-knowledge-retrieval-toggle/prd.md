# 移除知识库参与检索开关

## Goal

取消知识库级“参与检索”手工开关，使知识库是否具备运行时检索资格只由发布生命周期决定：存在当前已发布版本且未归档时参与检索，没有当前已发布版本或已经归档时不参与检索。

## Background

- 当前知识库管理列表和编辑抽屉各有一个“参与检索”开关，调用 `PUT /knowledge-base/{id}/active` 修改 `knowledge_base.active`。
- 向量检索额外过滤 `KnowledgeBase.active = true`，导致已发布知识仍可能因手工停用而不参与检索；当前分支的结构化上下文只读取工作空间 tracking 配置，不再读取知识库 `active`。
- 归档恢复当前会恢复已发布版本但保持 `active=false`，要求管理员再次手工启用，与目标行为冲突。
- 草稿发布期间，上一当前已发布版本继续是运行时知识；未发布草稿本身不得进入检索。

## Requirements

- R1：知识库管理列表和编辑抽屉不再显示或操作知识库级“参与检索”开关。
- R2：V2 管理接口不再提供知识库级启停操作，前端不再调用对应接口。
- R3：知识库向量召回使用发布生命周期资格：当前版本状态为 `PUBLISHED` 且知识库未归档；助手上下文继续通过现有统一召回服务消费这些结果。
- R4：历史 `active` 值不得继续阻止满足 R3 的已发布知识参与运行时检索。
- R5：没有当前已发布版本、当前版本不是 `PUBLISHED` 或知识库已归档时，不得参与运行时检索。
- R6：恢复历史已发布知识后，该版本重新成为当前 `PUBLISHED` 版本并自动具备检索资格，不再要求额外启用。
- R7：保留现有工作空间/租户权限、数据源适用性、对象权限、索引就绪、可见范围和平台知识“当前工作空间使用”覆盖规则；发布状态只替代知识库级 `active` 开关，不绕过这些过滤条件。
- R8：数据库中的历史 `active` 列和已禁用的旧版管理链路不在本次做破坏性迁移；V2 运行时和 V2 管理界面不得再依赖该字段。

## Acceptance Criteria

- [x] AC1：当前知识列表与知识编辑抽屉均不存在“参与检索”列、文案或开关，列表布局保持稳定且无横向溢出（源契约检查通过；真实登录后浏览器截图受鉴权环境限制）。
- [x] AC2：前端 V2 API 不再暴露或调用 `setActive`，后端 V2 路由不再注册 `PUT /knowledge-base/{id}/active`。
- [x] AC3：一条 `active=false` 但具有当前 `PUBLISHED` 版本、未归档且满足其他权限/适用性条件的知识，可以进入向量召回候选并由现有助手上下文链路消费。
- [x] AC4：无当前发布版本、版本非 `PUBLISHED` 或已归档的知识不会进入向量召回或结构化上下文。
- [x] AC5：归档知识恢复后无需第二次启用操作即可按既有权限与适用性规则参与检索，界面提示不再声称“保持停用”。
- [ ] AC6：前端构建/类型检查、相关前端契约测试、后端检索/结构化上下文/生命周期/API 定向测试通过，并完成实际页面桌面与移动视口检查和截图。

## Out Of Scope

- 不移除知识块级 `enabled`；停用知识块仍不进入新发布版本。
- 不移除平台公共知识的“当前工作空间使用”开关，也不改变任何租户、数据源、对象或字段权限。
- 不修改召回阈值、Top-K、切片、Embedding、排序和上下文长度。
- 不在本次删除数据库 `knowledge_base.active` 列或改造已经被 V2 切换屏障禁用的旧版上传管理 API。
