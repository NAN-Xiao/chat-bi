# 修复思考过程闪烁消失后恢复

## Goal

修复 Smart Q&A 同一会话存在重叠任务时，旧回答的“思考过程”区域突然消失、收到首个推理分片后又出现的问题，使每条回答的生成状态由自身任务生命周期稳定驱动。

## Background

- 用户提供的截图显示回答文本已出现，下方仅显示“已使用知识库（5）”，思考过程区域在生成期间存在阶段性消失后恢复的现象。
- 诊断阶段已经确认根因；用户随后明确要求实施修复。
- 诊断应覆盖前端条件渲染、流式事件合并、消息状态更新以及必要的后端事件顺序，不以单个组件的表象作为结论。

## Requirements

- 每条拥有未完成 `task_id` 的回答都必须保持自身生成态，不得因它不再是会话最后一条记录而退出生成态。
- 新建回答在后端返回 `task_id` 前，仍沿用“最后一条记录 + 当前发送中”的短暂生成态，避免初始占位消失。
- 一个任务完成、失败或停止时，只结束该记录的任务态；同会话仍有其他未完成任务时，不得提前解除会话输入锁或隐藏其他记录的思考态。
- `ChartAnswer` 内部轮询 loading 必须有组件自身可写的状态来源，不依赖父组件未监听的 `update:loading` 事件。
- 保持现有产品行为：正常单任务页面在生成中禁止继续提问；任务完成后思考正文自动收起，但“思考过程”入口继续保留。
- 修复必须覆盖页面恢复、多标签页形成的重叠任务和任务交错完成，不为特定问题、数据源或业务字段添加特例。

## Out Of Scope

- 不改变后端任务队列、SSE/轮询事件协议或数据库结构。
- 不主动开放同一页面并发提问；现有输入禁用与停止按钮行为保持不变。
- 不改变思考过程完成后自动收起的产品交互。
- 不处理与本问题无关的推荐问题生成时长或业务 SQL 口径。

## Acceptance Criteria

- [ ] 非最后一条记录只要仍有活动 `task_id`，首个 reasoning 分片到达前也持续显示“思考中”占位和入口。
- [ ] reasoning 分片到达后，思考内容在同一组件内连续追加，不发生隐藏后重建。
- [ ] 最新任务先完成但旧任务仍运行时，旧任务继续显示生成态，输入区仍保持禁用/停止态。
- [ ] 所有任务结束后，输入恢复可用；每条已有 reasoning 的回答保留“思考过程”入口并按现有规则收起正文。
- [ ] 页面恢复和多标签页造成的重叠任务状态满足以上行为。
- [ ] 聚焦单元测试、前端构建和真实浏览器回归全部通过，页面无新增控制台错误或横向溢出。

## Diagnostic Result

- 根因：同一会话存在并发任务时，前端只把最后一条记录标记为生成态；旧记录在首个 reasoning 分片到达前会同时满足 `thinkingActive=false`、`hasReasoning=false`，导致思考入口消失，分片到达后又重新出现。
- 次要缺陷：`ChartAnswer` 的 `_loading` 更新事件没有父级接收，所谓独立 loading 实际仍等同于 `message.isTyping`。
- 后端 reasoning 提交顺序和终态刷新已排除为本次根因。
- 完整证据、真实时间线和建议见 `research/diagnosis.md`。
