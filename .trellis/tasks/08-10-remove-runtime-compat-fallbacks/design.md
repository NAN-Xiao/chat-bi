# 技术设计

## 1. 设计原则

运行时只消费当前版本、当前租户、当前工作空间和当前数据源边界内的配置。兼容处理分为三类：

1. 业务语义兼容：删除，例如第一个租户、第一列、旧数据源、旧轴字段和全表 embedding 检索。
2. 数据格式迁移：迁移到当前格式后删除在线读取分支，例如看板日期配置、旧树位置、旧加密值和旧 Redis key。
3. 基础设施容错：保留，例如网络异常、Redis 故障、文件解析错误和国际化缺失，但必须返回明确错误或 miss，不能改变业务语义。

## 2. 边界改造

### 租户与数据源

- `resolve_current_tenant` 在请求租户不存在、禁用、无成员关系或未指定时返回权限错误；只有平台管理员的明确默认工作空间逻辑保留。
- tracking 配置读取必须使用精确 `tenant_id + datasource_id`。删除 `include_legacy` 及未绑定配置合并逻辑。
- 看板图表的执行数据源必须来自已保存、已授权的当前配置。图表缺少数据源时失败，不使用看板或请求参数推断值。

### 看板配置

- 先运行一次性迁移将 V1 日期字段写入 V2 `dateFilter`，并将旧 `pid/sort` 写入树位置表。
- V2 配置校验失败时返回 `migration_required` 或 `invalid`，但不再解析 V1。
- 前端只维护 V2 类型和 V2 序列化逻辑；旧字段只允许出现在迁移脚本和迁移测试夹具中。

### 语义、字段与检索

- 字段角色、字段类型、字段注释和图表轴必须来自当前 workspace/datasource 配置或明确的用户选择。
- 缺少 schema/embedding 配置时返回结构化不可用结果；不回退物理缓存、第一字段或全表扫描。
- Excel tracking 导入只接受当前模板结构；旧模板由校验错误拒绝。

### 协议与密钥

- SQL 执行内部和 API 输出统一使用 `SqlEngineResult` 标准结构。
- 旧加密数据先离线重加密，再删除旧密钥解析；旧明文不可再读取。
- 任务状态只读当前租户隔离 key，旧 key 不再作为查询来源。

## 3. 数据迁移与发布顺序

1. 备份核心数据库和 Redis 中仍在使用的任务状态。
2. 运行看板日期、树位置、tracking 配置和加密配置迁移，所有冲突进入人工清单。
3. 校验迁移后数据数量、租户边界、数据源边界和哈希/读回结果。
4. 发布删除运行时兼容分支的代码。
5. 清理过期旧缓存和旧任务 key；不在正常请求中读取旧值。
6. 通过 API、前端和浏览器验证后，才允许清理迁移专用旧字段或历史脚本。

迁移不得删除管理员创建的数据。迁移失败时停止发布并使用备份或代码回滚恢复，不能在运行时重新打开隐式 fallback。

## 4. 保留的非兼容容错

保留普通异常处理、请求取消处理、缓存 miss、Redis/网络错误、文件 JSON 解析错误和用户可见错误文案 fallback。它们不能选择另一个租户、数据源、字段、指标或旧格式数据。
