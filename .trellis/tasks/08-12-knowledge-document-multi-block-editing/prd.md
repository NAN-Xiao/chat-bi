# 知识文档多知识块编辑设计

## Goal

保持知识库列表“一行一份独立文档”的层级不变。用户点击某条记录的“编辑”后，在同一编辑页面查看并维护该文档内部的多个知识块，每个知识块可以独立编辑、排序、新增、复制、停用或删除，同时继续使用文档级草稿、校验、发布和回滚流程。

## Background

- 当前普通文档编辑器只有单个 Markdown 正文。
- 当前发布流程会根据正文标题和长度生成系统检索切片。
- 用户确认的目标是编辑一份文档内部的多个知识块，不是把知识库列表中的多份文档合并编辑。
- 用户可维护的知识块必须与系统自动生成的 RAG 检索切片分开建模。

## Requirements

- R1：知识库列表每一行继续表示一份独立知识文档；编辑入口只打开当前文档。
- R2：普通文档编辑页展示该文档的全部用户知识块，知识块至少包含稳定 ID、标题、Markdown 正文、顺序和启用状态。
- R3：支持新增、编辑、复制、拖拽或按钮排序、停用和删除知识块；文档至少保留一个知识块。
- R4：知识块共享所属文档的作用域、工作空间、权限、草稿和发布版本，不提供单块独立发布或回滚。
- R5：保存草稿以整份文档为事务边界；校验同时返回文档级和块级错误，并支持定位到具体知识块。
- R6：发布时根据知识块生成标准化正文和系统检索切片；检索切片保留来源知识块 ID，但不作为用户直接编辑对象。
- R7：删除、停用或重新排序草稿块不会立即影响当前已发布版本；只有新版本发布成功后生效。
- R8：现有单段 Markdown 普通文档无损兼容为一个知识块；上传内容可按标题生成知识块预览，用户确认后才替换草稿。
- R9：事件、JSON 字段和业务知识一期继续使用现有结构化编辑器；不同知识类型不混合到同一文档，Data Skills 继续独立管理。
- R10：块级接口和页面操作不得扩大现有平台、工作空间和普通成员权限边界。
- R11：并发保存采用块级乐观版本和文档结构版本；不同知识块可以并行保存，同一知识块或结构操作冲突时明确提示并保留本地内容，不自动覆盖或静默合并。
- R12：详细产品说明以 `docs/knowledge_document_multi_block_editing.md` 为准。
- R13：编辑页采用知识目录/内容详情双栏布局；左侧持续展示全部知识块，右侧一次只展示当前选中的一个知识块，避免同时挂载大量 Markdown 编辑器。
- R14：新增或复制后自动选中新块；排序按稳定块 ID 保持当前选择；删除当前块后选择相邻的剩余块，目录选择始终有效。
- R15：现有知识库编辑抽屉聚焦知识块正文，不再展示知识类型切换、文档级数据源绑定、标签、物理对象引用和替换源文件入口；已有字段继续兼容保存，不能因隐藏入口被清空。
- R16：知识块标题从左侧目录项的编辑按钮单独修改；检索状态放在知识块顶部状态区，右侧正文表单只展示 Markdown 内容，不重复提供标题和检索状态字段。
- R17：Markdown 正文保持直接可编辑，但不显示输入框边框、圆角或聚焦蓝框，使详情区呈现为无框内容编辑面。
- R18：知识块操作按钮遵循项目现有紧凑图标操作风格，使用固定方形无边框按钮，不使用椭圆或圆形描边按钮。

## Acceptance Criteria

- [ ] AC1：点击任意列表记录的“编辑”，仅展示该文档内部的全部知识块。
- [ ] AC2：用户可以在同一页面新增、编辑、复制、排序、停用和删除知识块，保存后重新进入顺序和内容一致。
- [ ] AC3：排序不会改变稳定块 ID；复制会生成新的块 ID。
- [ ] AC4：无效块可以保存在草稿中，但空标题、空正文或全部停用时不能发布，并显示块级错误。
- [ ] AC5：草稿变更不会影响当前发布版本；发布失败后上一版本继续提供检索服务。
- [ ] AC6：发布生成的每个检索切片都能追踪到文档版本和来源知识块。
- [ ] AC7：现有单 Markdown 文档迁移后正文不丢失，并显示为一个知识块。
- [ ] AC8：不同列表记录不会被合并到单条编辑页，不同知识类型和 Data Skills 不被混入一期普通文档块编辑器。
- [ ] AC9：块级操作服从现有文档权限和工作空间隔离，并有并发冲突与审计记录。
- [ ] AC10：桌面和移动视口无页面级水平溢出，知识块目录、标题、状态和操作区可正常使用。
- [ ] AC11：用户 A 和用户 B 同时编辑不同知识块时均可保存；同时编辑同一知识块、排序、删除或新增时，后提交方收到冲突提示并可查看服务端与本地差异，且本地内容不丢失。
- [ ] AC12：桌面端左侧目录与右侧单块编辑区同时可见；移动端目录可横向滚动，右侧只渲染所选知识块，新增、复制、排序和删除后选中项符合 R14。
- [ ] AC13：编辑抽屉只保留知识块主流程和保存、校验、发布动作；重新保存已有文档时，隐藏的文档级元数据保持原值。
- [ ] AC14：左侧目录可编辑当前知识块标题，检索状态可从知识块顶部切换，右侧正文表单只显示 Markdown 内容；修改仍通过现有草稿保存和块级并发校验提交。
- [ ] AC15：正文编辑区无可见输入框边界，鼠标悬停和聚焦时也不出现边框，编辑与保存行为不变。
- [ ] AC16：上移、下移、复制、删除和标题编辑按钮使用统一的紧凑方形图标样式，危险操作仅在悬停时显示红色反馈。

## Out Of Scope

- 跨文档批量编辑、移动或合并知识块。
- 单知识块独立版本、发布或回滚。
- 用户直接编辑系统检索切片、向量或切片参数。
- 一期改造事件、JSON 字段、业务知识和 Data Skills 的编辑模型。

## Risks And Constraints

- “知识块”和“检索切片”名称接近，页面文案和数据模型必须明确区分。
- 大量知识块同时挂载 Markdown 编辑器可能造成性能问题，需要折叠或按需渲染。
- 旧文档迁移必须保留正文、版本和引用关系，不能通过静默重新解析改变已发布内容。
- 文档级保存和发布需要保证块内容、顺序、状态与检索投影的一致性。
- 一期不实现字符级实时协同编辑；并发边界为块级内容和文档结构级别。
