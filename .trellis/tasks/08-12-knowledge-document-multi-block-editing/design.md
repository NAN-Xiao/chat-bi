# 知识文档多知识块编辑技术设计

## 1. 数据边界

普通文档仍保存于 `knowledge_base_version.payload`，不新增可独立发布的知识块实体表。`DOCUMENT` payload 升级为：

```json
{
  "knowledge_type": "DOCUMENT",
  "blocks": [
    {
      "id": "uuid",
      "title": "知识块标题",
      "markdown": "正文",
      "enabled": true,
      "block_revision": 1
    }
  ],
  "structure_revision": 1,
  "tags": [],
  "datasource_neutral": false,
  "object_references": []
}
```

- 块顺序由 `blocks` 数组顺序决定。
- `block_revision` 只在该块标题、正文或启用状态变化时递增。
- `structure_revision` 在新增、删除、复制或排序时递增。
- 文档版本表已有的 `revision` 继续保护整份草稿、校验、发布和文件替换操作。

## 2. 旧数据兼容

- 读取旧 `{ markdown: "..." }` payload 时，确定性转换为一个稳定知识块。
- 旧块 ID 由知识版本 ID 或稳定内容指纹生成，避免每次读取产生不同 ID。
- 保存后写入新 `blocks` 结构，不继续双写 `markdown`。
- 发布版本不做破坏性批量重写；在读取、校验、切片时统一经过规范化入口。

## 3. API 契约

保留现有整份草稿保存接口，供非文档知识和文件替换使用。普通文档增加块级保存接口：

- `PATCH /knowledge-base/{id}/versions/draft/blocks/{block_id}`：更新标题、正文或启用状态，校验 `block_revision`。
- `PATCH /knowledge-base/{id}/versions/draft/structure`：提交完整块顺序和结构操作结果，校验 `structure_revision`。

冲突返回 HTTP 409 和结构化详情：冲突类型、服务端结构版本、服务端块快照。客户端保留本地值并展示对比。

所有写入在数据库事务内再次校验：知识库权限、草稿归属、版本 ID、文档类型和预期版本。

## 4. 发布与检索投影

- 标准化正文按启用块顺序拼接，每块使用 Markdown 标题作为边界。
- 校验错误字段路径使用 `blocks[index].title`、`blocks[index].markdown` 或 `blocks`。
- 切片先按知识块边界处理，再在单块过长时使用现有长度算法拆分。
- `knowledge_chunk` 增加可空 `source_block_id`；旧版本切片保持为空，新发布文档切片写入来源块 ID。
- 内容哈希包含块 ID、顺序、正文、启用状态和文档元数据，确保结构变化使发布快照失效。

## 5. 前端交互

- `DocumentEditor.vue` 使用知识块目录加单个活动块详情的主从布局，参考知识库页面的目录/正文阅读模式；不同时渲染全部块编辑器。
- 组件用稳定块 ID 保存 `activeBlockId`。外部载入新文档或删除活动块时回退到第一个/相邻有效块；排序不改变选择。
- 提供新增、复制、上移、下移、启停和删除；拖拽可在后续增强，按钮排序满足一期完整操作与移动端可用性。
- 新增和复制后选中新块；删除当前块后优先选择原位置的后继块，没有后继时选择前驱块。
- 普通输入保存在页面本地状态；点击保存时逐块保存内容变更，再提交结构变更。
- 同块冲突显示服务端和本地标题/正文对比，用户可载入服务端或以本地内容基于最新 revision 重试。
- 页面关闭或切换记录前保留现有未保存行为，不引入实时字符协作。
- 移动端将目录变为横向滚动列表，详情区保持单列；目录按钮和活动详情均使用固定结构，避免标题、状态或操作按钮引发布局跳动。
- 编辑抽屉不再承担知识类型转换和文档级元数据维护：知识类型由记录创建时确定，普通文档隐藏 `datasource_neutral`、`tags`、`object_references` 表单，文件替换入口移除。字段仍由 payload 规范化和保存流程原样透传，避免隐藏 UI 造成破坏性数据变更。
- 知识块标题由目录项右侧的编辑按钮打开独立输入框修改，修改结果仍写回本地块 payload，并在保存草稿时走原有块级版本检查；检索状态移到知识块顶部，右侧正文表单只保留 Markdown 内容。
- 知识块操作采用项目既有的紧凑图标操作样式：固定 28px 方形、无边框、6px 圆角，普通操作悬停使用浅蓝背景，删除操作悬停使用浅红背景。

## 6. 事务与失败处理

- 块级更新采用 JSONB payload 条件更新和版本比较，成功后同时递增文档 `revision`。
- 同一块冲突不影响其他块已成功保存的结果；前端明确显示尚未保存的冲突块。
- 结构提交必须基于最新 `structure_revision`，防止删除、排序和新增相互覆盖。
- 发布继续使用现有文档级 revision/content hash 快照，任一发布阶段失败不切换当前版本。

## 7. 回滚

- 代码回滚可恢复旧单 Markdown 编辑器；新 payload 仍由后端兼容读取并拼接为 Markdown，避免新数据完全不可读。
- 数据库迁移只增加可空列，不删除旧字段或历史记录。
